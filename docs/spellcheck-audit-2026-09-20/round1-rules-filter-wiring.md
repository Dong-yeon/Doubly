## 2. 확정 결함

각 항목: **입력 → 관찰 / 기대 / 재현 / 원인 / 수정안 / 오탐 위험**. 재현 명령은 `$SP` 를 §1.1 경로로 읽습니다.

### 2.1 1층 — 놓침 (5건)

#### R1. `어떻하-` (어떻하지 · 어떻하냐 · 어떻하고 · 어떻하면 · 어떻한) — high

- **관찰**: 1층 `[]`. `EOTTEOK_RULES` 는 `/어떻해/`·`/어떡게/` 둘뿐 (`koreanSpellRules.ts:162-165`).
  2층 후보 `어떻하지 → [어떠하지, 어떡하지]`, 3층 pick 이 자모 동점을 '앞엣것'으로 풀어 **'어떠하지'(오답)** 를
  제안. `어떻한 → 어떠한` 도 같은 꼴.
- **기대**: 어떡하지 / 어떡하냐 / 어떡하고 / 어떡하면.
- **재현**: `node $SP/run.mjs check '어떻하지' '어떻하냐' '어떻해' && node $SP/run.mjs pick 어떻하지 어떠하지 어떡하지`
- **의도적 제외?** 아니다. 주석은 "어떡해는 서술어로만 쓴다"만 적음. `MUST_NOT_FLAG:66` 의 '없는대 어떡해'는 -대/-데 항목.
- **수정**: `EOTTEOK_RULES` 에 `{ re: /어떻하/g, to: '어떡하', reason: "'어떻게 하-'의 준말이라 '어떡하-'예요 (어떡하지, 어떡하냐)" }`.
  `dedupeOverlapping` 은 안정 정렬 + 규칙이 앞이라 같은 index 0 의 사전 오답('어떠하지')도 자동으로 밀린다.
- **오탐 위험: none** — '어떻'으로 끝나는 활용형이 없어 어절 경계에서 '어떻'+'하'가 생길 수 없고, ko.dic 에 '어떻하' 포함 항목 0건.
  반례 실행: 어떻게·어떡해·어떡하지·어떠하냐·어떠한 무반응.
- **부수 발견(핑퐁)**: 사전이 `어떡하면/어떡할까/어떡해야/어떡한/어떡할` 을 모른다(known=false; 어떡하지·어떡하든은 known).
  규칙이 '어떻하면 → 어떡하면' 으로 고치면 2층이 다시 `어떡하면 → 어떠하면` 을 제안한다. 3층에 '어떡하'로 시작하는 어절은
  묻지 않는 예외(또는 후보가 '어떠하'로 시작하면 버리기)를 넣고 `MUST_NOT_ASK` 에 '어떡하면' 을 고정한다. 이걸 빼면 규칙은
  맞아도 사용자가 고친 직후 틀린 재제안을 본다.

#### R2. 애교체 어미 뒤 되/돼·뵈/봬 (안되용 · 안되욤 · 되용 · 되욤 · 뵈용) — high

- **관찰**: 1층 `[]` — `/안되(요|서)/`, `/되요/`, `/뵈요/` 가 '용·욤'을 안 본다. 같은 호출에서 `됬어용 → 됐어용`,
  `할께용 → 할게용` 은 잡혀 "애교체 어미 뒤 어간 교정"이 이미 설계 목표임을 확인.
  2층: `되용 → stripNasal '되요' → ko.dic known=true → 면제(침묵)` (`koreanDictionary.ts:79-85`, **'되요'가 사전에 있다**);
  `안되용 → pick '안되다'`, `되욤 → pick '되요'(그 자체가 틀린 말)`, `뵈용 → pick '비용'` — 전부 엉뚱.
- **기대**: 안 돼용 / 안 돼욤 / 돼용 / 돼욤 / 봬용.
- **재현**: `node $SP/run.mjs check '안되용 그건' '안되욤' '되용' '뵈용' '됬어용' && node $SP/run.mjs pick 뵈용 비용 && node $SP/run.mjs nasal 안되용`
- **수정**: 기존 규칙은 그대로 두고 뒤에 추가 — 뒤에 한글이 이어지면 매치하지 않는다(붙여 쓴 용돈·용기·용량 차단):
  ```ts
  { re: /안되(용|욤)(?![가-힣])/g, to: '안 돼$1', reason: (기존 안되 규칙과 동일) },   // 안되 규칙이 되 규칙보다 앞
  { re: /되(용|욤)(?![가-힣])/g,   to: '돼$1',    reason: (기존 되요 규칙과 동일) },
  { re: /뵈(용|욤)(?![가-힣])/g,   to: '봬$1',    reason: (기존 뵈요 규칙과 동일) },
  ```
  **'영'은 넣지 않는다** — 되영→돼영 은 '되여(비표준)→돼여' 를 전제하고, 영화·영어·영원히 등 첫 음절 '영' 낱말과의 붙여쓰기
  충돌 확률이 높다. 규칙 주석의 "일부러 넣지 않은 것"에 기록.
- **오탐 위험: low** — 원안 `/안되(요|용|욤|영|서)/` 은 `안되영화 보자 → 안 돼영화`, `안되용돈 아껴 → 안 돼용돈`, `되용량 → 돼용량` 을
  만들었다(실행 확인). lookahead 를 붙이면 이 반례가 모두 사라지고 정탐(안되용ㅠㅠ·안되용~·되욤ㅋㅋ·뵈용~)은 유지된다.
  기존 `/되요/` 도 '안되요즘 → 안 돼요즘' 같은 위험을 이미 감수 중.

#### R3. `괜찬` · `귀찬` 어간 (괜찬아용 · 괜찬앙 · 괜찬은데 · 괜찬을까 · 괜찬해 · 귀찬은데 · 귀찬게) — high

- **관찰**: 1층 전부 `[]`. 2층은 괜찬은데·괜찬을까·귀찬게 는 구제하지만 `괜찬앙/괜찬아용 → [괜찮다](거리 2) → null`,
  `괜찬해 → pick '찬찬해'(엉뚱)`. `괜찬아·귀찬아` 는 '아' 끝이라 사전에 묻지도 않음(§2.3 F1).
- **재현**: `node $SP/run.mjs check '괜찬아용' '괜찬앙' '괜찬은데' '귀찬게' '편찬했어' '동찬아'`
- **의도적 제외?** 아니다 — 오히려 `verify-spellcheck.mjs:318-319` SAFE_PICK 에 `귀찬아→귀찮아`, `괜찬아→괜찮아` 기대가 있어
  "고치고 싶은 말"로 등록돼 있다(그런데 collectTokens 가 그 어절을 pick 까지 보내지 않는다 — §2.3 F1).
- **수정** (`WORD_RULES`):
  ```ts
  { re: /괜찬/g, to: '괜찮', reason: "'괜찮다'가 맞아요" },                            // 반례 없음
  { re: /귀찬(?=게|아서|았|지|은데|을까|아용|앙)/g, to: '귀찮', reason: "'귀찮다'가 맞아요" }, // 이름+조사(귀찬아·귀찬은·귀찬을) 제외
  ```
  '귀찬아/은/을'은 사람 이름 '귀찬'+조사와 못 가르므로 일부러 넣지 않는다고 주석에 적어 다음 조사자가 다시 보고하지 않게 한다.
- **오탐 위험: low** — ko.dic 에 '괜찬|귀찬' 포함 항목 0건. '괜'으로 시작하는 어휘는 괜히·괜스레·괜찮- 뿐. 편찬·편찬했어·동찬아·우찬아·만만찬 무반응.

#### R4. `기달-` (기달려 · 기달릴게 · 기달렸어) — high

- **관찰**: 1층 `[]`. 2층 `기달려 → [기다려, 시달려, 치달려, 기 달려]` → safe 3 + 띄어쓰기 변형 → pick null. 모든 층 침묵.
- **재현**: `node $SP/run.mjs check '기달려' '기달릴게' '기다려' && node $SP/run.mjs pick 기달려 기다려 시달려 치달려 '기 달려'`
- **수정** (`CONJUGATION_RULES`): `{ re: /(?<![가-힣])기달(?=[려리렸릴])/g, to: '기다', reason: "'기다리다'라서 '기다려'예요" }`
- **오탐 위험: low, 단 어절 첫머리 제한 필수** — 원안 `/기달(?=[려리렸릴])/` 은 `후기달렸어`(후기 달렸어), `국기달려`, `태극기달려있어`,
  `뭐하기달렸어`(-기 달렸어) 를 '…기다…'로 바꾼다(실행 확인). 앞에 한글이 없을 때만 매치하면 4개 반례 무반응, 정탐(기달려·기달릴게·기달렸어·조금만 기달려줘·기달리는) 유지.
  lookbehind 는 이 파일에서 처음 쓰는 것이라 Hermes 지원 확인이 필요(§5) — 안 되면 `(^|[^가-힣])기달` + `$1` 캡처 관례로.

#### R5. `됫-` (됫어 · 됫다 · 됫으면) — high

- **관찰**: 1층 `[]`. 2층 `됫어 → [되서, 됐어, 되어] → pick '되어'(오답)`, `됫다 → pick '되다'(오답)`. 침묵보다 나쁜 상태.
  `DOEN_RULES` 는 '됬→됐', '됀→된' 을 같은 논리로 이미 잡고 있어 '됫'만 빠진 논리적 누락.
- **재현**: `node $SP/run.mjs check '됫어 이제' '됫다' '됫박에 담아' && node $SP/run.mjs pick 됫어 되서 됐어 되어`
- **수정**: '됬' 규칙 바로 아래 `{ re: /됫(?=[어다으네고지요구])/g, to: '됐', reason: "'됐'(되었)이 맞아요. '됫'은 없는 말이에요" }`.
  lookahead 를 `[어다으네고지요구잖나냐던을음습]` 까지 넓혀도 안전.
- **오탐 위험: low** — '됫'을 가진 표준어는 됫박·됫박질·됫병·됫밥·됫술·됫수 계열뿐이고 뒤 음절이 ㅂ/ㅅ 초성이라 lookahead 에 걸리지 않음(9문장 무변화 확인).

### 2.2 1층 — 오탐 (5건)

#### R6. `역활` 이 합성어 경계에서 만들어짐 (지역활동 · 지역활성화 · 무역활동 · 구역활동 · 역활용) — high

- **관찰**: 5문장 모두 `역활 → 역할` 제안 → 적용하면 `지역할동`. 규칙은 `koreanSpellRules.ts:216` `/역활/g` (경계 없음).
  영역활동·해역활동·권역활성화·지역활력 도 걸림. 2층은 이 어절들에 pick null 이라 1층만 고치면 침묵으로 끝남.
- **재현**: `node $SP/run.mjs check '지역활동 하러 가' '지역활성화 사업이래' '무역활동이 늘었대' '구역활동 배정받았어' '공간 역활용 좋다'`
- **수정**: `{ re: /역활(?![동성용력기약발])/g, to: '역할', reason: "'역할(役割)'이 맞아요" }`.
  원안(lookbehind `(?<![가-힣])역활`)은 기각 — finding 자신의 5번째 문장 '공간 역활용'(앞이 공백)을 못 막고, 채팅체 `내역활은·제역활을·니역활` 정탐을 잃는다(실측).
  lookahead 는 5문장 + 위 4개 전부 막고 `역활을·내 역활이·내역활은·역활분담·역활이야·역활.·역활?` 은 그대로 잡는다.
- **오탐 위험: none**. HANJA_RULES 주석에 "X역+활Y 합성어 경계" 를 적어 둘 것.

#### R7. ㄹ받침 뒤 '께' 를 무조건 어미로 봄 — 무렵/근처 접미사 `-께` (말께 · 연말께 · 15일께 · 설께 · 발께) — medium (원 보고 high)

- **관찰**: 10문장 모두 `께 → 게` (약속 어미 -ㄹ게). `koreanSpellCheck.ts:68-78` 가 '딸께'·명사 '들께' 만 빼고 어미로 본다.
  주석(`:51`)과 `MUST_NOT_FLAG:178-182` 는 높임 조사만 다룸. ko.dic 은 말께·연말께·월말께·일께·설께·주말께·발께·귓불께·무릎께 known=true.
- **재현**: `node $SP/run.mjs check '이달 말께 보자' '연말께 갈게' '설께 내려가' '15일께 온대' '주말께 볼까' '발께 놔둬'`
- **수정**: '께' 분기에 `const KKE_SUFFIX_HEADS = ['말', '일', '설', '발']; if (KKE_SUFFIX_HEADS.includes(prev)) continue;`.
  목록은 4개로 최소화(물·불·팔·무릎은 빈도 낮아 보류). 주석에 "'께'는 높임 조사·무렵 접미사(이달 말께, 15일께)로도 쓰인다" 추가.
- **오탐(놓침) 위험: low** — '그만 말께'(말다+ㄹ게)·일다·설다 는 채팅에서 극히 드물고, 고빈도 오류(할께·갈께·올께·볼께·줄께·먹을께·만들께)는 prev 가 달라 영향 없음.
  MUST_FLAG 의 '금방 갈께'·'이따 만들께'·'다시 할께' 통과 확인. 심각도는 medium 이 적절 — '말께/일께'는 기사체·달력 화법.

#### R8. `껄껄` 웃음소리 (껄껄 웃었어 · 껄껄껄 · 껄껄대며) — high

- **관찰**: 두 번째 '껄'부터 `껄 → 걸` (껄껄껄은 2건). 첫 '껄'이 ㄹ받침이라 다음 '껄'을 어미로 봄(`koreanSpellCheck.ts:78-84`, 예외 없음).
  ko.dic 껄껄·껄껄대다·껄껄거리다·껄끄럽다 known=true, 할껄·갈껄 known=false.
- **재현**: `node $SP/run.mjs check '껄껄 웃었어' '껄껄껄 웃더라' '껄껄대며 웃어'`
- **수정**: '껄' 분기에 `if (prev === '껄') continue; // 껄껄(웃음소리)` 와 `if (text[i + 1] === '끄') continue; // 껄끄럽다`.
- **오탐(놓침) 위험: none** — '껄'로 끝나는 용언 어간이 없어 진짜 -ㄹ걸이 '껄' 뒤에 올 수 없다. `허허 껄껄 웃으며 할껄` 의 '할껄'은 prev 가 '할'이라 그대로 잡힘.

#### R9. `예기(?!치)` 가 명예기자·예기불안·예기를 꺾다 를 잡음 — low (원 보고 high)

- **관찰**: 6문장 모두 `예기 → 얘기` (`명예기자 → 명얘기자`). 규칙 `koreanSpellRules.ts:294`, 주석(`:293`)·`MUST_NOT_FLAG:192` 는 '예기치' 하나만 예외.
  ko.dic 에 예기하다/예기한/예기할/예기해·명예기자·예기 known=true.
- **재현**: `node $SP/run.mjs check '예기를 꺾었어' '예기불안이 심해' '명예기자로 뽑혔어' '예기 읽어봤어?' '예기하지 못한 사태'`
- **판정**: 결함은 진짜지만 **범위·심각도는 과장**. 예기(銳氣)를 꺾다·예기(禮記)·예기소 는 커플 채팅에서 사실상 안 나오고,
  '예기하지/예기했던'(豫期)은 글자열로 '얘기하다' 오타와 못 가르며 채팅 빈도상 오타가 압도적 — 규칙의 본질적 trade-off 이지 lookahead 로 고칠 결함이 아니다.
  고칠 가치가 있는 것은 **명예기자·예기불안** 둘.
- **수정**: `/(?<!명)예기(?!치|불안|를 꺾)/g`. 원안 `/(?<![가-힣])예기(?![치를불소])/` 은 기각 — '를' 제외로 가장 흔한 오타 `예기를 해줘` 를 놓치고,
  앞 한글 전체 제외로 채팅체 `내예기 들어봐·그예기 뭐야·무슨예기야` 를 전부 놓친다(실측). 주석에 trade-off 를 문서화.
- **오탐 위험: low**(잔여 오탐 예기(禮記)·예기하지 못한 은 고칠 수 없는 것으로 명시).

#### R10. `제작년` 이 製作+年度/年月 에서 만들어짐 (제작년도 · 제작년월) — low (원 보고 high)

- **관찰**: `제작년 → 재작년` 2건 (`koreanSpellRules.ts:217`, 경계 없음). `이 영화 제작년도가 언제야 → 재작년도가`, `제작년월일 → 재작년월일`.
- **재현**: `node $SP/run.mjs check '제작년도 좀 봐 봐' '제작년월 확인해'`
- **수정**: `/제작년(?![도월])/g`. `제작년에·제작년부터·제작년 겨울` 은 계속 잡힘. 주석: "'제작년도/제작년월'은 製作+年度·年月(영화·제품 정보)라 뺀다 —
  '재작년+도(조사)'를 잘못 쓴 '제작년도'는 놓치지만 가릴 방법이 없다."
- **오탐 위험: low**. '제작년'은 verify 의 MUST_ASK·SAFE_PICK(사전층)에만 있고 MUST_FLAG 엔 없어 lookahead 가 스크립트를 깨지 않음.

### 2.3 3층 — 안전장치 (8건, 원인 4개)

#### F1. `collectTokens` 의 `/[아야]$/` 필터가 `-잔아` 계열을 통째로 차단 — high

- **관찰**: `있잔아·맛있잔아·아니잔아·그렇잔아·알잔아·좋잔아·했잔아·맞잔아·맏아` 9개 전부 `tokens: []` (`koreanDictionaryRules.ts:96`), 1층도 `[]`.
  같은 어절을 `dict.py suggest | pick-json` 으로 직접 넣으면 **9/9 정답**(있잖아·맛있잖아·…·맞아). 즉 2·3층이 고칠 수 있는 오타를 필터 하나가 전 층 침묵시킨다.
  씨앗 s1(괜찬아)의 일반형.
- **재현**: `node $SP/run.mjs tokens '있잔아' '맛있잔아' '아니잔아' '그렇잔아' '알잔아' '좋잔아' '했잔아' '맞잔아' '맏아' && python3 $SP/dict.py suggest 있잔아 맛있잔아 아니잔아 그렇잔아 알잔아 좋잔아 했잔아 맞잔아 맏아 | node $SP/run.mjs pick-json`
- **필터를 풀 수 없는 이유(실측)**: 이름·애칭·일반 '아/야' 어절 93개를 suggest→pick 에 넣으면 18개가 non-null, 그중 약 15개가 오탐
  (지훈아→지진아, 재영아→영아, 내꺼야→내어야, 시우야→시루야, 멍멍아→멍멍이). 종성만 바뀐 후보만 허용하는 변형도 아린아→아리아, 여봉아→여보아 로 실패.
  "'아/야'를 뗀 나머지가 2음절 이하"도 있잔아(3)와 동연아(3)를 못 가른다.
- **수정: 필터는 그대로, 1층 규칙으로** (파일의 캡처+`$1` 관례 — 칩에 어절 전체 '있잔아 → 있잖아'가 보인다):
  ```ts
  { re: /([있없았었겠렇좋했맞알니])잔아/g, to: '$1잖아', reason: "'-잖아'가 맞아요" }, // '니' = 아니잔아. 어간 화이트리스트라 술잔아·찻잔아·수잔아·예잔아 무반응
  ```
  + R3 의 괜찬/귀찬 규칙. `맏아` 는 규칙화하지 않는다 — `/맏아/` 는 맏아들·맏아이 를 잡는다(꼭 원하면 `/맏아(?![가-힣])/`).
  MUST_NOT_FLAG 전 50문장 + 정문 21문장에 돌려 0 hit.
- **verify 정합**: SAFE_PICK 의 `귀찬아→귀찮아`·`괜찬아→괜찮아` 는 앱에서는 pick 까지 도달하지 않는 어절이므로 주석을 붙이거나 '아/야'로 끝나지 않는 예시로 바꾼다.
- **오탐 위험: low**(이름 '귀찬'에 조사가 붙는 경우 — R3 의 lookahead 로 대부분 회피).

#### F2. `pickSafeSuggestion` 자모 동점을 "앞엣것"으로 해소 = Hunspell 순서 의존 — medium (원 보고 high)

- **관찰**: `진짜루 [진짜라, 진짜로] → 진짜라`, 순서를 뒤집으면 `진짜로`. `별루 → 벼루`(뒤집으면 별로), `죠금 → 자금`(조금), `시러 → 시어`(역순 새러).
  `tie.mjs` 로 확인: 진짜라/진짜로, 벼루/별로/별러/별수, 죠금 후보 5개 전부 무가중 자모 거리 1 동점. 코드 주석(`koreanDictionaryRules.ts:167`)은
  "동점이면 앞엣것 — 사전이 준 순서가 그나마의 근거" 라고 스스로 근거 약함을 인정. 후보 순서는 **네이티브 hunspell 1.7.2 + 앱 ko.dic 으로 직접 확인**(spylls 아님).
  실사용 노출: `진짜루 고마워·별루 안 좋아·죠금만 기다려·나 시러` 1층 침묵 + tokens 통과 → 사용자에게 '자금만' 이 나간다.
- **재현**: `node $SP/run.mjs pick '진짜루' '진짜라' '진짜로' && node $SP/run.mjs pick '진짜루' '진짜로' '진짜라' && node $SP/run.mjs pick '별루' '불려' '벼루' '벼룰' '별로' '별러' '별수' && node $SP/run.mjs pick '조아' '조라' '쪼아' '좋아'`
- **원 보고의 과장**: 헤드라인 7건 중 `아즉·머해·고마와` 는 실제 후보에 '아 즉'·'머 해'·'고 마와' 띄어쓰기 변형이 있어 기존 포기 규칙으로 이미 null 이고,
  `조아` 는 '아' 끝이라 2층에 도달하지 않는다 → 4건은 실사용 노출이 아님. "33개 노출" 수치는 배선 전체(collectTokens→1층→띄어쓰기 규칙→pick)를 거치지 않은
  원시 suggest 집계(alt.mjs)라 이 하네스로는 확인되지 않음.
- **수정**: 유일 최소일 때만 반환, 둘 이상 동점이면 null. 주석을 "Hunspell 순서는 그럴듯한 순이 아니므로 동점이면 침묵"으로 교체.
  **가중 자모 거리(된소리 쌍·ㅐ/ㅔ 쌍 = 1)는 이번에 넣지 않는다** — 표가 틀리면 새 오답을 만들므로, 220개 코퍼스를 배선 전체로 재측정한 뒤 별도 커밋.
- **비용**: 정탐 약 16건(갔따·왓어·봣어·잇어·재밋었어 등 ㅅ/ㅆ 계열) 과 SAFE_PICK '안되요' 기대값(안돼요1·안되오1 동점 → null; 1층이 '안 돼요'로 잡음).
- **오탐 위험: low**(제안을 줄이는 방향).

#### F3. 편집거리 1 게이트가 "정답이 아닌 거리 1 이웃"을 고른다 — 특히 2음절 (dist1-gate + pick-2syllable) — high

- **관찰 (dist1-gate)**: 정답이 거리 2 이상인 채팅 축약·오타에서 거리 1 인 **다른** 낱말이 나간다: `시러→시어, 어케→어께, 왜케→왜께, 추카→추가, 드러가→드러나,

## 4. 층별 패치 계획

커밋은 층별로 나누고, 각 커밋마다 `npm run verify:spellcheck && npm run typecheck`. 순서는 **3층 → 1층 오탐 → 1층 놓침 → verify 정합** 을 권합니다
(3층 두 줄이 노출 오탐 139개 중 114개(82%)를 걷어내고, 그 뒤 1층 규칙을 넣으면 사전 오답과의 겹침을 신경 쓸 일이 줄어듭니다).

### 4.1 3층 `koreanDictionaryRules.ts` — 코드 스케치

```ts
export function pickSafeSuggestion(word: string, candidates: string[]): string | null {
  // (F3) 2음절은 거리 1 이웃이 수백 개라 어떤 어절이든 후보가 하나쯤 있다 —
  //      남친→남진, 카톡→톡톡, 죄송→죄소, 웅웅→영웅. 2음절 진짜 오타는 1층 규칙(갯수·됬어·궂이·뵈요·희안)이 담당한다.
  if ([...word].length <= 2) return null;

  // (F4) 사전이 'X Y'(띄어쓰기 변형)를 후보로 냈다면 그 어절은 "붙여 쓴 채팅체" 가설이 성립한다.
  //      채팅 띄어쓰기는 지적하지 않는 것이 원칙이므로 후보 수와 무관하게 침묵 —
  //      퇴근중→퇴근길, 먹을때→먹을래, 보고싶어→보고시어 같은 엉뚱한 낱말이 나갔다. 제작년·어렵던대는 1층이 잡는다.
  if (candidates.some((c) => isSpacingVariant(word, c))) return null;

  const safe = candidates.filter((c) => !c.includes(' ') && editDistance(word, c) === 1);
  if (safe.length === 0) return null;

  // (F2) 자모 거리 최소가 유일할 때만 반환. Hunspell 순서는 그럴듯한 순이 아니므로 동점이면 침묵 —
  //      진짜루 [진짜라,진짜로], 별루 [벼루,별로], 죠금 [자금,지금,조금,…] 은 전부 자모 거리 1 동점이었다.
  let best = safe[0], bestDist = jamoDistance(word, best), tie = false;
  for (let i = 1; i < safe.length; i++) {
    const d = jamoDistance(word, safe[i]);
    if (d < bestDist) { best = safe[i]; bestDist = d; tie = false; }
    else if (d === bestDist) tie = true;
  }
  return tie ? null : best;
}
```

- (R1 핑퐁) `collectTokens` 또는 `checkWithDictionary` 에 `'어떡하'` 로 시작하는 어절은 묻지 않는 예외 + `MUST_NOT_ASK` '어떡하면'.
- (X4 선택) `koreanDictionary.ts` checkWithDictionary: 벗긴 형태(stripNasalEnding)도 unknown 이면 suggest 를 건너뛴다(침묵). 왓엉→엉엉·봣엉→부엉 차단. 억제 방향.
- 가중 자모 거리는 **이번에 넣지 않는다**. 넣으려면 220개 코퍼스를 배선 전체(collectTokens→1층→pick)로 통과시킨 노출 집계를 먼저 재측정.

**2층 판단(allowlist vs 사전 보강)**: ko.dic 은 건드리지 않는다. 표준 표기가 '이번 주'인 어절을 사전에 넣는 것은 사전을 비표준으로 오염시키고 네이티브 dic 재빌드가 필요하다.
F3+F4 적용 후 잔여 오탐 25개(아메리카노·스쿼트·웨이트·트레이너·인바디·오트밀·에이드·하이볼·에어팟·베이비·호캉스·푸시업·다이어터·플렉스·저메추·썸타다·인터벌·눙치다·다이소·카카오·맘스터치·비비큐·아우디·포르쉐·안다르)만
앱 측 **소형 allowlist**(collectTokens 통과 또는 known 처리) 후보로 남긴다. 이 목록은 실기기에서 실제로 노출되는지 확인한 뒤(§5) 넣는다.
