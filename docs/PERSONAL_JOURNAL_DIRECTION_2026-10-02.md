## 1. 무엇인가

**상대에게 보이지 않는, 나에게 쓰는 오늘의 기록.** 밥 일기(럽바디)와 별개다. 기분 + 몇 줄 + (선택) 사진 한 장.

## 2. 왜 Dubly 에 맞나

| 이유 | 설명 |
| --- | --- |
| 혼자서도 매일 열 이유 | 지금 기능은 대부분 "둘이 해야" 의미가 있다. 상대가 바쁘거나 미연결이면 할 게 없다. 미연결 홈 "혼자서도 시작할 수 있어요"에도 들어간다 |
| 이별 후에도 남는 기록 | **관계가 아니라 사용자에게 저장**하면 관계가 끝나도 남는다. `LIFECYCLE_DIRECTION` §4-4 의 "이별 이탈은 막지 못한다"를 일부 보완 |
| 이미 쌓이는 하루 데이터 | 오늘 무드·먹은 것·운동 여부·오늘의 질문 답·둘의 사진을 **하루 페이지 밑바탕**으로 자동 정리 → 사용자는 한두 줄만. 일반 일기 앱과의 차별점 |

## 3. 원칙 (확정)

1. **진짜 비공개.** 상대·트레이너·가족 어떤 API 응답에도 실리지 않는다. 피드·주간 레터·AI 코칭·알림 미리보기에 섞이지 않는다.
   → 선행: `LOVEBODY_REVIEW` A-4(상대용 DTO 축소)가 먼저다.
2. **저장 단위는 `user_id`.** `relation_id` 에 묶지 않는다. 삭제는 탈퇴(`UserDataPurger`)에서만. `RelationRecordPurger`·"지난 기록 삭제"는 건드리지 않는다.
   단 밑바탕으로 보여주는 커플 데이터(둘의 사진·질문 답)는 **복사하지 않고 참조**만 — 관계가 지워지면 그 부분만 빈다.
3. **AI 는 동의할 때만.** 일기 본문을 AI(월간 회고 등)에 보내는 건 사용자가 켰을 때만. 기본 꺼짐.
4. **입구를 늘리지 않는다.** 홈 칩 3개 결정 유지. 1순위 입구 = **무드를 고른 직후 "한 줄 남기기"**(홈 왼쪽 위 무드 버튼 → MoodPicker).
5. **공유는 선택.** 쓴 뒤 "우리 기록에 공유하기"로 피드에 올릴 수 있다(복사본 게시 — 원본 일기는 비공개로 남음).
6. **민감정보 최소화.** 건강 수치·생리 등 구조화 필드를 넣지 않는다(`LIFECYCLE_DIRECTION` 원칙). 자유 텍스트 + 무드 + 사진만.

## 5. 열린 질문 (Code 분석으로 답할 것)

1. 하루 1개(날짜 유니크) vs 여러 개.
2. 밑바탕 자동 정리에 쓸 데이터의 실제 출처와 비용(API 몇 번, 새 집계 엔드포인트 필요 여부).
3. 사진 업로드 한도 — `PHOTO_UPLOAD` 는 커플 단위인데 개인 기록 사진을 어디에 셀지.
4. 무드와의 관계 — 무드 상태(현재값)와 하루 기록의 무드(그날 값)를 하나로 볼지.
5. 화면 위치 — 기록 목록·달력 보기를 어느 탭/스택에 둘지(MY? 우리 탭?).
6. FREE/PRO — 기록 자체는 무료가 원칙("데이터 인질 금지"), 월간 AI 회고만 PRO 후보.
7. 내보내기 — 기존 `CSV_EXPORT` 에 포함할지.
