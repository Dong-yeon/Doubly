# 사진 저장소 한도·비용 — 수익 없이 버티는 법 (2026-10-12)

질문: "사진이 25GB 를 넘으면 사라지잖아. 어떻게 해야 할까? 늘리면 돈이 드는데 지금 수익이 없다."

## 사실 확인

**"25GB"가 아니라 "월 25크레딧"이다.** Cloudinary 무료는 저장 1GB · 보기 전송 1GB · 변환 1,000회가 각각 1크레딧이고, 셋을 합쳐 월 25크레딧(전송·변환은 최근 30일 기준).

운영 실측(Admin API `/usage`, 2026-10-11 기준):

| 항목 | 사용량 | 크레딧 |
|---|---|---|
| 저장 | 0.97GB (원본 408 + 변환본 464) | 0.91 |
| 전송(사진 보기) | 3.2GB / 30일 | **2.98** |
| 변환 | 864회 | 0.86 |
| 합계 | | **4.75 / 25 (19%)** |

- 지금 한 커플(실사용 2명)이 한 달에 약 4.75크레딧 → **이 사용 패턴이면 활성 커플 5쌍 안팎이 무료 한도의 벽**이다. 쌓인 용량보다 **보는 전송량**이 먼저 찬다.
- **넘는다고 바로 지워지지 않는다.** 공식 설명: 한도는 소프트 리밋 → 경고 메일 반복 → 그래도 조치가 없으면 계정 비활성화(업로드·전송 중단 = 앱에서 사진이 안 뜬다)
  → **비활성 상태로 30일이 지나면 계정의 모든 에셋이 영구 삭제.** 무료 플랜에는 초과 과금이 없다(넘으면 유료 플랜으로 올리는 수밖에).
- **9/30 에 켠 Cloudinary 자동 백업은 이 시나리오를 못 막는다** — 백업도 같은 Cloudinary 계정 안에 있어 계정과 함께 사라진다.

## 비용 비교

| 선택 | 월 비용 |
|---|---|
| Cloudinary 유료(Plus) | 약 $89~99 — 수익 0 에서는 불가 |
| **Cloudflare R2** | 저장 10GB·쓰기 100만·읽기 1,000만 회까지 무료, **전송(egress) 무료**, 초과 저장 $0.015/GB — 25GB ≈ $0.23, 100GB ≈ $1.35 |

R2 는 지금 병목인 "보기 전송"이 공짜라, 이 앱의 비용 구조와 맞는다(docs/IMAGE_UPLOAD.md 의 전환 계획과 같은 결론).

## 할 일 (순서)

1. **지금 · 0원** — Cloudinary 경고 메일이 오는 주소를 확인하고, 사용량을 주기적으로 본다(Admin API `/usage`; 50%·80% 넘으면 알림을 받게 서버 스케줄러나 예약 작업으로).
2. **지금 · 거의 0원** — Cloudinary **밖**에 원본 사본을 둔다. R2 버킷을 만들고 기존 사진(약 1GB)을 복사 — 무료 범위.
   이게 "30일 뒤 전부 삭제"의 유일한 보험이다(docs/DATA_SAFETY_INFRA_2026-09-30.md 의 외부 백업 숙제와 같은 일).
3. **커플이 더 붙기 전(크레딧 50% 무렵)** — 새 업로드를 R2 로 바꾼다(IMAGE_UPLOAD.md "전환 표면", 반나절). 이미 올라간 Cloudinary 주소는 그대로 동작해 병행 전환된다.
   AI 분석용 축소(CloudinaryImageFetcher 의 w_1024 변환)는 앱이 이미 1024px 로 줄여 올리므로 R2 에선 필요 없다.
4. **그 뒤** — Cloudinary 쪽 옛 사진을 R2 로 옮기고 DB 주소를 바꾼 뒤 Cloudinary 를 정리한다(급하지 않다).

동영상 전송·사진 무제한 같은 기능은 3번 이후에 판단한다(docs/chat-video-decision_2026-10-12.md).
