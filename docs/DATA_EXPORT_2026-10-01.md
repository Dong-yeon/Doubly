# 기록 내보내기 (사진 포함) — 설계 결론과 구현 (2026-10-01)

선행: `docs/BETWEEN_GAP_CHECK_2026-09-30.md`("내보내기" 갭), `docs/DATA_SAFETY_INFRA_2026-09-30.md`
(탈퇴 유예 "남은 것: 유예기간 중 상대의 기록 내보내기"). 둘을 **한 기능**으로 묶었다.

목적은 하나다 — **"내 기록은 언제든 가져갈 수 있다."** 그래서 결제와 무관하다.

## 1. 결정 (사용자 확정)

| # | 질문 | 결정 | 이유 |
|---|---|---|---|
| 1 | 결과물 | **ZIP 한 파일 + "사진을 갤러리에도 저장" 선택지** | 백업은 "파일 하나를 어디 넣어 두는" 일이다. 갤러리는 덤 |
| 2 | 끊긴(ENDED) 관계 | **이번엔 제외** | 헤어진 상대의 채팅·사진을 한쪽이 혼자 가져가는 건 따로 판단할 문제. 복원하면 다시 대상 |
| 3 | 웹 | **기록만** (사진·음성은 앱에서) | 수백 MB 를 브라우저 메모리로 묶으면 탭이 죽고, 이어받을 저장소도 없다 |
| 4 | 한도 | **무제한은 안 됨 → FREE·PRO 같은 주 2회** | 원가 방어선. 플랜과 무관하게 같고, 넘겨도 결제를 권하지 않는다 |

## 2. 서버 ZIP vs 목록 + 앱 저장 — 앱 저장으로

| | 서버가 ZIP | **서버는 목록, 앱이 받아 묶기** |
|---|---|---|
| Cloudinary 대역폭 | Cloudinary→Railway→사용자 **두 번** | **한 번** |
| Railway | 수천 장 스트리밍 = 긴 요청, 끊길 위험·스레드 점유 | 페이지 JSON 조회뿐 |
| 끊기면 | 처음부터(또는 서버 임시 저장소 필요) | 받은 파일은 건너뛰고 이어받기 |
| 원가 통제 | 서버가 막을 수 있다 | URL 이 공개라 어차피 못 막는다(지금도 그렇다) |

전체 1회 ≈ 사진 2,000장 × 250KB ≈ 0.5GB ≈ Cloudinary 0.5 credit. 서버 ZIP 은 이걸 두 배로 만들 뿐이다.

## 3. 범위 — 공동 기록은 둘 다, 개인 기록은 내 것만

`backend/.../dataexport/ExportSection.java` 가 목록의 단일 출처다(테이블 하나 = 섹션 하나).

- **공동**: 우리 둘(관계)·사람(이름표), 피드+사진, 여행(일정·지출·준비물), 럽슐랭(장소·방문·평가),
  콘텐츠(감상·평가), 채팅(지운 메시지 제외, **상한 없이 페이지로**), 오늘의 질문, 기념일·일정, 무드,
  챌린지, 우리 이모지(지운 것 제외), 운동 응원 음성
- **나**: 내 정보(비밀번호·소셜 id 제외 — 컬럼 지정), 식단+음식, 운동+종목+세트, 신체 기록, 음성 클립, 물, 단식
- **제외**: 게임 판(스도쿠·오목·캐치마인드 획), 통화 기록, 리액션·북마크, **상대의 개인 기록**,
  콘텐츠 포스터(외부 작품 DB 이미지 — 우리가 올린 게 아니다)

행은 **스키마 그대로** 내보낸다(엔티티 DTO 없음). 섹션이 30개 가까운데 DTO 를 두면 컬럼이 늘 때마다
내보내기만 조용히 뒤처진다. 비밀이 섞인 테이블(`users`)만 컬럼을 지정한다.
**새 커플 콘텐츠 테이블을 만들면 `ExportSection` 에도 한 줄** — Purger 규칙(CLAUDE.md 4절)과 짝이다.

> **사진은 "원본"이 아니다.** 앱이 올리기 전에 긴 변 1024px JPEG q0.8 로 줄인다(`imageUpload.ts` shrinkImage).
> 서버에 있는 그 파일을 재압축 없이 그대로 담는다. 화면·README 에 그렇게 적었다 — 스토어 문구도 "원본" 금지.

## 4. API (새 테이블 없음 → Flyway·Purger 변경 없음)

| | 횟수 |
|---|---|
| `GET /api/v1/export/summary` — 섹션별 건수·파일 수·예상 용량·남은 횟수 | 안 씀 |
| `POST /api/v1/export/start` — 새 내보내기 시작 | **1회 씀** (`PlanGuard.consume(CSV_EXPORT)`) |
| `GET /api/v1/export/sections/{key}?cursor=&limit=` — id keyset 페이지(최대 500) + 파일 참조 | 안 씀 |

- **relationId 를 받지 않는다.** 토큰의 사용자 → 그 사람의 ACTIVE 커플. 남의 관계를 지정할 길이 없다.
- 섹션 조회가 횟수를 안 쓰는 이유: 화면에서 이미 보이는 내 기록을 다시 읽는 것이고, 그래야 이어받기가 공짜다.
- 음성 메시지는 URL 이 `content` 안(`"{url}|{초}"`)에 있어 따로 꺼낸다.
- 피드 첫 사진은 `feed_posts.image_url` 과 `feed_post_photos` 에 **둘 다** 있다(V79, 의도한 중복) — 요약은
  겹치는 것을 빼고 세고, 앱은 URL 로 한 번만 받는다.

### 과금 쪽 변경 — `CSV_EXPORT`

- `Quota.perMonth(1) / perWeek(1)` → **`perWeek(2) / perWeek(2)`**. 키 이름은 사용량·이벤트가 문자열로 들고
  있어 그대로(CSV 는 처음 계획의 흔적).
- 두 값이 같아져 `isListed()` 가 false → **플랜 화면 비교표에서 빠진다.** 그동안 비교표에 **존재하지 않는
  기능이 "월 1회 / 주 1회"로 떠 있었다**(`docs/STORE_TRUST_COPY_2026-09-30.md` §6 이 지적한 충돌) — 함께 해소.
- 커플 단위 판정에서 뺐다(개인 주머니) — 상대가 쓴 횟수 때문에 내가 못 받으면 안 된다(탈퇴 유예 중 등).
- **`PlanGuard.upsells(feature, plan)` 신설**: 402(결제 안내)와 429 를 가르는 근거를 "최상위 플랜인가"에서
  "**결제하면 풀리는가**"(= PRO 이상이 아니고 **FREE·PRO 한도가 다를 때**)로 바꿨다. 한도가 같은 기능을
  FREE 가 넘겼을 때 402 를 주면 앱이 결제 시트를 띄워 "돈 내면 풀린다"는 거짓말을 한다.
  `FeatureState.upgradable` 도 같은 함수를 본다. 부수 효과: `AI_TOTAL`(플랜 무관 안전망)도 FREE 에서 429 가 된다 — 맞는 방향.

## 5. 앱 (`frontend/src/utils/recordExport.ts`, 화면 `screens/my/RecordExportScreen.tsx`)

1. **요약** — 건수·파일 수·예상 용량, 남은 저장공간이 예상의 2.2배 미만이면 경고(묶는 동안 원본+ZIP 이 잠깐 같이 있다).
2. **기록 받기** — 섹션별로 `data/<key>.json` 에 페이지를 이어 쓴다. 섹션 하나가 끝나야 "끝남".
3. **파일 받기** — 4개씩 동시, 실패 시 3번(1s·4s·9s), **403/404/410 은 "서버에 없음"으로 바로 넘김**,
   네트워크가 끊기면 기회를 깎지 않고 돌아올 때까지 기다린다(NetInfo). 갤러리 저장을 고르면 받는 즉시 저장
   (`saved` 표시로 이어받을 때 두 번 안 들어감).
4. **묶기** — `zipWriter.ts`(의존성 없는 store ZIP, UTF-8 이름, ZIP64 없음 → 4GB·65,535개 한도) 로
   `FileHandle.writeBytes` 에 한 파일씩 흘려 쓴다. 다 묶으면 임시 파일을 지우고 ZIP 만 남긴다.
5. **저장** — 공유 시트(파일·드라이브). 받지 못한 목록은 README.txt.

- 상태는 **문서 폴더**의 `dubly-export/state.json`(캐시는 OS 가 말없이 지워 이어받기가 처음부터가 된다).
  화면을 떠나면 멈추고, 다시 오면 "이어서 받기 / 지우기". 이어받기는 횟수를 쓰지 않는다.
- iOS 는 백그라운드로 가면 받기가 멈춘다 — 백그라운드 다운로드는 네이티브 작업이라 하지 않았다. 받는 동안
  화면을 켜 둔다(`expo-keep-awake`, 이미 설치됨).
- **새 의존성 없음 → EAS Update(OTA)로 나간다.** (`expo-file-system`·`expo-sharing`·`expo-media-library`·
  NetInfo·keep-awake 전부 기존 설치분)

ZIP 구성:
```
Dubly_기록_2026-10-01.zip
├─ index.html   ← 압축을 풀면 오프라인으로 열리는 목록(사진은 상대 경로)
├─ README.txt   ← 설명·담긴 기록·받지 못한 파일 (BOM — 윈도 메모장 한글)
├─ chat.txt     ← 채팅 전체, 사진·음성은 ZIP 안 경로를 덧붙임
├─ data/<섹션>.json
├─ photos/<섹션>/<행id>_<컬럼>.jpg
└─ audio/<섹션>/<행id>_<컬럼>.m4a
```

진입점: MY → "내 기록 내보내기" · 홈의 **상대 탈퇴 예정 배너**("사진·채팅까지 기록 받기 ›") ·
**회원 탈퇴 확인 창**("기록 먼저 받기"). 마지막이 필요한 이유 — 탈퇴한 본인은 **로그인하는 순간 탈퇴가
취소**되므로(`AccountWithdrawalService.cancelIfPending`) 유예기간 중에 받을 수 없다. 탈퇴 **전**에 받아야 한다.
