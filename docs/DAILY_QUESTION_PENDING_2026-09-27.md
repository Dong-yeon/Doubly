# 오늘의 질문 — 한쪽만 답한 질문을 남기기 (2026-09-27)

## 1. 증상과 원인

"상대가 답해도 내가 오늘을 넘기면 없는 데이터가 된다."

**데이터는 지워지지 않았다 — 보여 줄 곳이 없었다.** `daily_answers` 에 상대 행은 그대로 있다.
그런데 조회 경로가 둘뿐이었다.

| 경로 | 보여 주는 것 | 상대만 답한 지난 날 |
| --- | --- | --- |
| `GET /daily-question` | `KstClock.today()` 날짜만 | 날이 바뀌면 빠짐 |
| `GET /daily-question/history` | 둘 다 답한 날만 | `mine != null && theirs != null` 에서 걸러짐 |
| `POST /daily-question` | 오늘 날짜로만 저장 | 지난 날짜에 답할 방법 없음 |

그래서 상대의 답은 DB 에만 남고 누구에게도 다시 보이지 않았다.

## 2. 결정

**한쪽만 답한 지난 질문은 남은 사람에게 기한 없이 "답을 기다리는 질문"으로 남는다.**

- `GET /daily-question/pending` — 상대는 답했고 나는 안 한 지난 날(최근순). **상대 답은 싣지 않는다** —
  "내가 답해야 서로 공개"는 지난 질문에도 같다.
- `POST /daily-question` 에 선택 필드 `questionDate`. 비우면 오늘(**예전 앱 그대로 동작**).
  지난 날짜는 pending 에 뜨는 날만 받는다. 답하면 둘의 답이 열리고 히스토리로 옮겨 간다.
  기다리던 상대에게 "지난 질문에 답했어요. 이제 서로의 답을 볼 수 있어요!" 푸시.
- 질문 문구는 카탈로그가 아니라 **상대 행의 스냅샷**(`question_text`)을 쓴다 — 카탈로그 순서가
  바뀌어도 상대가 답한 그 질문이어야 한다.
- 앱: 오늘 카드 아래 "답을 기다리는 질문 N" — 카드별 "답하기"로 펼쳐 답한다(한 번에 하나).
- 스키마 변경 없음(Flyway 불필요). 쿼리는 JPQL `not exists` 하나 — 유니크 인덱스
  `(couple_id, question_date, user_id)` 를 그대로 탄다.

| 거부한 것 | 이유 |
| --- | --- |
| 지난 답 수정 | 상대가 이미 읽은 답이 바뀐다. 오늘 답 수정과 달리 상대는 알 길이 없다 |
| 둘 다 안 답한 지난 날에 답하기 | 기다리는 사람이 없는 질문 — 되살리면 "밀린 숙제"가 된다 |
| 미래 날짜 | 질문이 아직 안 열렸다 |
| 기다리는 질문에 만료(예: 7일) | 요청이 "계속 유지". 쌓여도 한 사람이 매일 답한 만큼만 쌓인다 |
| 기존 응답(`DailyQuestionResponse`)에 목록 끼워 넣기 | 별도 엔드포인트가 예전 앱과의 호환이 깔끔하다 |

## 3. 검증

- 신규 `DailyQuestionPendingFlowTest` 4건: 기다리는 질문 목록·먼저 답한 쪽엔 안 뜸·히스토리 제외 /
  지난 질문 답 → 서로 공개·스냅샷 문구·히스토리 이동·오늘 질문 불변 / 둘 다 안 답한 날·미래·재답변 거부 /
  날짜 생략·오늘 날짜는 기존 동작(오늘 답 수정 허용).
- H2 와 **PostgreSQL 16 양쪽**에서 question·Reengagement·Withdraw 테스트 23건 통과.
- 프론트 `typecheck`·`verify:nested-buttons` 통과, 웹 export 후 API 목킹으로 렌더 확인
  (목록 2개 → 답하기 → 전송 바디 `questionDate` 포함 → 목록 1개·지난 질문에 둘의 답).
- **미검증**: 실기기, 실제 푸시 수신.

## 4. 배포 순서

백엔드 먼저(Railway). 앱은 JS 만 바뀌어 EAS Update 로 충분하다. 앱이 먼저 나가도 `pending()` 실패는
빈 목록으로 삼켜 화면이 깨지지 않는다(단 섹션이 안 보일 뿐).
