# 우리 이모지 만들기 화면 — UI/UX 객관 분석 (2026-09-29)

> 근거: 실기기(10A30Q, 서준=리뷰어A 계정, PRO)에서 한 세트를 끝까지 만들며 본 화면 + `CoupleEmojiCreateScreen.tsx`.
> 질문: "감정이 너무 많지 않나? 너무 복잡하지 않나?"

## 1. 지금 흐름

```
[만들기 화면]  안내 한 줄 → ① 누구 얼굴(상대/나) → 안내문 → ② 감정 17종 중 1~5개(기본 5개 미리 골라 둠)
              → 안내문 → ③ [사진 고르기] / [촬영하기]
[자르기 화면]  ④ 동그라미에 얼굴 맞추기 → 완료
[진행 격자]    그리는 5칸(1~2분) → [채팅에서 쓰기]
```

사용자가 내리는 결정은 **4번**(누구·감정·사진·자르기)이고, 이 중 **감정 고르기**가 가장 무겁다.

## 2. 결론 — "감정이 너무 많다"는 맞다. 다만 17종이 문제가 아니라 보여주는 방식이 문제다

| 판단 | 근거 |
| --- | --- |
| 17종 **자체**는 과하지 않다 | 카톡 이모티콘 한 세트가 24~32종이다. 우리 이모지는 결국 여러 번에 나눠 17종을 다 채우는 구조라 개수는 "모을 거리"로 작동한다 |
| **한 화면에 17개를 평평하게 펼친 것**이 무겁다 | 표정 6종(화남·기쁨·신남·슬픔·졸림·사랑)과 상황 11종(씻고왔다·꽃다발·출근…)이 구분 없이 섞여 있다. 칩 17개 + "5개까지" 규칙 + 이미 가진 감정의 점 표시를 한 번에 읽어야 한다 |
| **"5개까지"와 "표정 6종"이 어긋난다** | 기본 표정이 6종인데 한 번에 5장까지라, 첫 세트로 기본 표정조차 다 못 채운다. 사용자는 "왜 하나가 빠지지?"를 스스로 풀어야 한다 |
| **대부분은 고르지 않는다** | 이미 "아직 없는 것부터 5개"를 미리 골라 둔다. 고르지 않는 사람에게 17개 칩은 읽을 필요 없는 장애물이다 |

## 3. 화면에서 본 결함 (방향과 무관하게 고칠 것)

| # | 심각도 | 내용 |
| --- | --- | --- |
| U1 | 🟠 | 진행·결과 격자의 둘째 줄이 **양 끝으로 벌어진다** — 5장이면 [졸림 · (빈칸) · 사랑]. 3열에서 마지막 줄이 space-between 으로 퍼지는 모양. 왼쪽부터 채워야 한다 |
| U2 | 🟡 | 제목 "**나** 이모지를 그리는 중이에요 / 만들어졌어요" — "내 이모지"가 맞다(상대는 "지민 이모지") |
| U3 | 🟡 | 대상 칩이 "**나 나**"로 읽힌다 — 아바타 자리의 글자 "나"와 이름표 "나"가 나란히 붙는다 |
| U4 | 🟡 | 자르기 화면 제목이 "**프로필 사진**" — 프로필 사진 자르기 화면을 재사용해서다. "얼굴 맞추기" 등으로 |
| U5 | 🟡 | 그리는 동안 주 버튼이 초록 빈 막대에 점 하나(로딩 표시가 거의 안 보인다), "촬영하기"는 흐린 채 남아 있다 — 진행 중에는 숨기고 격자·안내문만 |
| U6 | 🟡 | 남은 횟수(PRO 월 4세트·산 세트)가 이 화면에 없다 — 다 쓰고 나서야 안다. 버튼 옆에 "이번 달 3세트 남음" 한 줄 |
| U7 | 🟡 | 결과 화면에 "이어서 만들기"가 없다 — 17종을 채우려면 뒤로 갔다 다시 들어와야 한다 |

(참고: 이름 편집 시트는 키보드가 올라오면 **시트가 키보드 뒤로 가려진다** — 이 화면 밖의 결함이라 따로 적는다.)

## 4. 제안 — 감정 고르기를 "접어 둔다"

```
누구 얼굴로 만들까요?   [지민]  [나]
만들 감정  😊 🥳 😢 😴 🥰  ·  바꾸기 ›          ← 한 줄. 누르면 지금의 17칩 시트
                                                  (표정 6 / 상황 11 두 묶음으로)
[ 사진 고르기 ]  [ 촬영하기 ]
이번 달 3세트 남음 · 사진은 저장하지 않아요
```

- 기본 흐름이 **누구 → 사진** 두 결정으로 줄어든다. 감정은 이미 좋은 기본값이 있으니 "바꾸고 싶은 사람만" 연다.
- 시트 안에서는 **표정 6 / 상황 11** 두 묶음으로 나눠, 무엇을 모으는지 구조가 보이게 한다. 이미 가진 감정의 점은 유지.
- **표정 6 vs 5장 한도**: 한도를 6으로 올리면(요청당 원가 +$0.045) 첫 세트가 "기본 표정 한 벌"로 딱 떨어진다. 한도를 그대로 두면 첫 세트 기본값에서 하나를 빼는 이유를 문구로 말해야 한다("나머지 하나는 다음에"). → **결정 필요**.
- 비용: 화면 재배치(소~중). 서버 변경은 한도를 6으로 올릴 때만(`MAX_EMOTIONS_PER_REQUEST`, 요청 검증·테스트).

## 5. 좋았던 것 (유지)

- 사진 저장 안 함 안내가 맨 위에 한 줄로 — 동의 화면 없이 신뢰를 준다.
- 없는 감정부터 5개를 미리 골라 둔다 — 아무것도 안 건드려도 가장 합리적인 세트가 나온다.
- 결과 5장이 같은 인물로 일관되게 나왔다(가상 인물 사진 기준, 2단계 생성).
- 격자가 그리는 감정 순서대로 채워진다(2026-09-28 P0 수정이 실기기에서 확인됨).

## 6. 구현 (2026-09-29, 같은 날)

- **감정 고르기를 접었다**: "만들 감정 (6/6) 😠😊🎉😢😴🥰 · 바꾸기 ›" 한 줄. 바꾸기 → 하단 시트에 **표정 6 / 상황 11** 두 묶음.
- **한 번에 6장**(서버 `MAX_EMOTIONS_PER_REQUEST` 5→6, 앱 `MAX_EMOJI_PER_REQUEST` 5→6). 첫 세트 기본값이 표정 한 벌이다.
- U1 격자 마지막 줄 왼쪽부터(빈 칸으로 채움) · U2 "내 이모지" · U3 칩 아바타 글자를 진짜 이름에서 · U4 자르기 제목 "얼굴 맞추기" ·
  U5 그리는 동안 버튼 숨김 · U6 "N세트 더 만들 수 있어요"(산 세트 포함) · U7 결과 화면 "이어서 더 만들기".
- 방전 자리표시 🪫(Emoji 14, 구형 안드로이드에서 네모) → 😩.
- 실기기(10A30Q)에서 접힌 줄·시트·남은 횟수 확인. 서버 한도 변경은 **백엔드 배포 후** 앱에서 6장이 된다 — 앱만 먼저 나가면
  6장 요청이 400 으로 거절된다(배포 순서: 서버 → 앱).
