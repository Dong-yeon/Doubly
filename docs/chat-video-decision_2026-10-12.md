# 채팅 동영상 — 왜 막아 두었고, 열려면 무엇이 필요한가 (2026-10-12)

질문: "채팅에서 사진은 되는데 동영상은 막아 놨다. 동영상을 보내면 문제가 뭘까? 파일이 쌓이는 게 문제지?"

## 결론

쌓이는 것(저장 용량)이 가장 큰 문제는 맞지만 그것 하나가 아니다. **지금 구조(Cloudinary 무료 · 변환 미사용 · 앱이 원본을 그대로 재생)에서는 막아 두는 게 맞다.**
열려면 저장소 이전(R2)과 앱 빌드가 먼저다.

## 문제 목록 (근거)

1. **용량** — 채팅 사진은 1024px 로 줄여 약 250KB(docs/DATA_EXPORT_2026-10-01.md). 폰 동영상은 1080p 기준 1분에 대략 50~150MB —
   30초 영상 한 편이 사진 수백 장이다. Cloudinary 무료 ≈25크레딧(저장·전송·변환 공용)은 README "사진 보관 정책"이 이미
   "커플 1~2쌍이면 소진, 동영상까지 넣으면 객체 스토리지 이전 + 월 수만원대"로 적어 둔 선이다. 자동 백업을 켜 둬서(2026-09-30) 저장량은 약 2배로 잡힌다.
2. **전송량(egress)이 더 아프다** — 변환을 안 쓰므로 볼 때마다 원본 전체를 내려받는다. 둘이 각자 보고, 다시 보고, 기기를 바꾸면 또 받는다.
   docs/IMAGE_UPLOAD.md 가 R2(egress 무료)로 옮길 이유로 든 게 바로 이것이다.
3. **올리기가 잘 실패한다** — 수십 MB 를 이어받기 없이 한 번에 올린다. 모바일 회선·앱을 내리는 순간 끊긴다(오늘 홈 식단 사진에서 본 것과 같은 문제가 훨씬 크게).
   상대도 셀룰러로 받으면 데이터를 쓴다.
4. **재생·호환** — 앱에 동영상 재생 모듈이 없다(expo-video 등 추가 = 네이티브 = **빌드**, fingerprint 변경). 아이폰 HEVC(.mov)는 일부 안드로이드에서 안 열린다 →
   변환이 필요한데, 서버 변환은 Cloudinary 크레딧이고 앱 압축도 네이티브 라이브러리(빌드)다. 썸네일·채팅 목록 스크롤 성능도 따로 챙겨야 한다.
5. **부수 경로가 같이 커진다** — 기록 내보내기 ZIP(사진 포함)이 몇 배가 되고, 탈퇴·관계 삭제 때의 Cloudinary 삭제(CloudinaryImageDeleter 는 video 리소스도 이미 구분한다)·
   고아 정리·한도(PlanGuard 기능 키)가 새로 필요하다.
6. **공개 URL** — 업로드는 공개 URL 이다(docs/DATA_SAFETY_INFRA_2026-09-30.md). 사진보다 동영상이 더 사적인 경우가 많은 커플 앱이라 노출 비용이 크다.

## 열게 된다면 (순서)

1. 저장소를 R2 로 옮긴다(IMAGE_UPLOAD.md 전환 표면 — 반나절 규모, 기존 URL 은 그대로 동작).
2. 앱에서 보내기 전에 압축(720p·길이 상한 30~60초 → 한 편 수 MB) + 재생 모듈 — 둘 다 네이티브라 다음 빌드에 묶는다.
3. 기능 키 하나(음성 메시지 VOICE_MESSAGE 처럼 하루 개수 한도, FREE 적게) — PlanGuard 를 지나야 계측에도 잡힌다.
4. 실패해도 잃지 않게 — 오늘 만든 식단 사진 보관함과 같은 방식(먼저 적고 나중에 올리기).

대안(비용 0): 여행·일정에 구글포토 공유 앨범 링크를 붙이는 필드(README 권장안, 미구현).
