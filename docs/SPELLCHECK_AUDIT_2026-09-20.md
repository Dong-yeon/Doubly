## 1. 방법

### 1-1. 하네스 — 앱 코드를 그대로 싣는다
`run.mjs` 는 `verify-spellcheck.mjs` 와 같은 방식으로 `koreanSpellCheck.ts`·`koreanSpellRules.ts`·`koreanDictionaryRules.ts` 를 Node 22 에서 직접 import 한다(1층·3층은 **앱 코드 그 자체**). `dict.py` 는 앱이 번들한 `ko.aff/ko.dic` 을 **시스템 Hunspell 1.7.2 CLI**(`-a` 파이프)로 돌린다. `e2e` 명령이 `ChatRoomScreen` 의 합산(1층 → 3층 collectTokens → 2층 suggest → stripNasalEnding 면제 → pickSafeSuggestion → dedupeOverlapping)을 재현한다.

### 1-2. 오라클 교체 이력 — 철회 사항 포함
처음엔 순수 파이썬 Hunspell(spylls)을 썼는데 이 `ko.aff`(ICONV 로 음절→자모 분해 뒤 처리)에서 **`suggest` 가 항상 빈 배열**이었고 **`lookup` 도 틀렸다**(헬스·데이트·뽀뽀·커플·맛집을 없음으로 판정). 그 단계에서 낸 "헬스→헬세 오탐"은 **철회**됐다. 이후 모든 수치는 진짜 Hunspell 기준이다.

### 1-3. 하네스 ↔ 네이티브 일치 (부록 `native-parity.md`)
- 번들 소스(`modules/korean-spell/cpp/hunspell/*`) 16개 파일이 upstream **v1.7.2 태그와 바이트 단위 동일**. 하네스 CLI 도 1.7.2. ICONV/OCONV 는 라이브러리 안에서 적용되므로 네이티브·CLI 모두 raw 문자열을 넘긴다 → 같다.
- 어절 1,189개를 CLI 와 **번들 소스를 직접 컴파일한 바이너리**에 넣어 비교: known 1,189/1,189 일치, 후보 목록·순서 1,189/1,189 일치.
- **유일한 차이는 시간 제한**(§6).

### 1-4. 판정 규칙
`verify-spellcheck.mjs` 의 `MUST_NOT_FLAG` 와 규칙 파일 주석의 "일부러 넣지 않은 것"에 이미 있는 항목은 결함이 아니다. 복수·신설 표준어(이쁘다·짜장면·허접하다·개기다·삐대다)를 틀린 말로 보지 않는다. 채팅체 띄어쓰기는 지적 대상이 아니다(설계 원칙).

두 조합의 차이는 "붙여 쓴 복합어 19건(운동중→운동장·먹방→석방·심쿵→심중·노잼→노점…)을 잡느냐"와 "채팅 오타 14건(뭐라구·몰라써·이따바…)을 잃느냐"의 교환이다. 여기 F2(동점 침묵)·F3(2음절 침묵)은 별도 축이다.

## 4. 패치 계획 — 세 패키지

전부 **JS 만 바뀌므로 OTA**. 각 패키지는 `verify-spellcheck.mjs` 에 정탐/오탐 쌍을 함께 넣고 `npm run verify:spellcheck` 를 통과해야 한다(현재 175건). 하네스 `e2e` 로 이 문서의 종단 40문장을 재측정해 "13/32 → ?" 를 기록한다.

### 패키지 A — 3층 안전장치 (파일 1개, 가장 큰 효과)
`koreanDictionaryRules.ts` `pickSafeSuggestion`:
1. 2음절 어절 → `null` (F3)
2. 띄어쓰기 변형 후보가 하나라도 있으면 `null` (F4/H1) — 또는 H1r
3. 안전 후보가 전부 한 음절 뺀 꼴 → `null` (H7); 전부 덧붙인 꼴 → `null` (H10)
4. 4음절↑·안전후보 3↑·마지막 음절만 다르면 `null` (H4c)
5. 고침이 2음절 반복어 → `null` (H11)
6. 자모 거리 최소가 **유일할 때만** 반환, 동점이면 `null` (F2)
`collectTokens`: 2음절 반복어는 묻지 않음 (H12).
`koreanDictionary.ts checkWithDictionary`: `안/못`+나머지가 known 이면 면제 (H2, retry 배치에 합쳐 왕복 추가 없음), `고싶` 포함 어절 면제 (H3).
`SAFE_PICK`·`MUST_NOT_ASK` 에 실제 Hunspell 후보를 옮긴 케이스 등록.

### 패키지 B — 1층 규칙 10건 + `-잔아` 계열
`koreanSpellRules.ts`: R1·R2·R3·R5 추가, `-잔아→-잖아`(있·없·았·었·겠·렇·좋·했·맞·알 등 어간 캡처), R6·R9·R10 lookahead 보강. `koreanSpellCheck.ts findRieulSuggestions`: R4 는 CONJUGATION_RULES, R7(KKE_SUFFIX_HEADS)·R8(껄껄) 예외. 각 규칙에 "일부러 넣지 않은 것" 주석(귀찬아·되영·바램).
후속 후보(별 커밋): 됄·왓어·마싯·재밋·겟→겠·KKEO_TAILS 같·될려.

### 패키지 C — 도메인 어휘
C-1 (JS, OTA): `koreanAllowlist.ts` 의 `Set` 을 `checkWithDictionary` 의 lookup **앞**에서 걸러 네이티브 왕복도 줄인다. 초안 59개(부록 round2 §6): 어떡해·잘가·남친·여친·오키·셀카·최애·노잼·먹방·홈트·웨이트·인터벌·트레이너·루틴·런지·버피·풀업·푸시업·인바디·오트밀·요거트·스무디·에이드·하이볼·런치·디너·패딩·… **표준 표기가 따로 있는 말(화이팅→파이팅·런닝→러닝·후라이드→프라이드·쉐이커→셰이커·프로포즈→프러포즈·카페라떼→카페라테)은 넣지 않는다** — 이건 사전이 맞다.
C-2 (네이티브, 빌드): `dict/extra.dic` + `KoreanSpellCore.cpp` 생성자에서 `add_dic()`. 허용 목록과 달리 **정답 후보를 만들어 오타까지 고친다**. `MAXDIFF` 상향은 사전 파일이 "자동 생성, 수정 금지"라 보류.

## 5. 판단이 필요한 것 (제가 정할 일이 아님)

1. **H1 vs H1r** — 붙여 쓴 복합어 오탐 19건을 없애는 대신 채팅 오타 정탐 14건을 잃을 것인가. 설계 원칙("맞는 말을 틀렸다고 하는 쪽이 훨씬 성가시다")대로면 H1.
2. **애교체 오타** — 조아·시러·머해·머하냐·뭐라구는 오타이기도 하고 일부러 쓰는 말이기도 하다. 1층 머리 주석은 "입말 억제는 참견". 잡지 않는 쪽을 기본으로 두고, 잡으려면 별도 결정.
3. **스쿼트·라떼처럼 표준 표기(스쾃·라테)가 있지만 통용형이 압도적인 외래어** — 허용 목록에 넣을지. 넣으면 사전이 맞게 지적하던 것을 끈다.
4. **C-2 네이티브 사전** — 빌드가 필요하고 iOS 심사와 맞물린다. 시점 판단.

## 6. 실기기에서만 확인 가능한 것 (부록 `native-parity.md` §3-4)

- `suggest()` 는 `TIMELIMIT 50ms / TIMELIMIT_SUGGESTION 100ms / TIMELIMIT_GLOBAL 250ms` 를 `clock()`(프로세스 CPU 시간)으로 잰다. 이 사전은 후보 계산이 무거워(x86 유휴 기준 중앙값 77ms, 660개 중 218개가 ≥100ms) **앱에서는 JS·UI 스레드가 시계를 앞당겨 후보 꼬리가 잘린다.** 잘리는 순서가 ngram → 띄어쓰기 변형 → 편집 후보라, 3층의 두 포기 신호("후보 여럿"·"띄어쓰기 변형")가 **정확히 먼저 사라진다** → 하네스에서 없던 오탐이 기기에서 되살아날 수 있다(4배 부하: 보고싶었어→보고시었어). **하네스는 오탐의 하한을 측정한다.**
- 같은 기기에서도 부하에 따라 판정이 달라진다 — "어제는 안 그랬는데" 제보가 여기서 나온다.
- 확정용 어절 10개(부록 §4): 사랑(known) · 업서(known, 동형이의) · 뭐했어용(면제) · 안녕하세이 · 제작년→[재작년] · 귀찬아→[귀잖아,귀찮아,…] · 실타→1위 싫다 · 보고싶어→[보고시어,보고 싶어,보고서] · **보고싶었어(3후보 — 2개면 4배 이상 잘리는 기기)** · **먹을거같아(하네스 337ms — 기기에서 []면 250ms 컷)**. raw `KoreanSpell.suggest()` 배열과 ms 를 `__DEV__` 로그로 찍어 대조한다.
- 장기: 3층이 "포기 신호의 부재"를 확신으로 해석하지 않게 하거나(후보 2개 이하면 ngram 이 잘렸을 가능성), Hunspell 1.7.3 의 chrono 타임아웃으로 올릴 때 하네스와 번들을 **동시에** 올린다.

## 7. 기각·제외한 것

- `안되지`: `안되다`가 사전에 한 낱말(일이 잘 이루어지지 않다). 1층이 안 잡는 게 맞다.
- `바램→바람`: 바램이 사전에 있음(바래다 명사형).
- `않-어절첫머리`(않먹었어 등): 재현은 됐으나 초안 정규식이 '먹지 않았어'를 잡아 폐기.
- `아니예요·뭐에요`: 예요/에요는 앞말 받침 규칙이 필요해 문맥 의존 — 범위 밖.
- `죄송`: 2음절 침묵(F3)에 흡수.
- H4·H5: 손실이 이득보다 크다(§3).
- 감사 1라운드 finding 141개 중 24개만 재현 검증했다. 나머지 117개(부록 round1 §7)는 심각도 낮음으로 분류됐고 미검증이다.
