# 럽바디 — 어제 식단 불러오기·식단 삭제 (2026-10-08)

## 사용자 보고
1. 오늘 식단을 등록한 뒤 "어제 식단 불러오기"를 누르면 중복된다.
2. 아침에 누르면 아직 안 먹은 저녁까지 모두 등록돼 버린다.
3. 식단 삭제 기능이 없다.

## 원인
- 불러오기는 어제 하루를 **통째로** 오늘로 옮겼다. 중복 방지는 "내용이 똑같은 오늘 끼니"만 건너뛰는 방식이라(`MealService.CopyKey`),
  오늘 점심을 따로 기록했으면 어제 점심이 한 끼 더 붙었다. 시간대도 보지 않아 아침에 저녁까지 들어왔다.
- 삭제는 서버(`DELETE /meal/{id}`)·스토어에 있었지만 **목록 카드 길게 누르기**에만 숨어 있었다.

## 결정
| 항목 | 결정 | 이유 |
|---|---|---|
| 불러오는 단위 | **끼니 단위로 고른다** — 시트에 어제 끼니(아침·점심·저녁·간식)를 보여 주고 고른 것만 | 아침에 하루를 통째로 옮기면 안 먹은 끼니가 기록된다 |
| 기본 선택 | **지금 시간대의 끼니만**(`defaultMealType()` — 아침이면 아침) | 대부분은 그대로 [불러오기]만 누르면 된다 |
| 오늘 이미 기록한 끼니 | 고를 수 없음("오늘 이미 기록했어요"), 서버도 건너뜀 | 점심을 두 번 기록하는 일을 막는다. 간식도 같다(오늘 간식이 하나라도 있으면 어제 간식은 안 온다) |
| 서버 API | `POST /meal/copy?mealTypes=BREAKFAST,LUNCH`(선택). 없으면 오늘 비어 있는 끼니 전부 | 옛 앱도 중복은 더 생기지 않는다(시간대 문제는 남는다 — 새 앱으로 해결) |
| 삭제 | **식단 수정 화면 헤더에 휴지통**. 장소가 붙은 끼니면 방문 기록도 지울지 묻는다(목록 길게 누르기와 같은 결정 Q4) | 길게 누르기는 발견되지 않는다. 길게 누르기도 그대로 둔다 |

예전 "내용이 같은 끼니만 건너뛰기"(`CopyKey`)는 끼니 단위 규칙이 포함하므로 지웠다. 기존 테스트(두 번 불러와도 한 벌, 지운 것만 다시)는 그대로 통과한다.

## 배포
서버 먼저(main 푸시 → Railway). 새 앱 + 옛 서버면 `mealTypes` 가 무시돼 비어 있는 끼니 전부가 아니라 예전처럼 통째로 온다 — 그래서 서버가 먼저다.
앱은 OTA(네이티브 변경·새 글리프 없음 — `delete-outline` 기존).

## 검증
- `MealFlowTest` 4건 추가(오늘 기록한 끼니 건너뛰기·고른 끼니만·고른 끼니가 이미 있으면 이유·어제 없으면 NOT_FOUND), diet 패키지 155건 통과.
- 웹(로컬 스택, 오전 10시대): 시트에서 아침만 기본 선택·점심 "오늘 이미 기록했어요" → 1끼 불러오기 → 오늘 = 점심+아침. 수정 화면 휴지통 → 확인 → 삭제 후 목록으로.
- 실기기 미확인: 시트 체크박스 터치 영역, iOS 헤더 휴지통 위치.
