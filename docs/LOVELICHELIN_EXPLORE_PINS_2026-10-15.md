## 2. 서버

- `GET /api/v1/places/nearby?kind=FOOD|CAFE|SPOT&swLat&swLng&neLat&neLng` → `PlaceSearchResponse`(이름 검색과 같은 모양).
- `KakaoLocalClient.searchCategory(code, rect, pages)` — 쪽당 15곳, `meta.is_end` 에서 멈춘다, 실패하면 받은 데까지.
  FOOD·CAFE 는 3쪽(45곳), SPOT 은 업종 둘 × 2쪽(최대 60 → id 로 중복 제거). 한 번 누를 때 카카오 호출 최대 3~4번.
- 순서는 카카오 정확도순 그대로(좌표를 안 주므로 거리순 아님). **"맛집"이라 부르지만 카카오 API 에는 평점이 없다** — 인기도 근사일 뿐이다.
- 400: 범위 뒤집힘·0 면적·NaN·0.3도 초과·잘못된 kind. 카카오 키 없으면 `available=false`(오류 아님).
- 덤으로 고친 것: **필수 쿼리 파라미터가 빠지면 500** 이던 전역 문제(`MissingServletRequestParameterException` 핸들러 없음) → 400. `/places/search`(query 없음)도 같았다.

## 3. 검증

- 백엔드 전체 1,485건 통과(H2). 새 테스트: 둘러보기 범위 검증(`PlaceDedupeFlowTest`), 필수 파라미터 400(`ParamTypeMismatchTest`).
- 로컬 서버 직접 호출(이상 입력): 정상 200(키 없음 → unavailable) · 30km 초과/뒤집힘/0 면적/NaN/소문자·없는 kind/문자 → 400 · 파라미터 누락 → (수정 전 500) → 400 · 토큰 없음 401 · 장소 목록에 `kakaoPlaceId` 실림.
- 웹(375×812, 로컬 서버 + 로컬 테스트 커플): 브라우저 패널이 `dapi.kakao.com` 에 못 닿아 **가짜 `window.kakao` + 둘러보기 응답만 가짜**(저장은 실제 서버)로 확인했다(10-05 와 같은 방식, 앱 코드에는 없음).
  - 칩 → 보이는 범위로 1회 호출, 작은 주황 핀 5 + 우리 핀이 위, 이미 담은 곳 제외(6 → 5), 둘러보기 이름표 없음
  - 핀 탭 → 이름표·미리보기 카드([럽슐랭에 담기] [메뉴·정보] 둘 다 시트 안), [메뉴·정보] → `place.map.kakao.com/{id}`
  - 담기(실제 서버) → "럽슐랭에 담았어요", 그 곳이 우리 핀(고름)으로 바뀌고 둘러보기에서 빠짐 → 다시 맛집: 4곳(담은 곳이 **서버 kakaoPlaceId 로** 빠짐)
  - 같은 칩 다시 = 끔 · 느린 맛집 응답 중 카페로 바꾸기 → 카페 결과만(늦은 응답 버림) · 지도 끌기 → "이 지역 다시 찾기" → 새 범위로 1회, 버튼 사라짐
  - 결과 0 안내 · 실패 → [다시 시도]가 둘러보기를 다시 부름(이름 검색 아님) · 45곳 → 44곳 표시·묶음 0·우리 이름표 유지 · 축척 11 → 호출 없이 "확대하면…" 토스트
  - 검색창에 "파스타"(우리 핀 거르는 중) → 카페 칩 → 검색창 비워지고 우리 핀 전부 복귀
- `npm run typecheck` 통과, 바꾼 파일 lint 새 경고 0(KakaoMap.web.tsx 경고 3건은 기존).

## 4. 배포

1. main 푸시 → Railway 백엔드 배포(`/backend/**` watch). 마이그레이션 없음.
2. 앱: `src/` 만 바뀜(의존성·app.json·폰트·package.json 무변경) → **EAS Update 가능**. 올리기 전 늘 하던 대로 fingerprint 비교, main 에 다른 세션의 OTA 보류분이 있는지 확인.
   - 서버보다 앱이 먼저 가면: 칩 → 404 → "주변 장소를 찾지 못했어요"(앱이 깨지지는 않는다). 그래서 서버 먼저.
   - 옛 앱 + 새 서버: 장소 응답에 필드 하나 늘었을 뿐이라 영향 없음.

## 5. 남은 리스크 · 실기기 체크리스트

1. **실제 카카오 SDK·실제 카테고리 응답으로 본 적이 없다**(패널 차단, 로컬엔 REST 키 없음). `rect` 순서(경도,위도,경도,위도)는 카카오 문서대로다. 배포 뒤 운영에서 한 번 눌러 볼 것.
2. 네이티브(WebView) 지도의 `label/cluster` 처리는 웹과 같은 코드를 `kakaoMapHtml.ts` 에 넣었지만 실기기 미확인.
3. 이모지 칩은 기기 글꼴에 따라 모양이 다르다(iOS·Android·웹).
