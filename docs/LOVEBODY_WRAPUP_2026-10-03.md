## 1. 한 줄 결론

**럽바디는 감량 도구가 아니라 "우리 식사 기록"이다.** 상대 식사를 보고 반응하고 "뭐 먹었어?"를 묻는 것이 중심이고,
숫자의 정밀도는 기록이 귀찮지 않을 만큼만 챙긴다. 분석에서 찾은 버그(P0)와 이 방향의 기능 6개는 **모두 서버 배포 +
OTA 까지 나갔다.** 화면은 실기기에서 확인하지 않았다(§6).

## 4. 일부러 안 한 것 · 알려진 한계

- **데이트 식단 짝 동기화**: 내 몫 칼로리·사진을 고치면 상대 몫도 같이 바뀐다(`syncSharedPair`). 불편 신호가 오면 비율이 아니라
  **동기화 범위를 좁힌다**(칼로리·항목은 각자, 날짜·끼니·사진만 공유).
- **"○○님 오늘" 실시간 갱신 없음**: `subscribeCouple` 이 목적지당 핸들러 하나라 홈과 럽바디가 같이 구독하면 서로 지울 수 있다.
  포커스·당겨서 새로고침으로 반영. 실시간이 필요하면 구독을 리스너 목록으로 바꾸는 게 먼저다.
- **Cloudinary 정리 배치 없음**: 모든 업로드가 한 폴더(`fitto`)를 쓰고, 기기 초안처럼 DB 밖에 URL 을 든 흐름이 있어 일괄 삭제는 위험하다.
  앱 강제 종료 등으로 앱이 놓친 고아는 남는다. 수정 시 예전 사진 정리는 식단·몸 변화만 했다(다른 기능은 이 트랙 밖).
- **"어제 불러오기" 동시 2회**는 여전히 check-then-insert(앱이 요청 중 버튼을 잠근다). 순차 재요청은 막혔다.
- **같이 먹기 짝 동시 수정·자동 분석 경합**: `@Version` 없음 — last-write-wins(current-state §4-5). 실사용 신호 없음.
- **AI 결과는 식품 DB 와 매칭하지 않는다**, 신뢰도 필드 없음 — 방향상 보류(direction §3 보류 줄).
- 그 밖에 current-state §4-7 의 경미 항목(즐겨찾기 1+N, `loadMoreHistory` catch 없음, `calendar` month 검증 등)은 그대로다.

## 5. 이 트랙에서 배운 것 (다른 작업에도 해당)

### 5-1. 마이그레이션 번호는 Java 도 센다
CLAUDE.md §7 의 명령이 `resources/db/migration` 만 봐서 **Java 마이그레이션(V119)을 놓쳤다** — 그대로 썼으면 V119 를 중복으로 집었다.
`1dd2ba61` 에서 SQL·Java 를 함께 세도록 고쳤다.

### 5-2. OTA 는 "다른 세션의 머지"도 함께 나간다
OTA 는 `main` 전체를 번들한다. 매번 ① 지난 OTA 이후 `frontend/` 커밋을 나열하고 ② 그중 서버가 먼저 필요한 것의 Railway 배포가
SUCCESS 인지 확인하고 ③ **깨끗한 체크아웃**에서 fingerprint 를 두 번 계산해 1.0.6(iOS `810b9a8b` / Android `5025c62d`)과 같을 때만 올렸다.

### 5-3. OTA 번들이 metro-cache 충돌로 죽는다
병렬 세션이 동시에 번들하면 `%TEMP%\metro-cache` 에서 `ENOTEMPTY`. **세션 전용 `TEMP`/`TMP`** 로 돌리면 된다(fingerprint 영향 없음).
이때 업데이트는 발행되지 않는다.

### 5-4. `npm run build:web` 은 아이콘 폰트를 다시 만든다
`assets/fonts/MaterialCommunityIcons.ttf`·`icon-glyphmap.json` 이 바뀐다. 폰트는 fingerprint 입력이라 **커밋하면 OTA 가 기존 빌드에 안 간다** —
웹 빌드 확인 뒤 매번 되돌렸다. 같은 이유로 검증 스크립트를 `package.json` scripts 에 등록하지 않았다(scripts 도 fingerprint 입력).

### 5-5. 상대에게 가는 응답 필드는 테스트가 고정해 둔다
`PartnerPrivacyTest` 가 `PartnerMealTodayResponse` 필드 목록을 고정한다. 필드를 더하면(이번엔 `nudgedToday`) 이 테스트가 먼저 깨진다 —
상대 식사 정보가 아닌지 판단하고 허용 목록에 이유를 적어 넣는다.

### 5-6. 새 `@MockitoBean` 조합을 만들지 않는다
테스트는 기존 클래스와 **목 구성이 똑같게** 맞춰 스프링 컨텍스트를 늘리지 않았다(알림 목만 = `MealNudgeTest`, 알림 목 + 삭제기 스파이 =
`MealPhotoCleanupTest`). CLAUDE.md §6 의 OOM 경고 그대로.

### 5-7. "끝났을 때만 치운다"
저장이 타임아웃(status 0)으로 실패하면 서버가 뒤늦게 저장했을 수 있다. 업로드를 치우는 건 **응답이 와서 확실히 거절됐을 때만**
(`wasRejected`) — 그 틈에 지우면 곧 생길 기록이 지워진 사진을 가리킨다. 분석 대기 초과("아직 만들고 있어요")도 같은 이유로 둔다.
