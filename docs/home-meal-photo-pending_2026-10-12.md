# 홈 사진 기록이 실패하면 사진이 사라진다 (2026-10-12)

## 제보

"홈에서 사진으로 올리기 하고 끄는데, 실패한 경우에는 다시 그 사진으로 올릴 방법이 없다. 밥을 다 먹어서 올릴 사진도 없다."

## 원인 (코드)

- 홈 식단 칩 → 시트의 "사진 찍기"는 `launchCameraAsync` — 찍은 사진은 **갤러리가 아니라 앱 임시(캐시) 폴더**에만 있다.
- `HomeScreen.saveMealFromPhoto` 는 그 경로를 메모리로만 들고 업로드 → 저장을 했다. 실패하면 토스트만 띄우고 끝,
  저장이 거절되면 올린 사진까지 지웠다(uploadApi.discard). 앱을 꺼서 업로드가 죽으면 사진을 가리킬 방법 자체가 사라진다.
- 기록 화면(DietRecordScreen)은 실패해도 화면에 사진이 남아 다시 누를 수 있다 — 문제는 홈 시트 경로.
- 시트 저장에는 멱등키도 없었다 → 서버는 저장했는데 응답만 못 받은 경우 다시 보내면 두 끼가 된다.

## 수정 (앱만, OTA)

`utils/pendingMealPhotos.ts` — 식단 사진 **보관함**.

- **먼저 적고 나중에 올린다** — 사진을 고르자마자 앱 문서 폴더(`pending-meal-photos/`, 시스템이 비우지 않는 곳)로 복사하고
  AsyncStorage 목록에 {끼니·날짜(찍은 순간)·멱등키} 를 적는다. 기록이 끝나야 지운다.
- **다시 올려도 한 끼** — 처음 만든 clientRequestId 를 끝까지 쓴다(서버 MealService.save 멱등 검사).
- **올린 주소도 적어 둔다** — 업로드 뒤 저장만 실패했으면 다음엔 업로드를 건너뛴다(식단 사진 업로드는 하루 한도 MEAL_PHOTO 를 쓴다).
- **자동 재시도** — 홈이 뜰 때(1.5초 뒤)와 앱이 다시 활성화될 때, 연결 실패·서버 오류(0·5xx)였던 것만 조용히 다시 보낸다.
  서버가 거절한(4xx) 건 같은 답이 돌아오므로 사용자가 누를 때만. 지금 올리는 중·1분 안에 찍은 건 건너뛴다
  (카메라에서 돌아올 때 안드로이드가 "활성"을 알려 같은 사진을 두 경로가 잡으면 토스트가 두 번 뜬다).
- **홈 한 줄 슬롯 맨 앞**에 "올리지 못한 식단 사진 N장 · 눌러서 다시 올리기"(`PendingMealPhotoPeek`) → [다시 올리기 / 버리기(확인 한 번 더) / 취소].
  놓치면 사진째 사라지는 유일한 항목이라 여행·일정보다 앞이다. 아이콘은 이미 서브셋에 있는 camera-outline(새 글리프 = 폰트 = 빌드).
- 실패 토스트: "… 사진은 남겨 뒀어요 — 홈에서 다시 올릴 수 있어요." 시트는 닫는다.
- 로그아웃하면 보관함을 비운다(authStore.clearTokens) — 다음 계정에 남의 끼니 사진이 뜨거나 그 계정으로 올라가면 안 된다.
- 웹은 `.web.ts` 빈 구현 — 브라우저엔 문서 폴더가 없고, 웹은 원래 기기 파일을 고르므로 원본이 남는다. 웹 경로는 그대로.

## 빌드 vs 업데이트

expo-file-system·AsyncStorage 는 이미 들어 있는 네이티브 모듈의 JS 호출 — app.json·package.json·아이콘 폰트 변경 없음 → OTA.
검증: typecheck, eslint(새 오류 0), `expo export --platform web` 통과. 실기기 미확인.

## 실기기 체크리스트

- [ ] 비행기 모드 해제 → 앱을 내렸다 올리면(1분 지난 뒤) 자동으로 "올리지 못했던 ○○ 사진을 기록했어요!", 슬롯이 사라진다. 끼니·날짜가 찍은 때 것.
- [ ] 찍자마자 앱을 완전히 종료 → 다시 열면 같은 흐름(기록이 이미 됐으면 중복 없이 사라짐).
- [ ] 슬롯 → 버리기 → 확인 → 사라진다.
- [ ] 정상 연결에서 찍기 → 지금과 같은 토스트 한 번(두 번 아님).
