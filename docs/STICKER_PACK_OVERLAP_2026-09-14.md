# 무료 이모지 시트와 PRO 시즌 팩이 12종 겹친다 (2026-09-14)

이모티콘 패널을 비트윈 스타일로 개편하면서 유니코드 이모지 팩의 존재 이유를 따져보다
나왔다. 사용자 질문은 "시즌 팩들 합칠 수 있지 않나? 근데 필요없는 것 같기도 —
기본 휴대전화 이모지잖아"였다.

## 1. 버그 — 무료 사용자 말풍선이 "전송 중"에서 멈춘다

서버는 스티커를 **어디서 골랐는지가 아니라 글자로** 판정한다:

```java
// ChatService.java
if (messageType == MessageType.STICKER
        && (StickerPack.isPremium(req.content()) || AnimatedSticker.isPremiumContent(req.content()))) {
    planGuard.require(senderId, Feature.PREMIUM_STICKER);
}
```

그런데 앱의 96종 무료 이모지 시트(`EmojiPicker`)와 시즌 PRO 팩 40종이 **12종 겹친다**:

```
🌸 ☔ 🌊 🏖️ 🍦 🍁 ☕ ❄️ 🎄 🔥 🎂 💐
```

시트 쪽 호출부는 `sendSticker(emoji, false, ...)` 로 **무료라고 단언**했고,
`stickerPacks.ts` 주석도 *"어느 팩에도 없는 이모지(이모지 시트에서 직접 고른 것)는
예전처럼 무료다"* 라고 적혀 있었다. 틀렸다.

결과: 무료 사용자가 시트에서 벚꽃을 고르면 서버가 402 를 낸다. STOMP 는 402 를 화면으로
되돌릴 방법이 없어서(`stickerPacks.ts` 가 이미 그 한계를 적어 뒀다) 낙관적 말풍선이
"전송 중" 표시인 채로 영영 멈춘다.

### 고친 것

호출부의 판정을 서버와 같게 맞췄다 — 시트에서 고른 이모지도 `isPremiumSticker()` 를
지난다. 이제 최소한 **이유가 보인다**(업그레이드 안내). 오해를 낳은 주석도 고쳤다.

**이건 증상 처리다.** 무료라고 광고한 시트에 유료 이모지가 섞여 있다는 것 자체는 남았다.

## 2. 더 큰 물음 — 유니코드 이모지를 PRO 로 파는 게 맞는가

시즌 5팩 40종(🌸🌷🌱 …)은 `Feature.PREMIUM_STICKER` 로 잠긴 유료 상품이다. 그런데:

- **파는 게 폰에 이미 있는 글자다.** 무료 사용자도 키보드로 같은 🌸 를 텍스트로 보낼 수
  있다. 차이는 크게 뜨느냐(`sticker: fontSize 56`)뿐이다.
- **그 약함이 위 버그로 이미 새고 있었다.** 같은 글자를 무료 경로로도 고를 수 있으니
  게이팅이 자리마다 어긋난다.
- **없애도 PRO 는 안 무너진다.** 움직이는 이모티콘 24종이 그대로 PRO 다.

### 선택지 (미결)

| | 내용 | 대가 |
|---|---|---|
| A | 유니코드 팩 6개를 스트립에서 전부 빼고, 이모지는 96종 검색 시트 하나로 | PRO 항목 하나 감소. 1번 버그는 근본에서 사라진다 |
| B | 6팩 → "이모지" 1팩으로 합치고 PRO 유지 | 스트립만 정리됨. 1번은 증상 처리인 채로 남는다 |
| C | 기본 16종(폰 키보드와 완전 중복)만 빼고 시즌 40종을 1팩으로 | PRO 유지 + 스트립 정리. 1번은 남는다 |

A 를 권한다 — PRO 상품으로서 정당성이 가장 약한 항목이고, 그 약함이 이미 버그로
드러났고, 대체 경로(96종 검색 시트 + 폰 키보드)가 이미 있다.

**결정 보류 상태다.** 유료 상품 구성이라 매출 판단이 섞인다.
