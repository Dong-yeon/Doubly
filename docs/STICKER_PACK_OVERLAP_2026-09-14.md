# 무료 이모지 시트와 PRO 시즌 팩이 12종 겹친다 (2026-09-14)

이모티콘 패널을 비트윈 스타일로 개편하면서 유니코드 이모지 팩의 존재 이유를 따져보다
나왔다. 사용자 질문은 "시즌 팩들 합칠 수 있지 않나? 근데 필요없는 것 같기도 —
기본 휴대전화 이모지잖아"였다.

## 1. 버그 — 무료 사용자 말풍선이 "전송 중"에서 멈춘다

서버는 스티커를 **어디서 골랐는지가 아니라 글자로** 판정한다:

```java
// ChatService.java
if (messageType == MessageType.STICKER
        && (StickerPack.isPremium(req.content()) || AnimatedSticker.isPremiumContent(req.content()))) {
    planGuard.require(senderId, Feature.PREMIUM_STICKER);
}
```

그런데 앱의 96종 무료 이모지 시트(`EmojiPicker`)와 시즌 PRO 팩 40종이 **12종 겹친다**:

```
🌸 ☔ 🌊 🏖️ 🍦 🍁 ☕ ❄️ 🎄 🔥 🎂 💐
```

시트 쪽 호출부는 `sendSticker(emoji, false, ...)` 로 **무료라고 단언**했고,
`stickerPacks.ts` 주석도 *"어느 팩에도 없는 이모지(이모지 시트에서 직접 고른 것)는
예전처럼 무료다"* 라고 적혀 있었다. 틀렸다.

결과: 무료 사용자가 시트에서 벚꽃을 고르면 서버가 402 를 낸다. STOMP 는 402 를 화면으로
되돌릴 방법이 없어서(`stickerPacks.ts` 가 이미 그 한계를 적어 뒀다) 낙관적 말풍선이
"전송 중" 표시인 채로 영영 멈춘다.

### 고친 것

호출부의 판정을 서버와 같게 맞췄다 — 시트에서 고른 이모지도 `isPremiumSticker()` 를
지난다. 이제 최소한 **이유가 보인다**(업그레이드 안내). 오해를 낳은 주석도 고쳤다.

**이건 증상 처리다.** 무료라고 광고한 시트에 유료 이모지가 섞여 있다는 것 자체는 남았다.

## 2. 더 큰 물음 — 유니코드 이모지를 PRO 로 파는 게 맞는가

시즌 5팩 40종(🌸🌷🌱 …)은 `Feature.PREMIUM_STICKER` 로 잠긴 유료 상품이다. 그런데:

- **파는 게 폰에 이미 있는 글자다.** 무료 사용자도 키보드로 같은 🌸 를 텍스트로 보낼 수
  있다. 차이는 크게 뜨느냐(`sticker: fontSize 56`)뿐이다.
- **그 약함이 위 버그로 이미 새고 있었다.** 같은 글자를 무료 경로로도 고를 수 있으니
  게이팅이 자리마다 어긋난다.
- **없애도 PRO 는 안 무너진다.** 움직이는 이모티콘 24종이 그대로 PRO 다.

### 결정 — A (2026-09-14)

**유니코드 이모지 팩을 전부 폐지했다.** 기본 16종·시즌 40종 모두. 이모지는 스트립 맨 끝
버튼 한 칸으로 96종 검색 시트를 연다(팩 여섯 칸 → 한 칸).

| | 내용 | 왜 안 택했나 |
|---|---|---|
| **A ✅** | 팩 6개 폐지, 이모지는 검색 시트 하나로 | — |
| B | 6팩 → "이모지" 1팩으로 합치고 PRO 유지 | 스트립만 정리된다. 위 버그가 증상 처리인 채로 남는다 |
| C | 기본 16종만 빼고 시즌 40종을 1팩으로 | 같은 이유. PRO 근거가 약한 건 그대로다 |

A 를 택한 근거는 세 가지다.

1. **파는 것이 성립하지 않았다.** 폰 키보드에 이미 있는 글자다. 이 판단은 새로 한 게 아니라
   이미 코드에 적혀 있었다 — `AnimatedSticker.java` 의 *"기존 StickerPack 프리미엄 팩은
   유니코드 이모지라 '키보드에 이미 있는 것을 파는' 모양이었다"*.
2. **그 약함이 이미 사고였다.** 위 12종 겹침. 게다가 `PremiumContentGateTest` 의 자기 주석이
   *"원래 자유롭게 쓰던 이모지가 갑자기 막히는 것 — 새 상품이 아니라 기능 회수로 체감된다"*
   를 최악의 경우로 꼽아 뒀는데, 팩 **안에서만** 따져서 정작 그 일이 벌어진 걸 못 봤다.
3. **PRO 가 안 무너진다.** 움직이는 이모티콘 24종(키보드에 없다) + 확장 무드팩이 같은
   `PREMIUM_STICKER` 게이트에 남는다.

### 무엇이 지워졌나

- 백엔드 `StickerPack` enum 삭제. `ChatService.send` · `ScheduledChatMessageService` 의
  PRO 판정은 `AnimatedSticker.isPremiumContent` 만 본다.
- 프론트 `constants/stickerPacks.ts` 삭제(`STICKER_PACKS`, `isPremiumSticker`).
- `StickerPanel` 에서 팩 단위 PRO 개념(자물쇠 배지·잠금 안내 줄·흐린 격자)을 걷었다.
  칸 단위 잠금은 남는다 — 움직이는 이모티콘은 한 팩 안에서 무료 6 / PRO 24 로 갈린다.
- `PremiumContentGateTest` 를 다시 썼다. 팩 안에서 따지던 것을 **예전에 막혔던 이모지가
  지금은 전부 무료인지**로 바꿨다(겹침 12종을 목록에 박아 뒀다). 이 테스트가 깨지면
  기능 회수가 되돌아온 것이다.

### 이미 보낸 메시지

영향 없다. 시즌 이모지는 `content` 에 **이모지 문자 그대로** 저장돼 있어서 말풍선은 예전과
같이 그려진다. 팩 정의가 사라져도 읽는 쪽이 참조하지 않는다.

## 3. 곁가지 — 피드 식단 카드 칼로리

같은 병합에서 나왔다. 09-13 에 "피드 식단 카드에서 칼로리를 뺀다"고 정했는데
(자동 노출이라 매 끼니 감시가 된다), 09-14 의 카드 재구성이 **그 결정을 모른 채**
부제를 `끼니 · 칼로리 · 장소` 로 다시 짰다. 병렬 세션이 서로를 못 본 경우다.

병합에서는 명시적으로 내려진 결정 쪽을 살렸다 — 부제 구조는 09-14 것을 쓰고
칼로리 한 줄만 뺐다(`끼니 · 장소`). 되돌리려면 `FeedItemMapper.toItem(Meal ...)` 의
`parts` 에 한 줄을 더하면 된다.
