### 2-1. 키워드 표

- **30묶음**. 사랑·뽀뽀·보고싶어·예뻐·잘자(졸려 포함)·굿모닝·배고파·미안·고마워·화나·짜증·싸움·삐짐·ㅋㅋ·ㅠㅠ·우울·
  피곤(어지러 포함)·퇴근·출근·축하·신나·좋아·헐·응/넵·더워·추워·그렇구나·난감·뿌듯·안아줘.
- 한 묶음에 코드 **최대 4개**, 캐릭터 스티커를 앞에 두고 EGG·DUO 를 섞은 뒤 `ANIM_*` 를 붙였다. 모든 묶음에 캐릭터 스티커가 하나 이상 있다.
- 짝(DUO)에 맞는 그림이 없는 묶음(미안·고마워·굿모닝·출근·응 등)은 솔로만 넣었다. 억지로 채우지 않았다.
- 🔸 **판단이 들어간 매핑**(실사용 반응을 보고 고칠 후보): 미안 → 식은땀·난감, 고마워 → 천사, 출근 → 하아·넵,
  보고싶어 → 우울, ㅋㅋ → 신남·행복(웃는 그림이 따로 없다), 굿모닝 → 행복.

### 2-2. 매칭 규칙 (`suggestStickers`)

1. 코드 입력 중(`(달걀이`·`(달걀이_사`) → 그 캐릭터의 캐릭터 스티커만. **예전과 같다.**
2. 입력 **전체**가 짧으면(정규화 후 ≤ 10자) → 라벨 정확 / 키워드 정확 / 부분 일치. **예전과 같다.**
3. **새로 추가**: 입력의 **마지막 어절**이 라벨·키워드와 같거나 그것으로 끝나면 추천한다. 끝에 붙은 자모 덩어리를 떼고 한 번 더 본다
   ("피곤해ㅠㅠ" → "피곤해ㅠㅠ", "피곤해"). 전체 길이 10자 상한은 여기에 걸지 않고, 대신 **입력이 40자를 넘으면** 모두 끈다.
4. 반복 자모를 줄인다: 같은 자모가 셋 이상이면 둘로("ㅋㅋㅋㅋㅋ" → "ㅋㅋ"). 물결·문장부호는 원래 `normalizeKey` 가 뺀다.
5. **"끝나면" 비교와 "키워드로 시작" 비교는 두 글자 이상 키워드만** 한다. "응원해"가 응(넵)으로, "네가"가 네(넵)로 걸리지 않게 하려는 것이다.
   (예전 표에도 쪽·럽·굿·흥·빡 같은 한 글자 키워드가 이 문제를 안고 있었다.)
6. 순위: 라벨 정확 > 키워드 정확 > 마지막 어절 라벨 > 마지막 어절 키워드 > 부분 일치. 같은 순위 안에서는 **최근 보낸 것**이 앞이고, 그다음은 표 순서다.
7. 막대는 최대 6칸이다. **캐릭터 스티커가 늘 움직이는 이모티콘 앞에 선다.** 둘 다 있으면 캐릭터 스티커는 최대 4칸만 쓴다.
   이 상한이 없으면 "사랑해" 같은 흔한 말에서 캐릭터 스티커가 여섯 칸을 다 채워 움직이는 이모티콘이 한 번도 안 보인다. **명세에 없던 규칙**이다.

### 2-3. 노출 (`ChatRoomScreen`)

- 입력이 250ms 멈춘 뒤에만 띄운다. 다시 치기 시작하면 바로 숨는다.
- **맞춤법 제안이 떠 있으면 스티커 막대는 숨는다.** 🔸 예전에는 두 막대가 **동시에 쌓였다**(스티커 막대 위, 맞춤법 막대 아래). 명세대로 고쳤다.
- 추천을 눌러도 **입력창 글은 그대로** 둔다. 🔸 **예전 코드는 `setText('')` 로 비우고 있었다**(명세의 "현재 설계 유지"와 실제가 달랐다).
  "나도 사랑해"를 치다 그림을 곁들인 사람의 문장이 지워지면 안 되므로 유지로 바꿨다.
  예외로 **코드를 치던 중("(달걀이_")에는 비운다.** 그 글은 보낼 말이 아니라 고르던 흔적이다.
- 누른 뒤에는 같은 글인 동안 막대를 숨긴다. **X 로 닫으면 입력이 빌 때까지**(보내거나 지울 때까지) 다시 띄우지 않는다.
- **잠긴 팩은 뺀다.** 판정은 패널과 같다(서버 팩 목록의 `usable`, 모르면 열린 것으로 본다). 팩 목록을 패널을 열 때만 받던 것이라 방에 들어올 때 한 번 받게 했다(캐시).
  지금은 두 캐릭터 팩·움직이는 이모티콘 팩이 모두 무료라 실제로 빠지는 것은 없다. 유료 팩이 생기면 그때부터 동작한다.

### 2-4. 개인화

- `utils/recentStickers.ts`: AsyncStorage `doubly.recentStickers` 에 최근 보낸 스티커 30개를 적는다(최신이 앞, 중복 제거). 읽기·쓰기가 실패해도 무시한다.
- **패널·추천·텍스트 코드 어디서 보냈든** `sendSticker` 가 성공하면 적는다. 서버는 바뀌지 않았다.

### 2-5. 계측

- `STICKER_SUGGEST_SHOWN`: detail = `키워드:코드,코드,…`. 같은 막대(같은 detail)는 방 안에서 한 번만 센다.
- `STICKER_SUGGEST_PICKED`: detail = `키워드:코드`.
- detail 의 "키워드"는 **표의 키워드나 라벨**이다. 입력 원문은 넣지 않는다(검증 스크립트에 케이스로 고정했다).
- 🔸 **백엔드도 바꿨다**: 클라이언트 이벤트는 `ClientAnalyticsEvent` enum 화이트리스트를 통과해야 하고, 없는 값은 400 으로 버려진다.
  `ClientAnalyticsEvent`·`AnalyticsEvent` 에 두 값을 더했다. 마이그레이션은 없다(`event_type` 은 VARCHAR(40)).
  **서버가 먼저 배포돼야 이벤트가 쌓인다.** 앱만 먼저 나가면 이벤트는 400 으로 조용히 사라진다. 화면 동작에는 영향이 없다.

### 2-6. 바꾸지 않은 것

- `STICKER_CODE_INDEX` 는 여전히 `STICKER_CHARACTERS` 로만 만든다. 텍스트 코드 파싱 동작도 그대로다(검증 §2).
- `stickerImages.ts` 는 건드리지 않았다(StickerImageSyncTest 구조 유지).

## 4. 실기기로 확인할 것

1. "사랑해" → 달걀이·짝 사랑해가 앞에 뜨고, 뒤에 움직이는 이모티콘 썸네일이 선다.
2. "나도 사랑해", "오늘 피곤해ㅠㅠ", "ㅋㅋㅋㅋㅋ" 에서 뜨는지 본다.
3. 타이핑 중에는 안 뜨고, 멈추면 약 0.25초 뒤에 뜨는지. 깜빡임이 거슬리지 않는지.
4. 추천을 눌러 보낸 뒤 **입력창 글이 남는지**, 이어서 전송하면 글도 나가는지.
5. X 로 닫고 계속 치면 안 뜨는지, 보내고 새로 치면 다시 뜨는지.
6. 맞춤법 검사를 켜고 틀린 말 + 키워드("안뇽 사랑해")를 쳤을 때 **맞춤법 막대만** 뜨는지.
   맞춤법 막대를 X 로 닫으면 스티커 막대가 뜨는지.
7. 움직이는 이모티콘 추천을 눌렀을 때 말풍선에서 움직이는지(전송 경로는 기존 STICKER 그대로다).
8. 여러 번 보낸 스티커가 같은 키워드에서 앞으로 오는지(앱을 껐다 켜도 유지되는지).
9. 서버 배포 뒤 `event_logs` 에 `STICKER_SUGGEST_SHOWN`·`PICKED` 가 쌓이고, detail 에 입력 원문이 없는지.
10. 키보드 위 막대 높이 — X 버튼이 추가돼 가로 폭이 약간 줄었다. 좁은 기기에서 6칸이 가로 스크롤로 넘어가는지.
