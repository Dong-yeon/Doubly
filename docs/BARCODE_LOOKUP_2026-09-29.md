# 바코드로 음식 찾기 되살리기 (2026-09-29)

선행: [DIET_FOOD_SEARCH_2026-09-12.md](DIET_FOOD_SEARCH_2026-09-12.md) §"바코드는 지원하지 않는다" —
그때 "살릴지 접을지"를 미결로 남겼고, 이번에 **A(영양성분표 사진) + B(식품안전나라) + C(Open Food Facts)**로 정했다.

## 1. 증상과 원인

"바코드 인식을 잘 못 한다." 실제로는 두 층이었다.

| 층 | 원인 | 사용자에게 보인 것 |
| --- | --- | --- |
| ① 조회 | `FoodDbClient.lookup()` 가 **무조건** `FOOD_DB_NOT_CONFIGURED` 를 던졌다(9/12 데이터셋 교체로 바코드 필드가 사라진 뒤 미결). | 카메라가 바코드를 제대로 읽어도 항상 "바코드 조회 기능이 아직 준비되지 않았어요" |
| ② 스캔 루프 | 실패하자마자 `setScanned(false)` 로 스캔을 다시 열었다. | 카메라가 여전히 보고 있는 같은 바코드를 곧장 다시 읽어 **진동과 실패 토스트가 끝없이 반복** → "인식을 못 한다" |
| ③ 스캔 화면 | 플래시·대안 경로가 없었다. 안드로이드 expo-camera 는 최고 해상도 프레임을 메인 스레드에서 분석한다(네이티브, 빌드 필요). | 어두운 곳·작은 바코드에서 느림 |

## 2. 결정 — 출처를 차례로 내려간다

```
바코드 ─▶ B. 식품안전나라 I2570(유통바코드) → C005(바코드연계제품정보)
            └ 제품명·업체·품목보고번호 ─▶ 식약처 영양성분 DB(기존 FOOD_DB_API_KEY)
                                          품목보고번호 일치 → 없으면 이름 일치(업체 맞으면 포함 관계)
       ─▶ C. Open Food Facts (키 없음) — 수입·다이어트 식품
       ─▶ 제품명만 찾음 → 앱: [영양성분표 찍기] [이름만 넣기] [다시 스캔]
       ─▶ 못 찾음(404)  → 앱: [영양성분표 찍기] [다시 스캔]
                                  └ A. 사진 → 기존 AI 분석이 NUTRITION_LABEL 로 표기값을 그대로 읽는다
```

- **B → C 순서**: 국내 제품은 B 가, 수입 다이어트 식품(프로틴바·파우더·제로 음료)은 C 가 강하다.
  B 의 바코드 연계 데이터가 2018년 이후 갱신이 멈춘 공백을 C 와 A 가 메운다.
- **영양 DB 행은 반드시 대조한다.** 조회 조건이 무시되면 포털은 에러 대신 DB 첫 행들을 준다 —
  대조 없이 첫 행을 쓰면 엉뚱한 음식의 칼로리가 들어간다. 품목보고번호 일치, 또는 이름 일치
  (분류 접두어 `라면_`·공백·괄호 무시), 또는 업체가 맞으면서 이름이 서로 포함될 때만 받는다.
- **이름은 바코드 제품명을 쓴다** — 영양 DB 행 이름(`라면_신라면`)보다 사람이 읽기 좋다.
- **Open Food Facts 는 1회 제공량 값을 우선**한다 — 프로틴바처럼 "한 개"로 먹는 식품은 100g 기준보다
  기록 단위와 맞는다. 나트륨 g→mg, kJ 만 있으면 kcal 로 환산. 브랜드를 이름 앞에 붙인다.
- **영양성분표 사진은 끼니 사진으로 쓰지 않는다** — 분석용으로만 올린다(이미 찍은 음식 사진을 덮지 않고,
  표 사진이 식단 앨범에 남지 않게). 글씨가 작아 평소(1024)보다 크게(1600) 줄인다. 표를 읽은 결과가
  한 항목이고 바코드로 제품명을 알면 그 이름을 쓴다.
- **출처별 적중을 INFO 로그로 남긴다** — `바코드 {} → 식품안전나라+영양DB / Open Food Facts / 제품명만 / 못 찾음`.
  한 달쯤 모아 B·C 를 계속 둘지 본다.

| 거부한 것 | 이유 |
| --- | --- |
| 바코드 기능 접기 | A·C 만으로도 수입·다이어트 식품과 "표 찍기"가 살아난다 |
| C 를 B 보다 먼저 | 국내 제품은 C 커버리지가 낮아 헛호출이 대부분이 된다 |
| 영양 DB 이름 검색 첫 행을 그대로 채택 | 위 "대조" 이유 — 틀린 칼로리는 빈 칸보다 해롭다 |
| 구글 코드 스캐너(`CameraView.launchScanner`)로 교체 | 인식률은 더 좋지만 첫 실행에 Play 서비스 모듈을 내려받고 UX 가 통째로 바뀐다. 실기기에서 ①②를 고친 효과를 본 뒤 판단 |
| 스캔 결과 캐시 | 호출량을 본 뒤. 지금은 요청당 최대 외부 호출 5번(I2570·C005·영양DB 2·OFF) |

## 3. 바꾼 것

**백엔드** (`com.fitto.diet`)
- `FoodSafetyBarcodeClient`(신규) — I2570 → C005. 실패·키 없음은 비어 있음.
- `OpenFoodFactsClient`(신규) — v2 API, User-Agent 명시, 404 는 "없음".
- `FoodDbClient.findForProduct` — 품목보고번호/이름으로 영양 찾기 + 행 대조.
- `BarcodeLookupService`(신규) — 위 순서. 바코드는 숫자 8~14자리만(QR 오인식 거절). 출처가 하나도 없으면
  `FOOD_DB_NOT_CONFIGURED`, 있는데 못 찾으면 `FOOD_DB_NOT_FOUND`("이 바코드의 영양정보를 찾지 못했어요.").
- `BarcodeLookupResponse` 에 `source`. 스키마 변경 없음(Flyway 없음).
- 설정: `FOOD_SAFETY_API_KEY`(신규, 비면 B 건너뜀), `OPEN_FOOD_FACTS_ENABLED`(기본 true, 테스트는 false).

**앱**
- `BarcodeScanScreen` — 한 번 읽으면 사용자가 고를 때까지 멈춤(루프 제거), 플래시 켜기/끄기, 결과 패널,
  하단 "바코드가 안 읽히나요? 영양성분표 찍기".
- `DietRecordScreen` — `scanLabel` 파라미터로 돌아오면 전환이 끝난 뒤 카메라 → 업로드 → AI 분석.
  사진 분석 결과 적용부를 `applyPhotoAnalysis` 로 분리해 두 경로가 함께 쓴다.

## 4. 검증

- 백엔드 신규 16건: 출처별 응답 해석 10건(`BarcodeSourcesParseTest` — 필드명 두 벌, 오류 코드, 1회 제공량·100g·kJ 환산,
  행 대조의 거절 경우) + 순서 6건(`BarcodeLookupServiceTest`, 스프링 컨텍스트 없이). 기존 `FoodDbNotConfiguredTest` 는
  "출처가 하나도 없으면 준비 안 됨"으로 갱신. diet 패키지 110건 통과.
- 앱: typecheck·nested-buttons 통과, 린트 신규 오류 없음. 웹 export 후 가짜 카메라로 스캔 화면 렌더·플래시 토글 확인.
- **미검증**
  - 식품안전나라 I2570/C005 **실응답** — 필드명은 공개 명세 기준. 이 환경은 외부 호출이 막혀 대조하지 못했다.
  - 영양 DB 가 `ITEM_REPORT_NO` 조건을 실제로 받는지 — 안 받아도 행 대조로 틀린 값은 막히고 이름 검색으로 넘어간다.
  - Open Food Facts 의 국내 제품 커버리지.
  - 실기기 스캔 → 결과 패널 → 영양성분표 촬영 → AI 읽기 전체 흐름.

## 5. 배포와 첫 확인

1. **식품안전나라 인증키 발급** — foodsafetykorea.go.kr → 공공데이터활용 → OpenAPI 인증키 신청.
   I2570·C005 이용 신청 후 Railway 에 `FOOD_SAFETY_API_KEY` 설정. (없어도 C·A 는 동작한다.)
2. 백엔드 배포(Railway) → 앱은 JS 만 바뀌어 EAS Update.
3. 첫 스캔 몇 건 뒤 Railway 로그에서 확인:
   - `식품안전나라 ... 오류를 돌려줬다 code=...` 가 보이면 키·서비스 신청 문제.
   - `바코드 ... → 제품명만` 이 국내 제품에서 반복되면 영양 DB 대조가 너무 엄격하거나 `ITEM_REPORT_NO` 가 안 먹는 것 —
     그 제품의 영양 DB 행을 직접 조회해 `BarcodeSourcesParseTest` 픽스처를 실제 값으로 바꾼다.
4. 앱이 먼저 나가도 깨지지 않는다 — 옛 백엔드는 503 을 주고, 새 스캔 화면은 그걸 "조회하지 못했어요 · 다시 스캔"으로 보여 준다.
