# 알림이 읽어도 상단바에서 안 사라진다 (2026-09-14)

폰 테스트 중 리포트: **"알림 읽어도 안 사라짐"**. 확인 결과 OS 알림 트레이(안드로이드
상단바) 쪽이고, 종류는 구분하지 않은 상태였다.

## 1. 원인 — 지우는 코드가 채팅 한 종류에만 있었다

`frontend/src/utils/push.ts` 의 `dismissRoomNotifications(relationId)` 가 앱 전체에서
유일한 정리 경로였다. 하는 일은 하나였다:

```ts
presented.filter((n) => n.request?.content?.data?.link === `chat/${relationId}`)
```

그래서 **채팅이 아닌 알림에는 지우는 코드가 아예 없었다.** 서버가 보내는 종류는
`PushLinks` 기준 20가지고(피드·질문·기념일·무드·스도쿠·오목·운동·식단·맛집·콘텐츠·
여행·트레이너·커플 연결…), 이 중 채팅만 정리 대상이었다. 나머지는 **탭해서 들어간
한 건만 OS 가 치워 주고**, 같은 종류로 쌓인 나머지는 앱에서 읽어도 영영 남았다.

채팅도 완전하지 않았다. 호출부가 `ChatRoomScreen` 두 곳(마운트 · AppState 복귀)뿐이라
그 화면이 떠 있지 않으면 돌지 않았다.

### 곁가지 — 콘텐츠 알림은 탭해도 아무 데도 안 갔다

추적 중에 나왔다. `PushLinks.content(id)` 가 `content/{id}` 를 보내는데
`linking.ts` 에는 그 경로가 없다(실제 경로는 `place/content/:contentId`). 알림을
탭해도 이동이 없었고, 화면 경로와 안 맞으니 아래 정리 로직으로도 안 지워진다.
`PushLinks` 클래스 주석의 *"여기에 없는 경로를 문자열로 직접 쓰지 말 것 — 그 사실이
발송 시점에는 드러나지 않는다"* 가 정확히 이 경우다. 실사용 3곳.

## 2. 고친 방식 — 종류를 나열하지 않고 경로로 맞춘다

서버가 보내는 `data.link` 와 앱의 화면 경로(`linking.ts` config)는 **원래 같은 문자열**
이다. 딥링크가 그 위에 올라가 있다. 그래서 알림 종류를 하나씩 나열하는 대신
**"지금 화면 경로 == 알림 링크"** 하나로 전부 덮었다.

| 언제 | 무엇을 |
|---|---|
| 경로가 바뀔 때 (`onStateChange`) | 그 경로로 온 알림을 트레이에서 지운다 |
| 콜드 스타트 (`onReady`) | 같은 일을 한 번. `onStateChange` 는 첫 상태에 안 불린다 |
| 포그라운드 복귀 (`AppState`) | 같은 일을 한 번. 복귀는 경로가 안 바뀐다 |
| 그 화면에 있는 동안 도착 | 트레이에 **아예 안 올린다** (`shouldShowList: false`) |

마지막 줄이 핵심이다. 그 화면에 머무는 동안 온 알림은 경로가 안 바뀌므로 위 세 경로
어디에도 안 걸린다. 올렸다가 지우면 깜빡이기도 한다 — 보고 있는 화면의 소식은 화면이
이미 보여 주고 있으니 처음부터 안 올린다.

호출은 `RootNavigator` 한 곳으로 모았다. `ChatRoomScreen` 의 채팅 전용 정리 두 곳은
같은 일을 하게 되어 지웠다(AppState 훅의 `connectSocket`·`syncMissed` 는 그대로 둔다).

### 왜 스토어가 아니라 모듈 변수인가

`setCurrentPath` 가 넣는 현재 경로는 `push.ts` 의 모듈 지역 변수다. 알림 핸들러는
네비게이션 트리 <b>밖</b>(모듈 최상단)에서 도는 콜백이라 훅으로 못 읽고, 이 값은
그리는 데 쓰지 않는다. Zustand 로 올리면 경로가 바뀔 때마다 구독한 화면이 다시 그려진다.

### 채팅 억제는 왜 남겨 뒀나

`isForActiveChatRoom`(activeRoomId 기준)을 경로 비교로 대체하지 않고 OR 로 뒀다.
둘은 미묘하게 다르다 — 채팅방을 열어 둔 채 **다른 탭으로 옮기면** 경로는 바뀌지만
`activeRoomId` 는 남는다(화면이 언마운트되지 않으므로). 경로 기준으로만 판정하면
그 상태에서 채팅 알림이 다시 뜨기 시작한다. 현장에서 검증된 동작(2026-08-31)을
바꾸는 건 이 리포트의 범위가 아니라 그대로 뒀다.

## 3. 남은 것

- **링크↔경로 어긋남을 잡는 장치가 없다.** 콘텐츠 버그는 사람이 읽어서 찾았다.
  `PushLinks` 의 값이 전부 `linking.ts` config 에 있는지 확인하는 검사가 있으면
  같은 종류가 다시 안 생긴다. 백엔드 테스트는 `linking.ts` 를 못 보고, 프론트에는
  테스트 러너가 없어서 `scripts/verify-*.mjs` 계열 + CI 배선이 필요하다 — 별건.
- **검증은 미완이다.** 타입체크·린트·백엔드 스위트는 통과했지만 트레이 동작 자체는
  실기기에서만 확인된다. 배포(Railway → OTA) 후 확인 항목:
  1. 채팅 아닌 알림(예: 기념일·질문)을 받고 → 해당 화면에 들어가면 상단바에서 사라지는가
  2. 그 화면에 머무는 동안 같은 종류가 오면 상단바에 안 올라오는가
  3. 채팅은 예전과 같은가 (방 진입 시 정리 · 방 안에서는 배너 없음)
  4. 콘텐츠 알림을 탭하면 콘텐츠 상세로 가는가 ← 백엔드 배포가 선행돼야 한다
