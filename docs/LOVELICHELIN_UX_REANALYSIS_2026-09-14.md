# 럽슐랭 사용성 재분석 — 가볍게 만든 뒤에도 남은 마찰 (2026-09-14)

> **계기**: "럽슐랭을 가볍게 사용자들이 많이 사용하도록 수정했는데 아직도 불편한 부분들이 있는 것
> 같다. 객관적인 사용자 시점에서 다시 분석해달라."
>
> **한 줄**: 8월의 단순화(카테고리 13→8, 위시리스트/방문완료 상태 제거, 3화면→1화면)는 **데이터
> 모델의 군살**을 뺐다. 남은 마찰은 모델이 아니라 **동선**에 있다 — 탭의 첫 화면이 신규 커플에게는
> 항상 비어 있고, 가장 잦은 행동인 "다녀온 뒤 기록"이 별점 두 개·버튼 두 개로 갈라져 있으며,
> 화면 상단에 모드·보기·카테고리·검색 4층이 그대로 쌓여 있다. 그리고 수집한 데이터 일부("다시
> 올래요?")는 어디에도 쓰이지 않는다.
>
> 코드를 직접 읽고(`PlaceScreen.tsx` 862줄, `PlaceDetailScreen.tsx` 732줄, `PlaceAddScreen.tsx`,
> `DietRecordScreen.tsx` 장소 연동부, `PlaceService.java`) 실제 사용자가 걷는 순서대로 다시 걸었다.
> 이전 분석 `docs/LOVELICHELIN_IA_SIMPLIFICATION.md`(8/28), `docs/DIET_PLACE_INTEGRATION_ANALYSIS_2026-09-02.md`
> 와 이어진다.

## 0. 먼저 — 잘 되어 있는 것

객관적으로 보려면 잘된 것도 적어야 한다. 아래는 건드리지 말 것.

- **장소 추가**: 카카오 검색 → 결과 탭 → 이름·주소·좌표·카테고리 자동 입력. 지도 빈 곳 탭 → "여기에
  추가". 커플 앱 기준으로 충분히 가볍다.
- **중복 등록 방지**: `kakaoPlaceId` 로 같은 장소를 두 번 만들지 않는다(식단 탭에서 추가해도).
- **상대 재촉 푸시**: 내가 첫 평가를 하면 상대에게 "당신의 평점이 등급을 결정해요" — 둘이 함께
  완성하는 구조를 실제로 굴리는 유일한 장치다.
- **식단 탭 쪽 연동**: 식단 기록에 장소를 붙이면 별 하나로 방문 기록 + 대표 평점이 함께 끝난다.
  이게 **올바른 모델**이고, 럽슐랭 탭 쪽이 이걸 못 따라가고 있다(아래 2절).
- **AI 맛집 추천**: 장소명 환각 없이 실존 장소를 원탭으로 담는다.

## 1. 사용자 여정으로 다시 걷기

### 1-1. 첫 진입 — 탭의 첫 화면이 가장 빈 화면이다

`PlaceScreen` 은 `mode` 초기값이 `'guide'` 다. 가이드는 `lovelichelinTier > 0` 인 장소만 보여준다.
등급은 **둘 다** 3점 이상을 매겨야 붙는다. 즉 새 커플이 이 탭을 열면 몇 주 동안 첫 화면은 항상 이것이다:

> 아직 럽슐랭으로 인증된 장소가 없어요
> 둘러보기에 담은 곳을 다녀온 뒤, 둘 다 평점을 매기면 등급이 매겨져요!

빈 상태 문구가 **3단계 절차**(담기 → 다녀오기 → 둘 다 평점)를 **앱 내부 어휘**(둘러보기·인증·등급)로
설명한다. 처음 온 사람은 "둘러보기"가 어디 있는지부터 찾아야 한다. 저장한 장소가 이미 다섯 개 있어도,
등급이 하나도 없으면 첫 화면은 여전히 비어 있다 — **내가 넣은 것이 안 보이는 첫 화면**은 "이 탭은
빈 탭"이라는 인상을 남긴다.

### 1-2. 상단 4층 — 단순화 이후에도 층수는 같다

| 층 | 가이드 | 둘러보기 | 콘텐츠 |
| --- | --- | --- | --- |
| ① 모드 칩 3개 | ● | ● | ● |
| ② 목록↔지도 토글 | | ● | |
| ③ 카테고리 칩 8개(전체 포함, 줄바꿈 2줄) | ● | ● | 타입 칩 |
| ④ 검색창 | | ● | ● |
| ⑤ "카드를 길게 눌러 삭제할 수 있어요" 안내 줄 | | ● | ● |

8/28 단순화로 ③의 칩 수는 13→8, 상태 필터 3개는 사라졌다. 그러나 **층 자체는 5개 그대로**다. 둘러보기
목록 첫 카드는 화면 절반 아래에서 시작한다. 장소가 세 개뿐인 커플에게 카테고리 8개는 목록보다 필터가 큰
상태다.

**가이드와 둘러보기는 같은 장소들의 부분집합 관계**(인증만 / 전체)인데 사용자에게는 별개 모드로 보인다.
"내가 넣은 그 카페가 왜 가이드엔 없지?"는 데이터 모델의 구분(tier)이 내비게이션에 노출된 결과다.

### 1-3. 다녀온 뒤 기록 — 가장 잦은 행동이 가장 갈라져 있다

이 탭에서 가장 자주 일어나는 일은 "다녀왔으니 남긴다"다. 럽슐랭 탭에서 그 동선:

1. 둘러보기 → (검색 또는 스크롤) → 장소 카드 탭
2. 상세 상단 **"럽슐랭 평가"** — 별 5개(나) + "다시 올래요?" 체크 + **[럽슐랭 평가 저장]**
3. 그 아래 **[방문 기록 남기기]** → 열리면 **또 별 5개** + 사진 + 메모 + "오늘 식단으로도" 체크 + **[기록 저장]**

같은 화면에 **별 위젯이 두 개, 저장 버튼이 두 개**다. 하나는 등급용 대표 평점(`place_ratings`), 하나는
방문별 별점(`place_visits.rating`)이다. 이 구분은 설계자는 알지만 사용자는 모른다. 9/2 분석이 이미
"비일관성"으로 지적했고 그대로 남아 있다. 그런데 **같은 앱의 식단 탭에서는 별 하나로 둘 다 끝난다** —
사용자는 탭에 따라 다른 규칙을 배워야 한다.

부수 마찰:

- **날짜를 고를 수 없다.** `RecordVisitPayload.visitedAt` 은 API에 있지만 화면에 날짜 UI가 없어 항상
  오늘로 저장된다. "지난 주말 갔던 곳" 을 남기려면 날짜가 틀리게 남는다. 실제 기록은 대개 **사후**다.
- **방문 목록에 사진 한 장.** 외식 사진은 여러 장 찍는다. 피드·사진첩은 이미 여러 장을 받는데 방문 기록만
  한 장이다.
- 방문 기록에서 "오늘 식단으로도" 를 켜면 끼니·칼로리·탄단지 입력이 펼쳐진다 — 식단 탭이 9/9에 버린
  **정밀 입력이 여기서 되살아난다.**

### 1-4. 등급을 이해하기 — 규칙은 없고 판정만 있다

- **규칙 설명이 어디에도 없다.** "둘 다 3점 이상, 평균 5.0=3스타 / 4.0~=2스타 / 3.0~=1스타" 를
  `LovelichelinBadge`, 상세, 빈 상태 어디서도 알 수 없다(8월 백로그 그대로).
- 대신 판정 문구만 보인다: **"럽슐랭 탈락 — 재평가하면 다시 등급이 매겨져요"**. 내가 4점, 상대가 2점을
  준 우리 단골집에 앱이 "탈락" 이라고 쓴다. 커플 앱의 어휘가 아니다. "등극", "인증", "후보" 도 같은 결이다 —
  미슐랭 패러디의 재미가 **실패 쪽 어휘**까지 따라왔다.
- 보이는 상태가 다섯 가지다: 3·2·1 럽스타 / 내 픽·상대 픽(솔로 픽) / 탈락 / 한 명 대기 / 아무것도 없음.
  장소 20개짜리 커플 목록에 상태가 다섯 가지면 배지가 정보가 아니라 소음이 된다.

### 1-5. 다시 쓰기 — 넣은 것을 돌려주는 순간이 약하다

기록을 쌓게 하려면 **쌓인 것이 돌아오는 순간**이 있어야 한다. 지금 돌아오는 것:

- 가이드 매거진 카드(커버 사진·별점·메모·등극일) — 좋다. 다만 1-1 대로 몇 주 동안 비어 있다.
- AI 맛집 추천(PRO) — **가이드 모드에서만** 버튼이 보인다.
- AI 데이트 코스 — **둘러보기 → 지도 모드에서만** 버튼이 보인다. 두 번 눌러 들어가야 존재를 안다.

돌아오지 않는 것:

- **"다시 올래요?"** — 체크박스로 수집하지만(`PlaceRating.revisitIntent`, 콘텐츠도 동일) **읽는 곳이 코드
  어디에도 없다.** 필터도, 배지도, 추천 입력도 아니다. 사용자는 매번 답하는데 앱은 한 번도 되묻지 않는다.
- **최근성.** 목록은 `findByCoupleIdOrderByIdDesc` — 등록순이다. 어제 다녀온 곳이 아래에 있고 석 달 전
  넣고 안 간 곳이 위에 있다.
- **"오늘 뭐 먹지"** — 우리 3스타 중에서 하나 골라주기 같은, 등급을 매긴 보람이 돌아오는 가장 쉬운 순간이
  없다.
- **채팅으로 보내기** — "여기 어때?" 는 채팅에서 일어나는데 장소 카드를 채팅에 보내는 길이 없다.

### 1-6. 콘텐츠 모드 — 이름과 내용이 어긋난다

럽슐랭은 미슐랭 패러디, 즉 **음식**의 은유다. 그 탭 세 번째 칩이 **영화·공연·드라마**다. 좌표가 없어 Place
도메인에 못 섞는다는 8/24의 기술적 이유는 맞지만, 사용자 시점에서는 "맛집 탭에 드라마가 왜 있지"다. 콘텐츠
모드는 장소 모드와 같은 기계(등급·솔로 픽·탈락 문구·검색·타입 칩)를 통째로 한 번 더 갖고 있어 화면 코드도
두 배다. 사용 빈도는 장소보다 낮을 가능성이 높은데 **항상 보이는 최상단 칩 한 자리**를 차지한다.

## 3. 제안 — "한 목록, 한 별점, 한 층 덜"

### 3-1. 기록을 하나로 (마찰 1 · 4 · 10)

식단 탭이 이미 하는 방식을 럽슐랭 탭의 **기본**으로 삼는다.

- 상세의 큰 버튼은 **"다녀왔어요"** 하나. 열리면 **별 5개 하나** + 날짜(기본 오늘, 탭해서 바꿈) + 사진(여러
  장) + 한 줄 메모. 저장하면 방문 기록이 남고 **그 별점이 곧 내 대표 평점**으로 upsert 된다(백엔드
  `rate()` 는 이미 upsert 라 안전).
- 대표 평점만 따로 고치고 싶을 때(오늘은 별로였지만 가게 평가는 유지)를 위해 상단 별점은 **"내 평가 ★★★★ ·
  수정"** 한 줄로 접는다. 두 번째 별 위젯은 기본 화면에서 사라진다.
- "오늘 식단으로도" 는 끼니 선택 하나만 남기고 칼로리·탄단지 입력은 뺀다 — 9/9 식단 방향(사진 저장 후
  백그라운드 AI)과 같은 원칙. 필요하면 식단 탭에서 고친다.
- "다시 올래요?" 는 **쓰기 시작하거나 없앤다**(3-4).

### 3-2. 첫 화면을 "우리 장소 전체"로, 가이드는 정렬로 (마찰 2 · 3 · 7)

- 모드 칩 **가이드/둘러보기를 없애고 목록 하나**로 합친다. 정렬은 **인증 등급 → 최근 방문 → 등록** 순.
  등급 있는 곳이 자연히 위에 매거진 카드로 서고, 그 아래 나머지가 일반 카드로 이어진다. 신규 커플도 첫
  화면에서 **자기가 넣은 장소를 바로 본다.**
- 지도는 모드가 아니라 **우상단 아이콘 하나**로 토글(목록↔지도). 둘러보기 안의 2단 토글이 사라진다.
- 카테고리 칩은 **가로 한 줄 스크롤**로 접고, **장소가 8개 미만이면 숨긴다** — 필터가 목록보다 클 때 보일
  이유가 없다.
- "카드를 길게 눌러 삭제할 수 있어요" 안내 줄은 뺀다. 삭제는 상세 화면 버튼으로 이미 가능하다.
- 빈 상태 문구는 절차 설명 대신 **행동 하나**로: "둘이 가고 싶은 곳을 먼저 담아보세요 — 다녀오면 별점을
  매기고, 둘 다 좋았던 곳이 우리 럽슐랭이 돼요."

### 3-3. 어휘를 커플 앱으로 (마찰 5)

| 지금 | 제안 | 이유 |
| --- | --- | --- |
| 럽슐랭 탈락 — 재평가하면… | 의견이 갈렸어요 · 나 ★★★★ / 상대 ★★ | 실패 판정이 아니라 둘의 차이를 보여준다 |
| 내 평점만 매겨졌어요 — 나머지 한 명의 평가를 기다리는 중 | OO님 별점을 기다리고 있어요 | 짧게, 상대 이름으로 |
| (규칙 없음) | 배지 탭 → 바텀시트 한 장: "둘 다 3점 이상이면 럽스타. 평균 5.0=★★★, 4.0=★★, 3.0=★" | 백로그 해소 |
| 등극 / 인증 | 유지 | 성공 쪽 어휘는 재미로 남긴다 |

상태 5종은 **배지 2종**(럽스타 1~3 / 솔로 픽)으로 줄이고, 대기·의견 갈림은 배지가 아니라 카드 하단 한 줄
텍스트로만 둔다.

### 3-4. 넣은 것을 돌려주기 (마찰 6 · 7 · 8)

- **"다시 올래요?"**: 두 갈래 중 하나. (a) 목록에 "또 가고 싶은 곳" 필터 칩 + AI 추천 프롬프트 입력으로
  실제로 쓴다. (b) 지운다. 수집만 하는 질문은 신뢰를 갚아먹는다. **(b)를 권한다** — 별점 4~5가 이미 같은
  뜻이고, 질문 하나가 줄면 3-1 의 기록 폼이 더 가벼워진다.
- **AI 버튼 두 개는 모드와 떼어** 상단 액션 자리에 항상 둔다. 지도가 켜져 있지 않아도 데이트 코스는 의미가
  있다.
- **"오늘 어디 갈까?"** 카드 하나: 우리 럽스타 중 한 곳을 골라 보여주고 새로고침. 등급을 매긴 보람이 처음으로
  돌아오는 자리다. 구현은 프론트 랜덤 하나로 시작한다(AI 불필요).
- **채팅으로 보내기**: 상세 우상단 공유 → 채팅에 장소 카드. 백엔드는 이미 `ChatMessage` 에 `workoutId`·
  `routineId` 참조를 싣는 패턴이 있어 `placeId` 하나 더 얹는 일이다. 별건으로 분리 가능.

### 3-5. 콘텐츠 모드 (마찰 9) — 판단 보류, 선택지만

- (a) 그대로 두되 칩 순서를 마지막으로 유지(현행).
- (b) 럽슐랭에서 빼서 **우리 탭**(9/14 확정, `docs/ALBUM_TAB_IA_2026-09-14.md`)의 "같이 본 것" 섹션으로
  옮긴다 — "둘이 함께 쌓는 기록" 성격이 그쪽에 더 맞다.
- (c) 사용량을 보고 정한다. 지금은 계정이 둘뿐이라 데이터가 없다.

기술적 제약(좌표 없음)은 어느 안에도 걸리지 않는다. 이름의 어긋남만 놓고 보면 (b)가 맞지만, 우리 탭 구현
뒤에 판단하는 게 순서라 **이번 범위에서는 뺀다.**

## 4. 순서 제안

1. **3-1 기록 통합 + 날짜 선택** — 매 방문마다 겪는 마찰이고, 백엔드 변경 없음(프론트만). 한 커밋.
2. **3-2 목록 통합 + 지도 아이콘 + 카테고리 접기** — `PlaceScreen` 재구성. 모드 state 제거로 코드도 준다.
3. **3-3 어휘·규칙 시트** — 문구와 바텀시트 하나. 작다.
4. **3-4 중 "다시 올래요?" 제거 + AI 버튼 상단 고정 + 오늘 어디 갈까 카드** — 프론트. 백엔드 컬럼은
   남겨도 무해(읽지 않으니), 정리는 다음 Flyway 때.
5. 채팅으로 보내기·콘텐츠 이관은 별건.

1~4는 전부 프론트 변경이라 **EAS Update** 로 나간다. 백엔드 정렬(최근 방문 우선)을 서버에서 하고 싶으면
`PlaceRepository` 쿼리 하나지만, 프론트 정렬로 충분하다(목록 크기가 수십 개).
