## 2. 일정 등록 플로우

### 탭 수
최소 경로: **`＋ 일정 추가`(1) → 제목 칸 탭 후 입력(2) → `저장`(3)** = 3탭 + 타이핑.
날짜는 선택한 날짜 또는 오늘로 미리 채워진다(`openCreate`, 327행). 다른 날짜면 격자에서 먼저 날짜를 누르거나(+1) 모달 안 `DateField` → 날짜 시트(+2~3).

### 입력 필드 (모달, 698행~)

| 필드 | 필수 | 기본값 | 제약 |
|---|---|---|---|
| 제목 | **필수** | '' | 100자 (`@NotBlank @Size(max=100)`) |
| 날짜(시작일) | **필수** | 선택한 날 or 오늘 | `DateField`(달력 시트에서 고름, 직접 입력 없음). 종료일 이후로 못 고름 |
| 종료일 | 선택 | 없음(하루 일정) | 시작일 이후만. **매년 반복이 켜지면 숨겨지고 지워짐** |
| 종류 | 선택 | `DATE`(데이트) | 기념일 / 생일 / 데이트 / 기타 |
| 누구 일정 | 선택 | `SHARED`(우리 일정) | 우리 일정 / 내 일정 |
| 나만 보기 | 선택 | 꺼짐 | '내 일정'일 때만 보이는 스위치 → `PRIVATE` |
| 매년 반복 | 선택 | 꺼짐 | 켜면 종료일 제거 |
| 메모 | 선택 | '' | 500자 |

**시간(시:분) 필드는 없다.** 모든 일정은 날짜 단위이고, "하루 종일" 토글이 따로 있는 게 아니라 전부가 사실상 하루 종일 일정이다.

### 하루 종일 · 여러 날
- 하루 종일: 위 이유로 **전부 하루 종일**(시간 지정 일정이 불가능).
- 여러 날: **지원**(V62 `end_date`). 종료일 = 시작일이면 저장 시 `null` 로 정규화(`CalendarService.normalizeEnd`). 반복 일정은 기간 불가(서비스가 400).

### 수정 · 삭제 권한 (`CalendarEvent.editableBy`, `CalendarService.requireEditableEvent`)

| 공개 범위 | 보이는 사람 | 수정·삭제 | 공개 범위 변경 |
|---|---|---|---|
| `SHARED` 우리 일정 | 둘 다 | **둘 다** | 만든 사람만 |
| `PERSONAL` 내 일정 | 둘 다 | 만든 사람만(상대는 403) | 만든 사람만 |
| `PRIVATE` 나만 보기 | 만든 사람만 | 만든 사람만(상대에게는 404 — 존재 자체를 숨김) | 만든 사람만 |

프론트는 상대의 개인 일정을 누르면 폼을 열지 않고 "○○의 일정이라 볼 수만 있어요" 토스트를 띄운다(338행). 삭제는 수정 모달 안 `삭제` → 확인 Alert.

### 월 조회 쿼리와 인덱스 (`CalendarEventRepository`)
1. 단발 일정 — 기간 겹침 기준:
   ```sql
   where e.coupleId = :coupleId and e.repeatYearly = false
     and e.eventDate <= :end
     and coalesce(e.endDate, e.eventDate) >= :start
   ```
   `(couple_id, event_date)` 인덱스로 `couple_id = ? AND event_date <= :end` 까지는 탈 수 있지만, `coalesce(...) >= :start` 는 인덱스로 못 자른다 → **그 커플의 그 달 이전 일정 전부를 읽고 걸러낸다.** 커플당 일정 수가 적어 현재는 문제 없음. 실제 PG 실행 계획은 확인 필요.
2. 반복 일정 — `findByCoupleIdAndRepeatYearlyTrue` 로 커플의 반복 일정 전부를 읽고 월 일치를 Java 에서 거른다.
3. 공개 범위 필터(`visibleTo`)는 쿼리가 아니라 Java 에서 적용(의도된 설계, 엔티티 주석 참고).

알림 스케줄러용 `findByEventDate(date)`(커플 무관 전체), `findByRepeatYearlyTrue()` 는 `event_date` 단독 인덱스가 없어 **매일 테이블 풀스캔 가능성** — 확인 필요(PG 실행 계획).

## 6. 럽슐랭 연결

- **일정 → 장소 선택: 없음.** 일정 폼에 장소 필드가 없고 `couple_events` 에 장소 FK 도 없다. 럽슐랭 저장 장소를 고르는 UI 없음.
- **방문 기록 → 캘린더: 읽기 전용 오버레이만 있음.**
  - `backend/.../calendar/service/DateMealCalendarService.java` 가 그 달의 **"같이 먹기" 식단**(`MealRepository.findSharedInPeriod`: `shared_group_id is not null`, 파트너 복제본 제외) 중 **`place_visits.meal_id` 로 방문이 붙은 것만** 골라 장소명·럽슐랭 등급(`places.lovelichelin_tier`)·사진과 함께 내려준다.
  - 화면에서 누르면 `PlaceDetail` 로 이동(570행). 수정·삭제·D-day 없음(원본은 식단).
  - 일정으로 행을 만들지 않은 이유는 서비스 클래스 주석에 있음(FREE 한도 잠식, 4경로 동기화, 미래/과거 혼재).
- **"다녀왔어요"(`PlaceDetailScreen.tsx` `onSaveVisit`, 244행)와의 관계**: 이 경로는 "식단으로도 등록"을 체크했을 때만 식단을 만들고 `mealId` 를 방문에 붙인다. 그런데 이때 `saveMeal` 호출에 같이 먹기(공유) 표시가 보이지 않는다 → **"다녀왔어요"로 남긴 방문은 캘린더 오버레이에 안 나올 가능성이 높다. 확인 필요**(`saveMeal` 이 공유 그룹을 만드는지). 식단과 연결되지 않은 방문은 확실히 안 나온다.

### 월 경계 · 말일 · 윤년 점검 결과
- **말일**: 서버 `YearMonth.atEndOfMonth()`, 프론트 `new Date(year, month, 0).getDate()` — 둘 다 정상.
- **월 경계에 걸친 기간 일정**: 서버는 겹침 조건으로 내려주고, 프론트 `byDate`(254행)는 보이는 달 범위로 잘라 점을 찍는다 — 정상(18개월짜리 장기 일정 버그는 이미 수정된 상태).
- **월 이동**: 12월↔1월 연도 넘김 처리 있음(`moveMonth`). 빠른 연타 시 늦게 온 응답은 요청 토큰으로 버림.
- **윤년**: 2/29 매년 반복은 평년에 2/28 로 당겨짐(`occurrenceInYear`). 월 조회·알림(D-7/D-1/당일) 모두 같은 함수를 써서 어긋나지 않음. 단, 평년 2/28 에 원래 2/28 일정과 2/29 반복 일정이 함께 나오는 건 의도된 동작.
- **반복 시작 전 연도**: 월 조회와 알림 모두 최초 연도 이전에는 나타나지 않도록 거름.
- **프론트 날짜 루프**: `new Date('YYYY-MM-DDT00:00:00')` + `setDate(+1)` 로 현지 시각 기준 전진. 일광절약시간이 있는 시간대에서도 날짜 단위 전진은 안전한 방식으로 보이나 실기기 검증은 안 함.
