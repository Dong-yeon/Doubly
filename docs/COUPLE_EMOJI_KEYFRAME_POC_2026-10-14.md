# 우리 이모지 키프레임 애니메이션 PoC — 실측 (2026-10-14)

설계 §13(`COUPLE_EMOJI_AI_DESIGN_2026-09-08.md`)이 "원가 2~3배 + 장마다 흔들림"으로 기각한 방식
(이미지 모델로 포즈만 바꾼 키프레임을 만들어 잇기)을 실제 서비스 조건으로 다시 돌려 봤다.

**결론: §13 결정 유지.** 얼굴 동일성은 예상보다 잘 지켜졌지만, 감정(표정)이 보존되지 않고 프레임 사이에
손·소품·크기가 튄다. 이모지 하나당 원가는 세트 원가의 2~3배라 앱 쪽 모션을 대체할 이유가 없다.

## 조건 — 서버 경로와 맞춘 것

스크립트: `scripts/couple-emoji-experiment/anim_keyframe_poc.py` (사용자가 준 PoC 를 고쳐서 넣음)

| 항목 | 값 | 서버 근거 |
| --- | --- | --- |
| 입력 | 운영에 있는 본인 이모지 2장(`couple-emoji-cut/`, v4, 이미 EmojiCutout 을 거친 투명 PNG) — LOVE, THANKS | `CoupleEmojiService.generateOne` |
| 모델 · 해상도 · 온도 | `gemini-3.1-flash-image` · `512px` · `0.4` | `GeminiProperties`, `GeminiClient.generateImageInBackground` |
| aspectRatio | 넣지 않음 | 같은 메서드 주석 — 넣으면 그림체가 바뀐다 |
| 배경 | 흰 배경 위에 참조를 얹어 보내고 흰 배경으로 생성 → `EmojiCutout` 을 파이썬으로 그대로 옮겨 따냄 | `EmojiCutout.java` 상수·순서 동일 |
| 키 | Railway `GEMINI_IMAGE_API_KEY` | |

원래 PoC 에서 바꾼 것: 해상도 기본값(1K → 512px), `aspect_ratio` 제거, temperature 0.4 추가, 배경 기본을 초록 키잉 →
`cutout`(서버 따내기 이식)으로. 초록 키잉은 남겨 두되 despill 을 배경 경계(0<alpha<255)에만 걸게 고쳤다.
윈도 콘솔(cp949)에서 `≈`·`₩` 출력이 죽던 것도 고침. 환경은 Python 3.14 venv 에서 바로 설치됐다(3.12 불필요).

## 결과

| 스티커 · 모션 | 프레임 | 시간 | WebP | 관찰 |
| --- | --- | --- | --- | --- |
| LOVE · blink | 2/2 | 15.9s | 95KB (4프레임) | **감정이 사라졌다** — 원본의 하트 눈이 "눈 반쯤 감기"에서 평범한 눈으로, 주변 하트가 없어지고, 2번째 장에선 손가락 하트 손까지 사라졌다. 깜빡임이 아니라 다른 이모지 세 장이 번갈아 나오는 모양 |
| THANKS · wave | 3/3 | 26.2s | 115KB (6프레임) | 얼굴·머리·옷은 꽤 일정. 그러나 **흔드는 손이 2→3번째 장에서 반대쪽으로 바뀌고**, 반짝이 소품이 생겼다 없어지고, 원본의 가슴에 얹은 손이 사라졌다. 머리 크기·가르마도 조금씩 다르다 |

- 따내기는 5장 전부 성공(`cutout_ok`), 512px 원본 그대로 받음. 장당 7.5~9.6초.
- 실비용: 5장 × $0.045 ≈ **$0.23(약 320원)**. 이모지 한 장을 3프레임으로 움직이면 장당 원가가 4배(원본 1 + 키프레임 3)가 되고,
  17종 한 벌이면 세트 원가가 $0.77 → 약 $3.1 이 된다.
- 결과물(contact sheet·webp)은 본인 얼굴이라 저장소에 올리지 않았다 — 로컬 `scripts/couple-emoji-experiment/out/anim-poc/`(gitignore).

## §13 대비

| §13 이 걱정한 것 | 실측 |
| --- | --- |
| 원가 2~3배 | 맞다 — 오히려 원본 포함 3~4배 |
| 장마다 흔들린다 | **얼굴 동일성은 걱정보다 낫다.** 대신 표정·손·소품·크기가 흔들린다. 이모지에서 정작 중요한 "감정"이 프레임마다 다시 해석된다 |

## 다시 꺼낼 때 먼저 볼 것 (미검증 아이디어)

- 포즈 프롬프트에 원본 표정을 명시("keep the exact same heart-shaped eyes")하면 감정 유실은 줄 수 있다 — 모션마다 감정별 문구가 필요해진다.
- 프레임을 장마다 따로 부르지 말고 **한 번 호출로 2×2 스프라이트 시트**를 그리게 하면 원가 1장·프레임 간 일관성 둘 다 나아질 가능성이 있다. 해 보지 않았다.
