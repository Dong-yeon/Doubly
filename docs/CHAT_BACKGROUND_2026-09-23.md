# 채팅 배경을 채팅방으로 옮기고 사진 배경을 붙였다 (2026-09-23)

## 1. 왜 건드렸나

설정 화면에 색 고르는 목록이 **둘** 있었다 — 액센트(그린·민트·피치)와 채팅 배경(10종).
같은 높이에 나란히 있으니 "왜 색을 두 번 고르지"가 됐다.

근거는 느낌이 아니라 **이름 충돌**이었다. 두 목록에 '민트'와 '피치'가 같이 있는데 서로 다른
색을 낸다.

| 고른 것 | 내 말풍선 실제 색 |
| --- | --- |
| 액센트 **피치** + 채팅배경 기본 | `#62B16B` — **초록** |
| 채팅배경 **피치** | `#B25500` — 주황 |

액센트 피치의 `primary` 계열이 초록인 것은 §3-1(상대 색 = 초록) 제약 때문이고
(`colors.ts:325`), 의도된 값이다. 겹친 건 **이름**이다.

## 2. 합치지 않고 층을 나눴다

"둘을 한 목록으로" 는 **접었다**. 데이터를 합치려면 둘 중 하나여야 한다.

- 채팅 테마 10종에 앱 팔레트를 붙인다 → 액센트 하나가 `Palette` 토큰 **34개 × 라이트/다크
  = 68값**이다(`ACCENT_OVERRIDES`). 7벌을 손으로 더 맞춰야 한다.
- 채팅 테마를 3종으로 줄인다 → 7종이 사라진다.

게다가 **넷은 합칠 수가 없다**. 차콜·포레스트·인디고·플럼은 "라이트 앱인데 채팅만 진하게"가
존재 이유라(`chatTheme.ts` 진한 배경 계열 주석), 앱까지 어두워지면 그건 다크 모드고 바로 위
테마(시스템/라이트/다크) 축과 싸운다.

**진짜 문제는 둘이 별개라는 게 아니라 설정에서 나란히 있다는 것이었다.** 액센트는 앱 전체
정체성(3종), 채팅 배경은 그 방의 취향(10종)으로 층이 다르다. 카톡·라인도 배경은 방 안에서
고른다. 그래서 자리만 옮겼다.

- 설정 "화면" 섹션 = 테마 + 액센트. 채팅 배경 섹션 삭제.
- 채팅방 ⋮ → **채팅 배경** → `ChatBackgroundSheet`.
- 겹치던 라벨 둘만 실제 색으로 개명: 피치→**앰버**, 민트→**에메랄드**. **id 는 그대로**라
  이미 고른 사람의 선택은 유지된다.

## 3. 사진 배경 — 배경이 아니라 글자를 고쳤다

`expo-image-picker`·`expo-image-manipulator`·`expo-file-system` 이 전부 이미 있어서
**새 의존성 0 → 빌드가 아니라 OTA** 다(`docs/EAS_BUILD.md` §8).

### 무엇이 깨지는가

팔레트는 **배경 휘도를 안다**는 전제 위에 서 있다 — 말풍선 없이 배경에 직접 얹히는 것들이
있기 때문이다(시간 10px·"보내는 중"·"수정됨"·날짜 구분선). 사진은 픽셀마다 휘도가 달라 그
전제가 깨진다. **스크림으로는 보장이 안 된다**: 순백 사진에 45% 검정을 씌워도 여전히 밝다.

### 해법

배경을 누르는 대신 **맨살 글자에 알약(캡슐)을 깐다** — 카톡의 날짜 라벨과 같은 방식이다.

| 값 | 근거 |
| --- | --- |
| 캡슐 `rgba(0,0,0,0.55)` | **가장 밝은 사진(순백)에서도** 흰 글자 **4.76:1**. 0.45 면 4.48 로 AA 아래, 더 올리면 사진이 안 보인다 |
| 글자 `#FFFFFF` | 캡슐이 어둡다고 보장되므로 테마와 무관하게 고정 |
| 구분선 `transparent` | 날짜 라벨이 캡슐을 얻으면 좌우 줄이 사진과 싸운다 |
| 스크림 `rgba(0,0,0,0.18)` | **대비용이 아니다**(그 일은 캡슐이 한다). 번잡한 사진에서 말풍선 경계가 덜 싸우게 하는 미관용, 한 단계 고정 |

캡슐은 `Text` 스타일에 얹는다 — RN 의 Text 가 배경색·반경을 스스로 그리므로 **JSX 에 사진
모드 분기를 심지 않는다**(`ChatRoomScreen` 한 파일에서만 다섯 자리가 갈라졌을 것이다).

### 사진은 테마를 대체하지 않는다

배경만 덮는다. "인디고 + 사진"이 되고, 말풍선·글자는 고른 테마의 **검증된 값 그대로**다.
그래서 `verify:chat-theme` 의 120건이 사진 기능과 무관하게 유효하다.

`background` 색은 사진 모드에서도 **안 건드린다** — 사진 레이어가 그 위에 깔리므로 파일이
사라지거나 디코딩이 실패하면 고른 테마의 배경색으로 떨어진다.

### 저장

로컬이다(`chatThemeStore` 의 기존 판단 유지 — 서버에 올리면 Cloudinary·관계 단위 삭제·
Purger 순서가 딸려오는데 얻는 건 "기기를 바꿔도 따라온다" 하나뿐). 피커·매니퓰레이터가 주는
uri 는 전부 **캐시 디렉터리**라 시스템이 비우면 사라지므로, 문서 폴더로 복사하고 그 경로를
기억한다. 파일명에 시각을 박는다 — 같은 이름으로 덮어쓰면 `<Image>` 가 uri 로 캐시해서
**바꿔도 옛 사진이 보인다**.

**웹은 미지원**이다(`chatBackgroundPhoto.web.ts`). 브라우저에 그 폴더가 없고 `blob:` uri 는
탭을 닫으면 죽는다. 남는 길인 data URL 은 배경 한 장이 localStorage 한도를 혼자 먹는다.

## 4. 실기기에서 잡은 것 (태블릿 1200×1920, 안드로이드)

| 증상 | 원인 | 고침 |
| --- | --- | --- |
| **타임스탬프에 캡슐이 안 붙는다** | `chatThemedStyles` 의 캐시 키가 `액센트:스킴:테마id` 뿐이라 **사진 유무가 축에 없었다**. 사진을 켜도 먼저 캐시된 스타일이 그대로 돌아온다 | 키에 `photo`/`plain` 추가. uri 값은 넣지 않는다(고를 때마다 캐시가 한 벌씩 쌓인다) |
| ⋮ 메뉴 마지막 줄이 내비 바에 잘린다 | 시트가 Modal 안이라 화면 SafeAreaView 밖이다. 네 줄일 땐 `paddingBottom` 만으로 넘겼는데 다섯째가 붙으며 넘쳤다 | 두 시트 모두 `useSafeAreaInsets().bottom` 을 더한다 |
| 새 아이콘이 빈칸 | 서브셋 폰트를 다시 만들어야 한다 | `scripts/subset-icon-font.cjs`(=`build:web`) 실행 후 **앱 완전 재시작**. JS 리로드만으로는 폰트가 안 바뀐다 |

**검증 스크립트가 조용히 두 테마를 빠뜨렸다.** 라벨을 고치면서 `id:` 와 `label:` 사이에
주석을 넣었는데, 파서 정규식이 그 둘을 한 덩어리로 훑어서 해당 테마가 통째로 검사에서
빠졌다 — 그런데도 **"전부 통과"는 그대로 나왔다**. "10종"이 "8종"으로 줄어서 들켰다.
선언된 `id:` 수와 파싱된 수를 대조하는 가드를 넣었고, 일부러 깨뜨려 실제로 실패하는 것까지
확인했다. 테마에 붙이는 주석은 이제 **블록 바깥, `{` 위**에 둔다.

## 5. 검증

- `typecheck` · `lint`(문제 229→228, 신규 0) · `verify:chat-theme`(10종 120건) ·
  `verify:nested-buttons` · `build:web` 전부 통과
- 실기기: 설정에서 섹션 사라짐 → ⋮ 메뉴 → 시트 → 테마 전환 → 사진 적용(캡슐 렌더 확인) →
  사진 빼기로 원상 복귀까지 한 바퀴

## 6. 남은 것

- **폰 폭 미확인** — 태블릿에서만 봤다. 시트의 10칸이 360dp 에서 몇 줄로 접히는지 별개 확인.
- 사진 배경 **다크 모드** 미확인. 캡슐은 스킴과 무관한 고정값이라 값은 같지만 실물은 안 봤다.
- 사진 위 `highlight`(검색 강조 행)는 테마 값 그대로 둔다 — 1.8초짜리라 급하지 않지만,
  밝은 사진에서 약할 수 있다.
- 액센트와 이름이 겹치지 않게 바꾼 건 둘뿐이다. '기본'이 액센트를 따라가는 구조는 그대로다.
