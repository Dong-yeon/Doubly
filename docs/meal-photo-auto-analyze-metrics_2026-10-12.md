# 식단 사진 "붙이자마자 분석" — 1주 계측 확인 (2026-10-12)

질문: 럽바디 기록 화면에서 사진을 붙이면 "AI로 음식 분석"을 누르지 않아도 바로 분석하는 게 낫지 않나?
10-05 기록 화면 계획서(`lovebody-record-screen-plan_2026-10-05.md` §보류)가 "한도 소모·비용 판단이 따로 필요"하다며
미뤄 둔 안이고, 그 판단용으로 넣은 `MEAL_*` 계측 1주(10-05~10-11)를 운영 `event_logs` 에서 읽기 전용으로 읽었다.

## 읽는 법의 함정

- `event_logs.created_at` 은 **날짜 단위로 잘려 저장된다**(전부 KST 자정). 같은 날 이벤트의 순서는 시각이 아니라 **`id` 순서**로 봐야 한다.
  처음 시각 기준으로 묶은 쿼리는 엉뚱한 결과를 냈다.
- 표본이 작다 — 기록 화면에서 사진을 쓴 사람은 **1명(user 1)** 뿐이다. 경향은 보이지만 일반화는 못 한다.

## 숫자 (10-05 ~ 10-11)

| 사람 | 쓰는 길 | 내용 |
|---|---|---|
| user 1 | 기록 화면 | 사진을 붙인 기록 **10건 전부** 같은 세션에서 사진 분석을 눌렀다(새 기록 9건 저장 · 1건 이탈). 사진만 붙이고 분석 없이 저장한 적은 **0건** |
| user 1 | 기록 화면 | 그중 **3건은 분석을 두 번** 눌렀다(10-08 ×2, 10-10). 원인(실패 재시도인지 다시 보기인지)은 이벤트로 구분 안 된다 |
| user 1 | 기록 화면 | 수정 화면에서 사진을 새로 붙이지 않고 분석만 다시 누른 경우 1건(10-08) |
| user 5 | 홈 빠른 기록 시트 | 사진만 저장 5건(`sheet;…;a=1`) — 서버 자동 분석에 맡김. 기록 화면에서 사진을 쓴 적 없음 |
| user 14 | 기록 화면 | 10-05 하루에 열고 아무것도 안 넣고 나감 5번(`i=0;p=0`) — 사진 이전 단계의 문제라 이번 질문과 별개 |

텍스트 분석은 6건(전부 user 1), 사진 분석 14건.

## 결론

- **기록 화면에서 사진을 붙인 사람은 예외 없이 분석을 눌렀다.** 그 버튼은 선택지가 아니라 매번 거치는 한 단계다 → 붙이자마자 시작하면
  매번 한 번의 탭과 대기가 줄고, **분석 횟수는 늘지 않는다**(어차피 쓰던 1회). 늘어나는 건 잘못 고른 사진을 다시 고를 때뿐.
- 사진만 빠르게 남기는 사람은 이미 홈 시트 + 서버 자동 분석으로 버튼 없이 쓰고 있다 — 이 길은 건드릴 필요 없다.
- 그래서 **기록 화면에서 "새 사진을 붙였을 때"만** 자동 시작하는 게 맞다. 조건:
  1. 새로 붙인 사진 1장당 1회. 수정 화면을 열었을 때 이미 있던 사진으로는 돌지 않는다(그건 지금처럼 버튼).
  2. 음식 항목이 비어 있을 때만 — 이미 적어 둔 걸 덮지 않는다.
  3. 남은 사진 분석 횟수가 0 이면 돌지 않는다(버튼·안내는 지금 그대로).
  4. 설정의 "음식 사진 자동 분석"(`autoAnalyzeMealPhoto`)을 끈 사람은 돌지 않는다 — 같은 뜻의 스위치다.
  5. 분석 중에 저장하면 기다리지 않고 저장하고, 칼로리는 서버 자동 분석이 채운다(지금 사진만 저장할 때와 같은 길).
  6. 장소 힌트(10-11): 럽슐랭에서 들어와 장소를 이미 알면 그대로 싣는다. 사진 뒤에 장소를 고르면 기존 메뉴 칩으로 이름만 바꾸는 흐름(297caf3f)이 있다.
- "두 번 누른" 3건의 원인은 계측으로 알 수 없다. 자동 시작 뒤에도 같은 패턴이면 실패 재시도일 가능성이 높으니 서버 로그(`docs/STABILITY_*`)와 대조한다.
