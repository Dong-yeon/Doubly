# 채팅 사진 자르기 — 분석 (2026-10-14)

> 요청: "스샷 같은 건 바로 올리기보다 잘라서 올리잖아. 올리기 전에 자르기를 할 수 있으면 좋겠다."
> 분석만 했고 코드는 고치지 않았다. 기준 커밋 `7fd4b5ec`(origin/main).

## 1. 지금 어떻게 되어 있나

| 단계 | 위치 | 동작 |
|---|---|---|
| 고르기 | `ChatRoomScreen.tsx` `onPickImage` → `utils/imageUpload.ts` `pickImages(5)` | 시스템 피커, **`allowsEditing: false`**, 최대 5장 |
| PC 붙여넣기·드롭 | `onDroppedImage` | 같은 미리보기로 들어온다 |
| 미리보기 | `ChatRoomScreen.tsx` 사진 전송 미리보기 `Modal` | 첫 장만 크게(`contain`), 나머지는 아래 줄 썸네일(**누를 수 없음**). 버튼은 취소 / 보내기뿐 |
| 보내기 | `onConfirmSendImage` | 한 장씩 `shrinkUnknownImage(uri, 2048)` → `uploadImage` → `IMAGE` 전송. 한도(PHOTO_UPLOAD)는 **업로드 서명 시점**에 깎인다 |
| 말풍선 | `chatStyles.msgImage` 200×200 + `resizeMode="cover"`, `thumbnailUrl(url, 200)`(Cloudinary `c_fill`) | **정사각으로 가운데만** 보인다 |

**편집 단계는 어디에도 없다.** 시스템 크롭(`allowsEditing`)을 일부러 끈 이유가 `imageUpload.ts` 주석에 있다 —
iOS 는 정사각 고정, 안드로이드는 기기마다 다른 화면, 웹은 미지원. 게다가 `allowsEditing` 은
`allowsMultipleSelection` 과 함께 쓸 수 없어 켜는 순간 여러 장 보내기가 깨진다.

### 함께 발견한 것 (자르기와 맞물린다)

1. **말풍선이 세로 스샷을 잘라 보인다.** 200×200 `cover` 라 1080×2400 스샷은 가운데 정사각만 보이고, 탭해야 전체가 나온다.
   사용자가 "잘려서 올라간다"고 느끼는 것의 절반은 이쪽일 수 있다. 자르기를 만들어도 세로로 긴 결과물은 여전히 잘려 보인다.
2. **R2 사진은 썸네일 변환을 못 탄다.** `thumbnailUrl`·`cardImageUrl` 은 Cloudinary `/image/upload/` 경로에만 변환을 끼우고
   나머지는 원본을 그대로 돌려준다. 10-12 부터 새 업로드는 R2(`media.dubly.co.kr`)라, 채팅 말풍선 200dp 칸에 2048px 원본을 받고 있다
   (전송량·스크롤 성능). 자르기와는 별개지만 같은 말풍선 코드를 만질 때 함께 봐야 한다.

## 2. 쓸 수 있는 재료

- **`components/AvatarCropSheet.tsx`(383줄)** — 프로필·우리 이모지에서 쓰는 직접 만든 크롭 시트. 제스처(`react-native-gesture-handler`)로
  사진을 끌고 핀치/버튼으로 확대, `react-native-svg` 마스크, `expo-image-manipulator` 로 잘라 **로컬 uri 만** 넘긴다(업로드는 호출부, 한도 낭비 없음).
  웹은 확대 버튼으로 대신한다. **고정 원형 프레임 + 사진을 움직이는 방식**이라 그대로는 못 쓴다 — 스샷 자르기는 "사진은 가만히, **틀의 네 모서리를 끄는** 자유 비율"이 맞다.
- 필요한 라이브러리는 전부 이미 들어 있다(`expo-image-manipulator`·gesture-handler·reanimated·svg) → **네이티브 빌드 없이 OTA 로 배포 가능**.

## 3. 방법 비교

| 안 | 내용 | 빌드 | 판단 |
|---|---|---|---|
| A. 직접 만든 자유 자르기 시트 | 미리보기에 "자르기" → 사진 위 사각 틀, 모서리·변 끌기, 비율 칩(자유·원본·1:1·4:5 정도) → `ImageManipulator.crop` | 불필요(OTA) | **권장** |
| B. 시스템 크롭(`allowsEditing: true`) | 피커가 고른 직후 OS 편집 화면 | 불필요 | 탈락 — 여러 장 선택 불가, iOS 정사각 고정, 웹 미지원, 붙여넣기 경로엔 적용 안 됨 |
| C. 네이티브 크롭 라이브러리(`react-native-image-crop-picker` 등) | 회전·자유 비율까지 완성품 | **필요** + 의존성 추가 | 보류 — 기능은 좋지만 빌드 비용·웹 미지원·피커 교체 범위가 크다 |

## 4. 권장안 (A) 의 모양

1. **미리보기를 "고를 수 있는" 목록으로** — 아래 줄 썸네일을 누르면 그 사진이 크게 뜬다(지금은 첫 장 고정).
2. 크게 보이는 사진 위에 **[자르기]** 버튼. 누르면 같은 모달 안에서 자르기 모드:
   - 틀은 처음에 사진 전체. 모서리 4개·변 4개 손잡이를 끈다. 틀 안을 끌면 틀이 이동한다.
   - 비율 칩: 자유(기본) · 1:1 · 4:5 · 원본. 스샷은 대부분 "자유"로 위아래만 잘라낸다.
   - [되돌리기]·[완료]. 완료하면 그 사진만 잘린 로컬 uri 로 바뀐다(썸네일에 ✂ 표시). 업로드 없음.
3. 보내기는 지금 그대로 — 잘린 uri 가 `shrinkUnknownImage` → `uploadImage` 를 탄다. **한도·순서·실패 복원 로직은 손대지 않는다.**
4. 원본 uri 는 보낼 때까지 들고 있어 "원래대로"가 가능하다. 웹 `blob:` 은 기존처럼 `releaseObjectUrl` 로 풀어 준다(잘린 사본도).
5. 공용 컴포넌트(`components/PhotoCropSheet.tsx` 같은)로 만들어 두면 일상 남기기(`FeedComposeScreen`, 최대 5장)에도 그대로 붙는다.

**말풍선 비율(§1-1)은 같이 고칠 것을 권한다.** 잘라도 정사각으로 다시 잘려 보이면 체감이 없다. 메시지에 이미 원본 크기가 없으므로
가장 싼 길은 "가로 200dp 고정, 세로는 이미지 비율대로(최대 280dp, 넘으면 위쪽 기준 cover)" — `Image.getSize`/`expo-image` 의 onLoad 로
비율을 얻는다. 서버 변경 없음.

## 5. 위험·확인할 것

- **좌표 변환**: 미리보기는 `contain` 이라 화면 좌표 ↔ 원본 픽셀 비율·여백을 계산해야 한다. 원본 크기는 `Image.getSize` 로 재는데,
  안드로이드 EXIF 회전 사진은 잰 크기와 실제 방향이 어긋날 수 있다 — 갤러리 세로 사진·카메라 사진·스샷 세 종류로 실기기 확인 필요.
- **웹**: 마우스 드래그는 gesture-handler 로 되지만 붙여넣은 `blob:` 을 manipulator 가 다루는지 확인 필요(`shrinkUnknownImage` 는 이미 같은 경로를 탄다).
- 이상 사용(전역 지침): 틀을 0 크기·화면 밖으로 끌기, 자르기 중 모달 닫기(뒤로 가기), 자른 뒤 다시 자르기, 5장 모두 자른 뒤 한 장만 취소,
  자르기 도중 한도 초과 상태에서 보내기, 아주 큰 이미지(파노라마·4000px 이상)·아주 작은 이미지(100px 스티커).

## 6. 결정이 필요한 것

1. 범위 — 채팅만 / 채팅 + 일상 남기기.
2. 말풍선 비율(§4 끝)을 같이 할지.
3. 회전까지 넣을지(권장: 1차는 자르기만, `ImageManipulator.rotate` 로 나중에 쉽게 붙는다).
4. R2 썸네일(§1-2)은 별개 작업으로 뺄지.
