# 스티커 팩 하이브리드 수익화 (2026-09-21)

구독(PRO)이면 전부 열리고, 아니면 원하는 팩만 낱개로 사는 구조를 넣었다. 함께 PRO 대표
기능 셋을 서버가 정하도록 바꿨다.

## 0. 최종 모델 — 세 갈래

작업 중에 과금 구조가 한 번 크게 바뀌었다. 아래 절들은 그 과정을 순서대로 적은 것이라
**결론은 이 표**다.

| 트랙 | 과금 | 근거 |
|---|---|---|
| **움직이는 이모티콘** 110종 8팩 | **전부 무료** | 결국 폰 키보드에도 있는 글자다. 움직인다는 것만으로는 상품 근거가 얇다 |
| **캐릭터 스티커** | **상점 낱개 구매** | 유니코드에 없다. 우리가 그린 것 |
| **우리 이모지** | **PRO 구독 전용** | 유니코드에 없고, 원가가 실제로 나간다(장당 약 0.04 USD) |

파는 것이 **유니코드에 없는 것**으로 모였다. 2026-09-14 에 "유니코드 이모지는 팔 수 없다"
까지 갔던 논리를 끝까지 적용한 결과다 — 그때는 움직이는 이모티콘 24종을 PRO 로 남겼는데,
같은 잣대를 대면 그쪽도 버티지 못했다.

**"우리 이모지 PRO 전용"은 코드 변경이 없다.** 낱개로 못 사고 구독으로만 열린다는 뜻이고,
`Feature.AI_COUPLE_EMOJI` 가 이미 그렇게 동작한다. 만들어 둔 세트는 구독이 끊겨도 계속
쓴다 — 이미 원가가 나간 자산을 회수하지 않는다.

## 1. 왜 팩을 다시 만드나 — 2026-09-14 결정과 충돌하지 않는다

일주일 전에 `StickerPack` enum 을 지웠다(`STICKER_PACK_OVERLAP_2026-09-14.md`). 그때
지운 것은 **유니코드 이모지를 팩으로 묶어 PRO 로 팔던 것**이고, 근거는 "폰 키보드에 이미
있는 글자를 파는 모양"이었다. 여기서 되살리는 팩은 세 가지가 다르다.

1. **묶는 대상이 다르다.** Lottie 애니메이션과 번들 PNG 다. 키보드로 대체할 수 없다.
2. **역할이 다르다.** 그때 팩은 *판정 기준*이었다(이 팩에 있으면 PRO). 지금 팩은
   *상품 단위*다 — 판정은 "무료인가 / 샀는가 / 구독인가" 셋으로 갈리고, 팩은 그중
   "샀는가"를 적을 자리다. enum 의 boolean 한 칸으로는 **무엇을 샀는지 적을 수 없다**.
3. **무료로 주던 것을 잠그지 않는다.** 최종적으로 움직이는 이모티콘은 8팩 전부 무료가
   됐고, `StickerPackSyncTest.누가_무엇을_쓸_수_있는지는_그대로다` 가 그 불변식을 값으로
   고정한다 — 한 장이라도 유료 팩에 들어가면 깨진다.

## 2. 판정 — 세 갈래

`StickerService.requireUsable(userId, packId)` 하나를 지난다. 순서가 곧 비용 순서다.

| 갈래 | 조건 | 비고 |
|---|---|---|
| 무료 팩 | `is_pro_only = false AND price = 0` | 대부분 여기서 끝난다 |
| 낱개 구매 | `user_sticker_purchases` 에 행이 있다 | 구독과 무관·영구. `PlanGuard` 를 지나지 않는다 |
| PRO 구독 | `PlanGuard.require(카테고리의 Feature)` | 402 문구·계측이 전부 거기 붙어 있다 |

**마지막을 `PlanGuard` 에 위임한 이유**: 402 문구, `PLAN_UPGRADE_REQUIRED` vs
`USAGE_LIMIT_EXCEEDED` 구분("돈 낸 사람에게 결제를 또 권하지 않는다"), `FEATURE_USED`/
`FEATURE_BLOCKED` 계측이 모두 거기 있다. 직접 던지면 이 경로에서만 조용히 사라진다.

**모르는 코드는 통과시킨다.** 팩에 없는 content(유니코드 이모지·우리 이모지 id·내린
캐릭터의 지난 코드·시드에 없는 팩 id)는 전부 무료로 지난다. 관대함이 아니라 재발 방지다 —
STOMP 는 402 를 화면으로 돌려줄 방법이 없어서, 무료라고 보여 준 것을 막으면 말풍선이
"전송 중"에서 영영 멈춘다. `MoodPack` 이 "목록에 없는 이모지는 무료다"로 이미 쓰던 규칙이다.

**소유는 개인, 사용은 커플.** 구매 행은 산 사람에게 붙지만 판정은 커플 상대까지 퍼진다.
`Feature.PREMIUM_STICKER` 가 이미 커플 단위 판정이라, 낱개만 개인 판정으로 두면 "구독으로
열면 둘 다 쓰는데 낱개로 사면 나만 쓴다"는 설명할 수 없는 차이가 생긴다.

## 3. 시드한 팩 — 12개

`IMAGE` 카테고리는 한 행도 없다 — 이미지 스티커를 전부 내렸다(4절). 캐릭터 팩이 들어오면
여기에 붙는다.

| id | 이름 | 카테고리 | 유료 | 가격 | 장수 |
|---|---|---|---|---|---|
| `ANIM_LOVE` | 사랑 | ANIMATED | | 0 | 18 |
| `ANIM_FUN` | 웃음·장난 | ANIMATED | | 0 | 18 |
| `ANIM_UPSET` | 속상해 | ANIMATED | | 0 | 16 |
| `ANIM_CELEBRATE` | 축하해 | ANIMATED | | 0 | 14 |
| `ANIM_CHEER` | 응원해 | ANIMATED | | 0 | 18 |
| `ANIM_ANIMAL` | 동물 | ANIMATED | | 0 | 9 |
| `ANIM_FOOD` | 먹을 것 | ANIMATED | | 0 | 10 |
| `ANIM_WEATHER` | 날씨 | ANIMATED | | 0 | 7 |
| `MOOD_BASIC` | 기본 무드 | MOOD | | 0 | 12 |
| `TOUCH_BASIC` | 기본 터치 | TOUCH | | 0 | 3 |
| `MOOD_PREMIUM` | 확장 무드 | MOOD | ✓ | 1,200 | 12 |
| `TOUCH_PREMIUM` | 프리미엄 터치 | TOUCH | ✓ | 1,200 | 2 |

**지금 상점에 팔 물건이 둘뿐이다** — 확장 무드와 프리미엄 터치. 캐릭터 스티커를 전부
내렸기 때문이고, 새 그림이 들어와야 채워진다.

**내린 스티커는 일부러 시드하지 않았다** — 팩이 없으면 무료로 통과하고, 그게 지난 말풍선이
그대로 그려지는 근거다(4절).

**스토어 상품 id 는 컬럼이 아니라 규칙이다**: `sticker_pack_` + 팩 id 소문자
(`ANIM_LOVE → sticker_pack_anim_love`). 행마다 적으면 오타가 곧 "산 사람이 못 쓰는"
사고가 된다. 콘솔에 등록할 때 이 규칙을 따를 것.

## 4. 이미지 스티커를 전부 내렸다 — 그리고 그 과정에서 낸 버그

그림 출처를 정리하는 동안 **곰돌이 10 · 더비 14 · 블리 14 를 피커에서 통째로 뺐다**.
패널에 남는 건 움직이는 이모티콘(Noto Animated Emoji — CC BY 4.0 / Apache 2.0, 라이선스가
확실하다)과 우리 이모지(사용자 본인 사진으로 런타임 생성)뿐이다.

**AI 로 만들었다는 게 문제였던 적은 없다.** 앱 아이콘부터가 AI 로 뽑은 것이고 그대로 쓴다.
걸리는 건 <b>무엇을 레퍼런스로 넣었나</b> 하나뿐이다 — 본인 그림이면 문제없고(더비·블리),
출처가 확인 안 되면 뺀다(곰돌이).

곰돌이는 "완성본 한 장을 참조 삼아 `variants.mjs` 로 변주를 뽑은" 세트라 그 참조 그림의
출처가 확인되지 않았다. **더비·블리는 출처 문제가 없다** — 동연님 손그림 스케치에서 나온
자체 캐릭터다. 그림 교체 계획 때문에 잠시 내렸을 뿐이라, 되살리려면 목록을 옮기고
`CHARACTER_PACKS` 에 두 줄이면 된다.

### 고르는 것과 그리는 것은 다른 일이다

처음 구현에서 더비·블리를 `STICKER_CHARACTERS` 에서 빼면서 **말풍선 조회 목록까지 같이
비웠다**. `STICKER_IMAGES = STICKER_CHARACTERS.flatMap(...)` 이었고, 그게
`stickerImageOf()` 의 유일한 출처였다 — 즉 "피커에서만 내린다"고 정한 것이 실제로는
**지난 말풍선을 빈 칸으로 만드는** 변경이었다. 라벨만 사라지는 거라 tsc 도 못 잡고,
앱을 열어 옛 대화를 스크롤해야 보인다.

그래서 목록을 둘로 쪼갰다.

| 목록 | 쓰임 | 지금 내용 |
|---|---|---|
| `STICKER_CHARACTERS` | 피커 스트립 | 비어 있음 |
| `RETIRED_STICKER_IMAGES` | 말풍선·알림 미리보기 | 곰돌이 10 + 더비 14 + 블리 14 |
| `STICKER_IMAGES` | 위 둘의 합 — `stickerImageOf()` 의 출처 | 38장 |

`StickerImageSyncTest` 도 **두 집합을 각각** 대조하도록 바꿨다. 한쪽만 보면 정확히 위
상태를 놓친다. 에셋 파일도 남겨 둬야 한다 — `require` 경로가 비면 번들에서 터진다.

## 5. 우리 이모지를 사람별로 나눴다

커플이 각자 얼굴로 만드는데 한 팩에 섞여 있었다. 내 얼굴과 상대 얼굴이 같은 격자에서
뒤섞이면 보내려던 장을 찾는 데 시간이 걸리고, 세트가 두 벌이라는 것도 안 읽힌다.
`subjectUserId` 로 갈라 스트립 칸 두 개("내 이모지" / "{상대이름} 이모지")로 편다.

한 세트도 없는 쪽은 칸을 만들지 않는다 — 빈 칸이 둘이면 고장으로 읽힌다. 둘 다 없으면
"내 이모지" 칸 하나만 남겨 만들기 안내를 띄운다(기존 동작 유지).

## 6. 패널 UI — 잠금이 칸에서 팩으로 올라갔다

예전엔 움직이는 이모티콘 한 팩 안에서 칸마다 무료/PRO 가 갈렸다. 그러면 "무엇을 사는가"가
격자 안에 흩어져 읽히지 않는다. 지금은:

- 잠긴 팩은 스트립에서 **자물쇠 배지**(재생 배지를 이긴다 — 잠긴 팩에서 알아야 할 것은
  "움직인다"가 아니다)
- 열면 격자가 흐려진 채 아래에 **잠금 해제 줄**이 깔린다. 격자를 숨기지 않는 게 요점이다:
  **살 것을 먼저 보여준 뒤에 값을 말한다**
- 무료 팩이 스트립 앞에 온다. 잠긴 팩이 앞에 서면 패널 전체가 유료처럼 보인다
- 기본 선택은 `ANIM_LOVE` — 커플 앱에서 가장 많이 쓰는 결이고, 무료 팩이다

팩 이름과 가격은 **서버가 내려준다**(`GET /stickers/packs`). 앱에 박으면 바꿀 때마다
스토어 심사를 기다려야 한다. 어느 코드가 어느 팩인지만 앱이 번들로 들고 있다
(`constants/stickerPacks.ts`).

## 7. 결제 검증

`POST /stickers/purchases/google|apple` — 구독 검증과 같은 원칙이다.

- **앱이 보낸 내용을 믿지 않는다.** 무슨 상품인지도 누구 것인지도 스토어에 되물어서 정한다
  (Play `purchases.products.get`, App Store `/inApps/v1/transactions/{id}`).
  `packId` 는 **검증 대상이지 근거가 아니다** — 스토어 응답과 다르면 거절한다.
- **귀속은 스토어의 계정 식별자로만.** `obfuscatedExternalAccountId` / `appAccountToken`.
  로그인한 사람과 다르면 붙이지 않는다.
- **보류(pending)는 유효로 보지 않는다.** 일회성 상품은 만료가 없어서, 먼저 열어주면
  승인이 끝내 안 나도 회수할 경로가 없다.
- **키가 없으면 거절한다.** 구독 동기화는 조용히 건너뛰지만(웹훅이라 다음 신호가 또 온다)
  여기는 사용자가 방금 결제를 누른 자리다. 조용히 넘어가면 돈은 나갔는데 아무 말도 없다.
- 같은 영수증이 다시 와도 멱등이다(복원·재설치). `(user_id, pack_id)` unique 인덱스.

**아직 안 붙은 것**: 스토어 콘솔의 일회성 상품 등록과 앱의 결제 SDK 호출. 지금 앱은
잠금 해제 줄을 누르면 안내 시트만 뜬다(`ChatRoomScreen.unlockStickerPack`). 콘솔에
상품을 올린 뒤 그 자리에서 `stickerApi.verifyGoogle/verifyApple` 로 이으면 된다.

## 8. Purger — 한쪽만 지운다

- **`UserDataPurger`: 지운다.** `user_id` 에 FK 가 없어서 탈퇴를 막지는 않지만, 그래서
  오히려 빠뜨리면 조용히 남는다(`ai_usage_logs` 와 같은 모양). 환불·정산 근거는 스토어
  콘솔에 남으므로 지워도 된다.
- **`RelationRecordPurger`: 일부러 안 지운다.** 일회성 상품이라 산 사람에게 영구 귀속되고,
  관계가 끝났다고 회수하면 환불 없는 몰수다. 관계 참조가 없어 FK 위반도 안 난다
  (테이블에 `relation_id` 컬럼 자체가 없다). 헤어진 뒤 달라지는 건 **사용 범위**뿐이고,
  그건 `ownedPackIds` 가 활성 커플을 다시 조회하므로 저절로 반영된다.

두 방향 모두 `WithdrawFlowTest` 가 본다 — "탈퇴가 성공했다"만으로는 FK 없는 테이블에 대해
아무것도 증명되지 않으므로, 행이 실제로 사라졌는지/남았는지를 확인한다.

## 9. PRO 대표 기능 셋

기획의 세 가지를 `Feature.isHero()` 로 표시하고 `/plan/catalog` 가 `hero` 로 내린다.

| 기획 이름 | 코드 | 상태 |
|---|---|---|
| `AI_EMOJI_CREATOR` | `AI_COUPLE_EMOJI` | **이름을 바꾸지 않았다** |
| `AI_FOOD_PHOTO` | 그대로 | 무료도 하루 5회 — 유일한 "체감가치 훅" |
| `WORKOUT_V2_STATS` | 신설 | 볼륨·1RM·부위 밸런스 |

**`AI_COUPLE_EMOJI` 를 안 바꾼 이유**: `usage_counters`·`ai_usage_logs`·분석 이벤트가 전부
이 enum 이름을 **문자열로** 들고 있다. 상수만 갈면 과거 사용량과 원가 집계가 통째로 끊긴다.

**`WORKOUT_V2_STATS` 는 실제로 게이트한다.** 게이트하지 않는 Feature 는 매핑된 게 아니다.
`GET /workout/stats` 에 `deep` 블록(8주 볼륨 추이 · 추정 1RM 상위 5종목 · 30일 부위 비중)을
더하고 잠겼으면 `null` 로 내린다 — 402 를 던지면 통계 화면이 통째로 못 뜬다
(`MealStatsResponse` 가 `FULL_STATS` 로 쓰는 모양 그대로).

**무료에서 아무것도 회수하지 않았다.** 주·월 운동일수, 최근 7일 그래프, 30일 부위별 세트
수는 전부 그대로다. 잠기는 건 새로 계산해 얹은 세 가지뿐이다.

`FULL_STATS` 와 따로 둔 이유: 저쪽은 "무료는 최근 구간만"이라는 **기간** 게이트고 실제
적용도 식단 통계 한 곳뿐이다. 이쪽은 기간이 아니라 **지표 자체**를 연다. 합치면 식단 통계의
기간 제한을 풀 때 운동 지표까지 같이 열린다.

`PlanScreen` 의 대표 기능 4개 하드코딩도 서버 `hero` 기준으로 바꿨다. 앱에는 한 줄 문구만
남는다(문구는 한도가 아니라 편집 판단이다).

## 10. 집계는 SQL 이 아니라 자바에서

`findDeepStatRows` 는 완료된 세트를 그대로 긁어오고 볼륨·1RM·밸런스를 자바에서 세 번 접는다.
주 단위 묶기가 `date_trunc` 를 부르는데 H2/PostgreSQL 양립 제약(CLAUDE.md 4절)에 걸린다.
범위가 8주라 헤비 유저도 수백 행이고, 질의 세 개보다 싸다.

요약 필드(`WorkoutSet.weightKg`)가 아니라 `entries` 를 본다 — 요약은 마지막 세트 값이라
백오프 세트에서 최고 무게와 총 볼륨을 둘 다 놓친다. `completed = true` 만 센다(진행 중인
세션의 체크 안 된 세트가 섞이면 오늘 숫자가 실제보다 커진다).

## 11. 움직이는 이모티콘 30 → 110종

Noto Animated Emoji 는 처음 들여올 때 100여 종이었는데 지금은 400종이 넘는다. 30종만 쓰고
있었다 — 같은 라이선스·같은 포맷·같은 렌더 코드라 추가 비용이 사실상 0이다.

일괄 수집 경로: `https://fonts.gstatic.com/s/e/notoemoji/latest/<codepoint>/lottie.json`
(정적 썸네일은 `googlefonts/noto-emoji` 의 `2D/png/72/emoji_u<cp>.png` — 경로가 옛날
`png/72/` 에서 바뀌었다). **전부 애니메이션이 있는 건 아니다** — 🎀🍰🧁🐶🐰🍺💤📱 등은 404 라
후보를 실제로 찔러보고 골랐다.

핑거하트(🫰)·손하트(🫶)가 없었다. 한국 사용자가 제일 많이 쓰는 제스처인데 빠져 있었다.

팩당 12~18장으로 맞췄다 — 격자가 **스크롤 없이 18장**까지 보이기 때문이다
(`MAX_PANEL_HEIGHT` 주석).

**번들이 1.9MB → 7.7MB 늘었다.** 에셋만 바뀌므로 OTA 로 나간다. 큰 것 넷이 평균을 올렸는데
(아이스크림 333KB · 유니콘 271KB · 폭발 229KB · 버거 201KB) 빼면 1MB 줄어든다.

카탈로그 3종(백엔드 enum · 프론트 카탈로그 · 팩 매핑)은 한 원본에서 생성했고
`StickerPackSyncTest` 가 대조한다. **기존 30종은 코드·라벨을 그대로 두고 팩만 배정했다** —
content 에 코드가 저장돼 있어서 지난 말풍선이 그대로 읽힌다.
