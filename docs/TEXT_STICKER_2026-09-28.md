# 문구 스티커 (2026-09-28)

> 작업 프롬프트: `STICKER_ENGAGEMENT_PROMPTS_2026-09-28.md` 프롬프트 ①. 브랜치 `feat/text-sticker` → `main`.
> 캐릭터 스티커(달걀이·구운이♥달걀이) 위에 짧은 문구(최대 12자)를 얹어 보낸다. 예: "지민아 사랑해".

## 1. 결정

### 1-1. content 에 문구를 담는다 (코드가 아니라)

- 새 타입 `TEXT_STICKER` 에서 **`content` = 사용자가 쓴 문구 그대로**를 담는다. 스티커 코드는 새 nullable 컬럼
  `chat_messages.sticker_code`(V107)에 담는다.
- **이유 — 옛 앱 호환**: 스토어에 있는 옛 앱은 이 타입을 모른다. 옛 앱이 모르는 타입을 어떻게 그리는지 먼저 확인했다.
  - 스토어 1.0.3 소스(`5c34c06`)의 `ChatRoomScreen` 은 알려진 분기에 안 걸리는 메시지를 `item.content` 그대로
    **글 말풍선**으로 그린다. `messagePreview` 도 `default: return content` 다.
  - 그래서 문구를 content 에 두면 옛 앱에서는 "지민아 사랑해"가 평범한 말로 읽힌다(그림만 빠진다).
    코드를 content 에 두면 옛 앱에 `EGG_LOVE|지민아…` 같은 문자열이 뜬다.
  - `STREAK_CARD`·`GAME_CARD` 가 이미 이 규칙을 쓴다.
- 부수 효과: 검색·알림 미리보기·답장 인용이 content 를 그대로 쓸 수 있다.

### 1-2. 그림은 앱이 합성한다 (서버 합성 아님)

- 서버는 문구와 코드만 저장한다. 이미지를 만들지도, Cloudinary 에 올리지도 않는다 → **원가 0**, 업로드 한도와도 무관하다.
- 스티커 그림을 고치거나 글꼴을 바꾸면 **지난 메시지도 같이 바뀐다**. 합성 이미지를 저장했다면 옛 그림이 박제된다.
- 서버 합성은 이미지 라이브러리·한글 글꼴을 서버에 들이고, 전송마다 렌더·업로드를 붙인다. 얻는 것은 "옛 앱에서도 그림이 보인다" 하나다.
  1-1 로 옛 앱은 이미 문구를 읽을 수 있으므로 그 하나의 값이 작다.

### 1-3. 그 밖의 결정

| 항목 | 결정 | 이유 |
| --- | --- | --- |
| 얹을 수 있는 스티커 | 피커에 있는 **캐릭터 스티커만**(`StickerImage` 중 내리지 않은 것) | 움직이는 이모티콘은 Lottie 라 글자를 얹을 자리가 매 프레임 바뀐다. 내린 스티커는 새로 고를 수 없어야 한다 |
| 길이 | 1~12자, **코드포인트** 기준, 줄바꿈 금지 | 스티커 아래 띠 두 줄에 들어가는 길이. 서버 `codePointCount` 와 앱 `Array.from().length` 가 같은 셈이다. ❤️(변형 선택자)는 2자로 센다 — 앱과 서버가 다르게 세서 거절되는 것보다 낫다 |
| 팩 사용권 | STICKER 와 같은 `requireUsable` | 잠긴 팩의 그림에 글만 얹어 우회하면 안 된다 |
| 알림 미리보기 | `[스티커] 문구` | 스티커 라벨("사랑해")보다 사용자가 쓴 말이 더 의미 있다 |
| 방 목록·답장 배너 | 문구만 | 프롬프트대로 |
| 검색 | TEXT 와 같이 찾는다 | content 가 사람이 쓴 문장이다 |
| **수정** | 지원 안 함 | 서버·앱 모두 수정을 TEXT 에만 허용한다. 그대로 뒀다 |
| **예약 전송** | 지원 안 함 | 예약 테이블(`scheduled_chat_messages`)에도 코드 컬럼이 필요해진다. 이번 범위에서 뺐다. 서버 허용 목록에 없어 400 이다 |
| 답장·삭제·반응·북마크 | 동작 | 타입과 무관한 경로다. 삭제하면 `sticker_code` 도 비운다 |
| 관계 복원(`RelationRecordRestorer`) | 변경 없음 | 행째 `relation_id` 만 바꾸므로 새 컬럼도 따라간다 |
| Purger | 변경 없음 | 테이블이 늘지 않았다 |

### 2-1. 앱 동작

- **스티커 패널**: 캐릭터 스티커를 **짧게 누르면 예전처럼 바로 전송**하고, **길게 누르면 "문구 넣기" 시트**를 연다.
  움직이는 이모티콘·우리 이모지·잠긴 팩에는 길게 누르기를 붙이지 않았다.
- **추천 막대**: 캐릭터 스티커를 길게 누르면 **지금 입력 중인 문장을 문구로** 넣은 시트가 열린다(12자 넘으면 잘라서, 줄바꿈은 공백으로).
  이 경로로 보내면 **입력창을 비운다** — 문장이 스티커로 옮겨 갔으니 같은 말이 글로 또 나가지 않게 한다.
  코드 입력 중("(달걀이_")에는 옮길 문장이 없어 빈 시트로 연다.
- **시트**: 미리보기(말풍선과 같은 컴포넌트), 입력(12자 카운터), 빠른 문구 칩 6개("{이름}아/야 사랑해"·보고 싶어·잘 자·좋은 아침·고마워·미안해).
  이름 조사는 `withJosa`. 상대 이름이 없거나 붙여서 12자를 넘으면 그 칩은 뺀다.
- **말풍선**: 132px 스티커 그림 하단 약 25% 에 Pretendard SemiBold 문구를 겹친다. 길이에 따라 18→13pt, 두 줄까지.
  외곽선은 RN textShadow 로는 안 돼서 같은 글을 흰색으로 네 방향에 깔고 진한 글을 얹었다.
- 문구 스티커를 보내면 "최근 보낸 스티커"에도 올라간다(추천 순서, `STICKER_SUGGEST_REVIVE_2026-09-28.md`).

## 3. 사실 확인에서 바로잡은 것

- 🔸 **스티커 PNG 는 배경이 투명하다**(RGBA, 모서리 alpha 0, 34~48% 가 투명). 처음 쓴 주석은 "흰 배경 그림이라 글자색 고정"이었는데 틀렸다.
  글자 뒤가 채팅 배경(라이트·다크·사진)일 수도 있다. 진한 글 + 흰 외곽선은 어느 위에서도 읽혀서 **고정 색은 유지**하고 근거만 고쳤다.
- 🔸 **그림은 360×305 가로형**이고, 눈·표정은 높이의 40~65% 쯤에 있다. 하단 25% 에는 **손·발·소품**(예: `egg_love` 의 하트 손)이 있다.
  프롬프트대로 하단에 겹쳤지만 **소품 일부를 덮는다**. 실기기에서 거슬리면 띠를 그림 **아래로** 빼는 것이 대안이다(말풍선이 약 30px 길어진다).

## 5. 실기기로 확인할 것

1. **띠가 소품을 덮는 정도**(§3) — 43종 중 하단에 소품이 큰 것(하트 손·발) 몇 장을 문구 1자·12자로 보내 본다. 거슬리면 "그림 아래" 안으로 바꾼다.
2. 라이트·다크·사진 배경에서 글자가 읽히는지. 흰 외곽선 1.5px 이 저해상도 기기에서 끊겨 보이지 않는지.
3. 패널에서 짧게 누르기 = 즉시 전송, 길게 누르기 = 시트. 스크롤하다 길게 누르기가 잘못 걸리지 않는지(delay 350ms).
4. 추천 막대 길게 누르기 → 입력 문장이 시트에 들어오고, 보내면 입력창이 비는지.
5. 시트: 키보드가 입력창을 덮지 않는지(Android — KeyboardAvoidingView 가 iOS 에만 padding 이다. ScheduleMessageSheet 와 같은 구성).
   빠른 문구 칩, 12자에서 더 안 쳐지는지, 붙여넣은 줄바꿈이 공백이 되는지.
6. **옛 앱(스토어 버전)**에서 문구 스티커가 글 말풍선 "지민아 사랑해"로 보이는지. 푸시 알림 문구 `[스티커] 지민아 사랑해`.
7. 답장·삭제·리액션·북마크, 검색에서 문구로 찾아지는지.
8. 웹: 글꼴(Pretendard)이 적용되는지, 외곽선이 보이는지.

### A 구현 기록 (2026-09-28)

- `constants/stickerMotion.ts` — 피커의 43장 전부에 모션 종류를 붙였다. **43장을 한 장에 모아 직접 보고** 골랐다(라벨만으로 고르지 않았다).
  - 화남·폭발·대판 싸움·열받아 → 떨림(shake), 사랑해·반했어 → 두근(beat), 우울·속상해·하아·더워 → 처짐(droop),
    삐짐·흥·째려봄 → 고개 젖히고 버티기(hold), 아하·헉·넵·꽃다발류 → 팝(pop), 식은땀·난감·얼었어·엉엉 → 잔떨림(jitter) 등.
  - **녹는다**는 바닥의 웅덩이까지 한 그림이라 아래로 내리면 웅덩이째 뜬다 → 위아래로 눌리는 **squash** 모션을 새로 만들었다.

- 재생 규칙은 우리 이모지와 **같은 코드**(`hooks/useOneShotMotion.ts` 로 뺐다): 방을 연 뒤 새로 오간 메시지만 한 번, 탭하면 다시, 동작 줄이기면 정지.
- 움직이지 않는 것: 패널 격자·추천 막대(정지 썸네일), **문구 스티커**(글자가 흔들리면 읽기 어렵다), 내린 스티커(지난 메시지).

  한 장을 빼면 실패하는 것, CRLF 로 체크아웃돼도 43건을 읽는 것을 확인했다.

132 칸 안에서 회전할 때 잘리지 않는지, 동작 줄이기 켜면 정지하는지.
