## 2. 커밋에 안 남는 판단들

**"애인에게는 공유되지 않아요"는 약속이었다.** 운동 사진을 오운완으로 바꾸며 커플 피드에
싣기로 했는데, 옛 안내 문구가 그렇게 <b>약속</b>했고 `FeedItemMapper` 가 실제로 지키고 있었다
(러닝 앱 화면에는 집 근처 경로 지도가 함께 찍힌다). 그래서 **소급하지 않는다** —
`Workout.imageShared`(V94, 기본 false)를 두고 새 기록만 true 로 저장한다. 덤으로 구버전 앱은
이 필드를 모르므로 자동으로 안전한 쪽에 선다. 안내 확인 키도 새로 뗐다(`…ShareAck.v2`) —
옛 안내에 동의한 사람은 "안 간다"에 동의한 것이라 같은 키를 쓰면 바뀐 사실을 영영 못 본다.

**피드 식단 카드 칼로리 — 병렬 세션끼리 결정이 엇갈렸다.** 9/13 에 "피드에서 칼로리를 뺀다"
(자동 노출이라 매 끼니 감시가 된다)고 정했는데, 9/14 의 카드 재구성이 그 결정을 모른 채 부제를
`끼니 · 칼로리 · 장소` 로 다시 짰다. 병합에서 **명시적으로 내려진 결정 쪽을 살렸다** — 부제
구조는 9/14 것을 쓰고 칼로리 한 줄만 뺐다. 되돌리려면 `FeedItemMapper.toItem(Meal …)` 의
`parts` 에 한 줄을 더하면 된다.

**닫기 경로를 언마운트에 건 이유.** 기록 화면을 닫는 길이 넷이다 — X · 하드웨어 백 · 모달
스와이프 · 저장 후 자동 닫기. X 핸들러에만 붙이면 셋이 빠지고 확인창을 한 벌 더 쓰게 된다.
다만 값을 effect deps 에 그냥 넣으면 **파라미터가 바뀔 때 cleanup 이 먼저 돌아 화면에
그대로 있는데 탭이 바뀐다** — 바코드 스캔이 `navigate('DietRecord', { barcodeResult })` 로
같은 인스턴스에 돌아오며 파라미터를 갈아끼우는 경로가 실제로 있다(react-navigation 은
`merge: true` 를 줄 때만 병합한다). 값을 ref 에 담아 언마운트에서만 읽는다 —
`frontend/src/hooks/useReturnToTab.ts`.

## 3. 미해결 — 이어서 할 것

### 3-1. CI 가 매일 9시간씩 빨갛다 (미수정, 이 세션에서 발견)

`./gradlew test` 가 20건 실패하길래 추적했더니 **깨끗한 `main` 에서도 똑같이 실패**했다.

- 운영 코드는 `KstClock.ZONE = Asia/Seoul` 로 "오늘"을 계산한다 — `common/time/KstClock.java:18`
- 테스트는 `LocalDate.now()`, 즉 **JVM 기본 시간대**(CI·이 컨테이너는 UTC) — 예: `CalendarFlowTest.java:83`

두 날짜가 어긋나는 **15:00~24:00 UTC(= 00:00~09:00 KST)** 동안 식단·캘린더·에너지밸런스·
리인게이지먼트 20건이 깨진다. 자정을 넘겨 다시 돌리면 710건 전부 통과한다(실측).
CI 가 모든 브랜치 push 마다 도는 워크플로라, 한국 시간 새벽~오전에 올린 커밋은 전부 빨갛게 보인다.

> 고치는 방향: 테스트가 "오늘"을 `LocalDate.now()` 가 아니라 `KstClock` 기준으로 잡으면 된다.
> 위 4개 클래스 + `MealPhotoAutoAnalysisTest`·`WorkoutFlowTest` 가 대상.
> `docs/SCHEDULER_TEST_FLAKE_2026-09-15.md` 의 스위퍼 flake 와는 **다른 건**이다.
