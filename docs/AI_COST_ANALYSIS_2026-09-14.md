# AI 원가 분석 (2026-09-14)

"AI 지출이 생각보다 많다"는 외부 진단 리포트를 코드로 검증한 결과와, 그에 따라 실행한 것·남은 것.

## 0. 한 줄 결론

**텍스트 AI는 청구서에 잡히지 않는다. 청구액은 사실상 우리 이모지(이미지 생성) 하나다.**
텍스트 키는 결제가 붙지 않은 무료 프로젝트이고(`GeminiProperties.imageApiKey` 주석 — 텍스트
프로젝트에 결제를 붙이면 무료로 돌던 호출까지 전부 과금되므로 일부러 분리했다), 결제가 붙은
프로젝트는 이미지 전용 키 하나뿐이다.

## 1. 외부 리포트 가설 채점

| 가설 | 리포트 주장 | 실제 |
|---|---|---|
| H1 thinking 토큰 | 1순위 원인 | **부분적.** 1차 모델 `gemini-2.5-flash-lite` 는 thinking 기본 OFF. 폴백 `gemini-2.5-flash` 만 기본 ON이라 503 폴백 경로에서만 샌다 |
| H2 이미지 해상도 | 원본 4000px 업로드 | **이미 두 겹으로 해결됨.** 프론트 `shrinkImage(maxSide=1024)` + 서버가 Cloudinary 에서 `w_1024,c_limit,q_auto` 로 받는다 |
| H3 주간 편지 컨텍스트 | 채팅 히스토리 통째로 | **틀림.** 프롬프트 입력은 숫자 4줄이고 `AiResultCache` 가 주 단위로 캐싱한다 |

리포트의 "지금 바로 켤 스위치" 5개 중 4개도 이미 들어가 있었다 — `responseSchema` 강제(모든 텍스트
호출), 모델 티어 분리(이미 flash-lite), 클라이언트 리사이즈, 결과 캐시. **"3.5 Flash 를 전 기능에
쓰고 있었다면 6배"는 성립하지 않는다** — 쓰고 있지 않다.

리포트의 단가표에는 정작 우리가 쓰는 2.5 계열이 빠져 있었다. 확인한 실제 단가:

| 모델 | in / out (1M) | 무료 티어 | 우리 쓰임 |
|---|---|---|---|
| 2.5 Flash-Lite | $0.10 / $0.40 | 있음 | 텍스트 1차 |
| 2.5 Flash | $0.30 / $2.50 | 있음 | 텍스트 폴백(503 시) |
| 3.1 Flash-Image (NB2) | 0.5K $0.045/장, 1K $0.067/장 | **없음** | 우리 이모지 |
| 3.1 Flash-Lite-Image | 1K $0.0336/장 | 없음 | 미사용(검토 대상) |

## 2. 진짜 원인 세 가지

### ① 세트가 17장이다
`CoupleEmojiEmotion` 이 6종 → 17종이 되면서 세트 원가가 `17 × $0.045 ≈ $0.77`. PRO 월 3세트면
커플당 월 약 $2.3. 이건 이미 인지된 상태였다(월 5 → 3 으로 인하, `Feature.java` 주석).

### ② `free-trial=true` 라 전원 PRO 판정이다
`application.yml` 의 `fitto.plan.free-trial=true` → 매출 0인데 커플당 월 $2.3 의 원가 문이 열려 있다.
커플 100쌍이면 월 $230, 1,000쌍이면 $2,300. **리포트가 권한 "원가 상한 → 쿼터 역산"은 역산할
매출이 아직 없어서 지금은 성립하지 않는다.** PRO 가격도 저장소 어디에도 확정값이 없다
(`GOOGLE_PLAY_BILLING.md` 는 가격 설정 절차만 있고 숫자가 없다). 리포트의 4,900원은 근거 없는 가정.

### ③ 전체 안전망이 이미지에는 사실상 안 걸린다
`dailyLimitTotal=1000` 은 **호출 수**를 세는데 세트 1건 = 1회로 세고 실제로는 17장이 나간다.
장 기준 방어선이 없다.

> 곁가지: `Feature.AI_TOTAL` 의 `Quota.perDay(10)` 은 죽은 값이다. 실제 상한은
> `fitto.gemini.daily-limit-per-user`(50)이고, `PlanGuard` 는 AI_TOTAL 로 불리지 않는다.
> `PRO_PLAN_DESIGN.md` 에 적힌 "AI_TOTAL(일 10회)"은 틀린 서술이다.

## 3. 이번에 한 것 (커밋 `1d9f08b`)

1. **`usageMetadata` 적재** (`V89`, `ai_usage_logs`) — 응답의 토큰을 그대로 남긴다.
   `thoughts_tokens` 를 따로 둔 이유는 output 단가로 과금되면서 답변에는 안 들어가기 때문이다.
   여기서 **기능별 원가 비중**과 **유저별 월 원가 상위 N** 이 질의 하나로 나온다.
   기록 실패는 전부 삼킨다(계측이 AI 결과를 깨뜨리지 않는다). `user_id` 는 FK 없이 두고
   `UserDataPurger` 가 명시적으로 거둔다 — 백그라운드 기록이 탈퇴와 경합하기 때문.
2. **이미지 해상도 512px 명시** — 지정하지 않으면 기본 1K 라 장당 $0.045 → $0.067.
   `aspectRatio` 는 일부러 두지 않았다(그림체 v4 는 비율 미지정으로 확정한 것이라 결과물이 바뀐다).
   `GEMINI_IMAGE_SIZE=` (빈 값)이면 필드를 안 보낸다 — 일부 모델·게이트웨이가 `imageSize` 를
   400 으로 거절한다는 보고가 있어 재배포 없이 끌 수 있게 했다.

**두 변경은 짝이다.** `imageSize` 는 조용히 무시될 수도 있는데(preview 모델에서 그런 보고가 있다),
그건 `ai_usage_logs.candidates_tokens` 가 기대보다 크게 찍히는 것으로만 드러난다. 즉 1번이 2번의
검증 수단이다.

## 4. 남은 것 — 우선순위 순

1. **배포 후 `candidates_tokens` 확인.** 512px 이 실제로 먹었는지 판정한다. 1K 기준값에 가까우면
   무시된 것이므로 모델 ID(preview 여부)를 다시 본다.
2. **이미지 전용 일일 총량 캡** — 세트가 아니라 **장** 기준. ③의 구멍.
3. **`thinkingBudget: 0`** — 폴백 경로 보험. 싸다.
4. **NB2 Lite($0.0336) 검토** — 단가 절반이지만 그림체 일관성을 v4 프롬프트로 NB2 에서 실측 확정한
   것이라 재검증 없이는 못 바꾼다. `scripts/couple-emoji-experiment/` 가 남아 있으니 6종만 돌려보면 된다.
5. **무료 체험 중 우리 이모지를 계속 열어둘지 결정** — ②. 이건 원가가 아니라 정책 판단이라
   구현으로 결정할 수 없다.
6. `PRO_PLAN_DESIGN.md` 의 "AI_TOTAL(일 10회)" 서술 정정.

식단 OCR 경로는 손댈 게 없다. 굳이 꼽으면 `FoodAnalysisService.analyze` 가 `AiResultCache` 를 안 타서
같은 `photoUrl` 재분석이 매번 새 호출이 되는데, 무료 키라 돈이 아니라 사용자 한도만 깎인다.

## 5. 필요한 외부 정보

- **Google Cloud Billing 이번 달 청구액** — 결제 프로젝트가 이미지 하나뿐이므로
  `총액 ÷ $0.045` 또는 `÷ $0.067` 로 나눠보면 실제 장당 단가와 생성 장수가 역산된다. ①③이 바로 판명난다.
- **PRO 가격 확정값** — 없으면 쿼터 역산이 불가능하다(②).

## 6. 자체호스팅 LLM

반대 입장 유지. GPU 고정비($200~300/월)가 현재 AI 지출을 넘는 동안은 역방향이고, 위 레버를 다 쓴
뒤에도 지출이 그 선을 지속적으로 넘을 때만 재검토 대상이다.
