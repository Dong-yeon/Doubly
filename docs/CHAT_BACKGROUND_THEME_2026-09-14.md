# 채팅 배경 테마 (2026-09-14)

카톡처럼 채팅방 배경을 고를 수 있게 했다. 6종 × 라이트/다크, 기기별 설정, 전부 무료.
**구현·검증 완료, main 미병합** (브랜치 `claude/theme-color-options-c55437`).

코드를 보면 알 수 있는 건 적지 않는다. 여기 남기는 건 **왜 다른 안을 버렸는지**다.

---

## 1. 앱 전체 테마에서 채팅 배경으로 좁힌 경위

처음 질문은 "하양·다크만 있는데 핑크·블루도 넣자"였다. 앱 전체 팔레트를 조사한 결과
배선은 이미 깔려 있었지만(`palettes: Record<Scheme, Palette>` + 읽는 시점에 해석하는
프록시) 아래 세 가지가 걸렸다.

1. **`ThemeMode` 가 2축을 1축에 담고 있다.** `'system' | 'light' | 'dark'` 한 축이라
   "핑크인데 시스템 다크를 따라간다"를 표현할 수 없다. 색상 축과 명도 축을 쪼개야 한다.
2. **앱 색은 장식이 아니라 의미다.** `me=Gold / partner=Green / together=Olive` 로
   누가 한 기록인지를 구분한다(43곳). 테마마다 "서로 구분되면서 새 배경 위에서 AA를
   통과하는" 3색 세트를 다시 만들어야 하고, 팔레트가 2개→6개면 그 검증이 3배다.
3. **하드코딩 hex 23개 파일.** 라이트/다크 둘일 땐 안 보이던 게 테마가 늘면
   "핑크 테마인데 여기만 초록"으로 드러난다.

여기서 범위를 **채팅방 배경만**으로 좁혔다. 앱 팔레트를 안 건드리므로 위 세 가지가
전부 해당 없고, 프론트 전용이라 EAS Update 로 배포된다.

**앱 전체 테마를 언젠가 다시 한다면** 위 1~3번이 그대로 선행 조건이다. 그리고
`colors.ts` 주석에 적힌 실패 이력(Coral/Indigo → 정당 색, Gold/Teal → 배경에 묻힘,
Forest/Cream → 배경까지 초록이라 무거움)을 먼저 읽을 것. 결론은 **"바탕은 색에서 빼고
액센트에만 쓴다"** 였다. 배경을 다시 칠하려는 안은 이미 세 번 실패했다.

## 2. "배경색"이 아니라 "한 묶음"인 이유

채팅 배경 위에는 **말풍선 없이 놓이는 것들**이 있다.

| 요소 | 원래 색 | 배경만 바꿨을 때 |
|---|---|---|
| 상대 말풍선 | `surfaceAlt` #F1F2F0 | 거의 흰색 — 연한 틴트 배경에 묻힌다 |
| 시간·"보내는 중"·"수정됨" | `textTertiary` 10px | 대비를 잃으면 바로 안 보인다 |
| 날짜 구분선 | `border` + `textTertiary` | 선이 사라지거나 튄다 |
| 우리 이모지 | 흰 배경이 딸려 와 원형 크롭 | 어두운 배경에서 흰 원이 뜬다 |

그래서 테마 하나가 `{배경, 내 말풍선, 상대 말풍선, 글자, meta, 구분선, 강조}` 를 통째로
갖는다. 배경만 따로 고르게 두면 조합이 폭발해 가독성을 보장할 수 없다 — 카톡이 배경
"테마"를 파는 것도 같은 이유로 보인다.

## 3. 개인별로 둔 이유 (커플 공용을 버림)

커플앱이니 "우리 배경"이 어울려 보이지만 버렸다.

- **비용**: 테이블 + Flyway + `CoupleEventPublisher` 실시간 반영 + `RelationRecordPurger`
  삭제 순서 갱신. 개인별은 AsyncStorage 한 줄로 끝난다(백엔드 0, 마이그레이션 0).
- **얻는 것**: "둘이 같은 배경을 본다" 하나뿐.
- **잃는 것**: 한쪽이 바꾸면 상대 화면이 예고 없이 달라진다. 좋게만 읽히지 않는다.

같은 이유로 **기기별**이다(계정 동기화 안 함). 기기를 바꾸면 다시 골라야 하는데,
그 정도 비용이면 서버를 끌어들일 값을 못 한다.

## 4. 전부 무료 (PlanGuard 안 탐)

처음엔 "기본 2개 무료 + 나머지 PRO" 로 정했다가 전부 무료로 바꿨다.

프론트 전용 구현이라 `PlanGuard` 를 지나지 않는다 — CLAUDE.md 7절의
"게이팅을 우회해 구현하면 지표에서도 사라진다"에 정확히 해당한다. **나중에 PRO 로
돌리려면** 프론트 게이팅만으로는 `FEATURE_USED`/`FEATURE_BLOCKED` 에 안 잡히므로,
테마 적용 시 PlanGuard 를 지나는 가벼운 백엔드 호출을 하나 붙여야 한다. 다만 무료→유료
전환은 반발이 크므로 사실상 되돌리기 어렵다고 보는 편이 맞다.

## 5. 덤으로 고친 기존 버그 2건

둘 다 **채팅에서만** 고쳤다. 앱 전체 팔레트는 안 건드렸다.

- **라이트 시간 글자가 AA 미달이었다.** `textTertiary` #767C76 on `background` #FAFAF9
  = 4.09. 기본 테마의 `meta` 를 #6A706A 로 두어 4.86.
- **다크 내 말풍선 위 흰 글자가 3.97 이었다.** `colors.ts` 의 `primary` 는
  "버튼 배경(어두울수록 좋다)"과 "링크 글자(밝을수록 좋다)"를 겸해 그 파일 주석대로
  둘 다 만족하는 값이 없다. **말풍선은 버튼 역할만** 하므로 채팅 팔레트에서는 낮출 수
  있다 — #2F7A55 로 5.20.

기본 테마의 "상대 말풍선 vs 배경" 1.08 만 기준(1.10) 아래인데 **현재 출시된 값 그대로**라
남겼다(검증 스크립트에서 이 한 건만 면제). 기본값을 바꾸면 기존 사용자 화면이 예고 없이
달라진다. 나머지 5종은 전부 그보다 낫다.

## 6. 검증

`npm run verify:chat-theme` — 12벌 × 5항목 = 60건. 값을 스크립트에 적어 두지 않고
`chatTheme.ts` 를 파싱한다. 둘이 어긋나면 검증이 거짓말을 하기 때문이다.
팔레트를 손댔으면 반드시 돌릴 것.

기준: 내 말풍선 위 글자 ≥ 4.5 · 상대 말풍선 글자 ≥ 4.5 · 배경 위 meta ≥ 4.5 ·
상대 말풍선 vs 배경 ≥ 1.10 · 구분선 vs 배경 ≥ 1.18.

**웹 프리뷰로 확인한 것**: 라이트/다크 양쪽에서 로즈 적용, 앱 테마를 바꿔도 채팅 배경
선택이 유지됨, 설정 견본이 현재 스킴을 따라감. **실기기 검증은 안 했다.**

## 7. 남은 것

- **실기기 확인** — 특히 우리 이모지·이미지 스티커가 각 배경 위에서 어떻게 보이는지.
  `coupleEmojiImage` 배경을 `bubbleTheirs` 로 바꿔 뒀지만 생성물 자체의 흰 테두리는
  테마별로 다르게 읽힐 수 있다.
- **"우리 사진을 배경으로"** — 커플앱으로선 제일 매력적인데, 사진마다 말풍선 가독성이
  달라져 통제가 안 된다. 오버레이(배경 위 반투명 레이어) 설계가 선행돼야 한다.
  단색/그라데이션과 달리 이건 저장소·업로드도 필요해 사실상 별건이다.
- **채팅방 안에서 바로 바꾸기** — 지금은 설정 화면에만 있다. 카톡은 채팅방 메뉴에도
  둔다. `ChatMoreMenuSheet` 에 넣는 게 자연스럽다.
