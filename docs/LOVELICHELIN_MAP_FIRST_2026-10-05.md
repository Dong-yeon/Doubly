## 2. 하단 시트 구현 방식

- **라이브러리 없이 직접**(`screens/place/MapSheet.tsx`): `react-native-gesture-handler` 2.31 + `react-native-reanimated` 4.3.1 + `react-native-worklets`.
  셋 다 이미 의존성에 있고 `App.tsx` 가 `GestureHandlerRootView` 로 감싸 있다. 바텀시트 라이브러리는 의존성 추가(+ 경우에 따라 네이티브)라 빌드가 필요해질 수 있어 피했다.
- 3단 높이: 미리보기(손잡이 + 제목 줄 + 카드 한 장 / 목록 반 장) · 절반(영역의 50%) · 전체(지도 위 검색창·칩 바로 아래).
  - 2026-10-06: 가운데 단을 **지도 60 : 목록 40**으로(사용자 요청, `SHEET_HALF_RATIO = 0.6`, 접근성 이름 '절반' → '중간'). 미리보기의 목록 몫 84 → 56px — 그대로면 375×667 에서 미리보기와 가운데가 45px 차이라 단이 갈리지 않는다.
  - 2026-10-06: 장소 목록 카드를 **네이버 지도 모바일식 한 줄**로(`PlaceListCard`). 등급 있는 곳의 16:9 커버 사진이 40% 시트를 통째로 먹었다(사용자: "사진이 너무 크다"). 이제 모든 곳이 왼쪽 글자(이름+배지 / 세부 분류·동네 / 나·상대 별점 또는 차례 안내 / 방문 / 한마디) + 오른쪽 76px 정사각 사진(없으면 자리 없음), 카드 박스 대신 구분선. 등극일·주소 전체·평균 평점은 목록에서 뺐다(상세에 있다).
  미리보기는 지도 영역의 62% 를 넘지 않는다. 375×667 실측: 전체 241 / 절반 348 / 미리보기 445(px, 화면 위 기준).
- **끄는 곳은 손잡이·시트 머리뿐**이다. 목록 본문은 늘 스크롤만 한다 — 본문까지 끌기를 받으면 목록 스크롤과 시트 끌기가 같은 손가락을 다툰다(플랫폼마다 판정이 갈린다).
  손잡이는 눌러도 한 단씩 바뀐다(웹 마우스·스크린 리더용, `accessibilityRole="adjustable"` + increment/decrement).
- 시트는 지도 위에 겹친 **형제 View** 라 시트 위의 터치는 WebView/지도로 새지 않는다 → 시트 끌기와 지도 팬·줌이 충돌하지 않는다(웹에서 확인, 네이티브는 실기기 확인 필요).
- 처음 크기를 잰 순간은 애니메이션 없이 놓는다(아니면 열 때마다 위에서 미끄러져 내려온다). 동작 줄이기면 늘 즉시.
- React Compiler 린트(`react-hooks`)가 shared value 에 `.value =` 대입을 막아 reanimated 4 의 `.get()/.set()` 을 쓴다.

## 3. 지도·핀

- 핀 SVG 는 **앱에서 한 번 그려** 네이티브(WebView)·웹(메인 문서) 지도에 같이 넘긴다(`utils/kakaoMapHtml.ts` `buildPlacePinIcons`).
  두 지도 구현이 핀을 따로 그려 왔고 실제로 웹 핀에는 등급 배지가 빠져 있었다. **아이콘 폰트 글리프는 안 쓴다**(폰트 = fingerprint 입력).
- 핀 종류: 등극(`lovelichelinGold` 원 + 흰 왕관 도형) / 다녀옴(채운 원) / 안 가봄(흰 원 + 테두리) / 검색 결과(물방울 — 우리 핀과 실루엣이 다르다). 고른 핀은 1.35배 + 맨 위.
- 핀 탭 → 시트 미리보기에 카드 한 장(이름·카테고리·나/상대 ★·최근 방문 + [다녀왔어요] [상세]). 핀은 시트에 가리지 않게 **보이는 영역 가운데**로 옮긴다(`panTo` 오프셋).
  [다녀왔어요]는 `PlaceDetail { openVisit: true }` 로 방문 폼을 펼친 채 연다.
- 지도 빈 곳 탭: 고른 핀이 있으면 고름만 푼다(지도 앱의 "빈 곳 = 닫기"), 없으면 예전처럼 "여기에 추가".
- 좌표 없는 곳: 시트 카드 아래 "위치 없음 · 지도에 표시하기" → `PlaceAdd { place, focusLocation: true }`(위치 칸으로 스크롤). 지도 위에 "지도에 없는 N곳".
- 빈 상태(0곳): 서울시청 중심, 검색창 "가보고 싶은 곳을 찾아보세요", 시트는 짧은 안내만.
- 시야 맞추기는 **처음 마커가 생겼을 때 한 번**(예전엔 "처음 그릴 때"라 목록이 늦게 오면 서울시청에 머물렀다 — 다른 지도 화면에도 같이 좋아진다). 여백은 위 덮개·아래 시트 높이(`setPadding`).

### 클러스터 기준 — 21곳 이상(20곳 초과)
- FREE 커플의 장소 한도가 20곳(`PLACE_PIN`, `backend/.../common/plan/Feature.java`)이라 **무료 커플 지도는 늘 낱개 핀 + 이름표**다.
- 그 이상(PRO)에서 서울 한 화면(축척 5~7)에 20개가 넘는 이름표가 겹치면 읽을 수 없다. `MarkerClusterer(minLevel: 5)` — 넓게 볼 때만 묶고 동네 단위(축척 4 이하)로 당기면 풀린다.
- 이름표(CustomOverlay)는 클러스터에 안 들어간다(공식 문서에 CustomOverlay 지원 언급 없음) → 묶는 동안은 **축척 4 이하에서만 이름표를 보인다**.
- 검색 임시 핀도 개수에 들어간다(우리 장소 20 + 결과 몇 개면 묶일 수 있다).

### "이 지역 장소 보기"
- 사용자가 끌거나 확대했을 때만 뜬다. 판정은 `idle` 이 아니라 그 앞의 `dragstart`(늘 사용자) · `zoom_start`(앱이 안 움직일 때)로 한다 —
  로드 직후와 시야 맞추기가 `idle` 을 두 번 내면 두 번째가 사용자 것으로 읽혀 버튼이 처음부터 떠 있었다(웹 확인).
- 누르면 그 범위로 **시트 목록만** 거른다(지도 핀은 그대로 다 보인다). 시트 머리 "이 지역 N곳" ✕ 로 푼다.

### 현재 위치 버튼 — 1.0.7 에 넣음(2026-10-06)
`expo-location` + `app.json` 위치 권한 문구 → 네이티브 빌드. 덮개 아래 오른쪽 둥근 버튼(가운데 "이 지역 장소 보기"와 안 겹친다).
누르면 권한(사용 중에만)을 묻고, 최근 2분 안 마지막 위치가 있으면 그걸, 없으면 새로 잡는다(10초에서 끊는다, `utils/myLocation.ts`).
파란 점(`MY_LOCATION_DOT_HTML`, 네이티브·웹 공용)을 놓고, 축척 5보다 넓게 보고 있었으면 5로 당긴 뒤 보이는 영역 가운데로 옮긴다.
시트가 '전체'면 미리보기로 내린다. 계속 따라가지 않는다(한 번 찍기). 위치는 서버로 보내지 않는다.
거절 → 안내 토스트, "다시 묻지 않음" → 설정 열기 다이얼로그(네이티브), 못 잡음 → 위치 서비스 확인 토스트.

## 4. 확인 결과 — 카카오 JS SDK 기본 지도 POI 탭

- `kakao.maps.Map` 이 내는 이벤트는 center_changed · zoom_start · zoom_changed · bounds_changed · click · dblclick · rightclick · mousemove · dragstart · drag · dragend · idle · tilesloaded · maptypeid_changed 뿐이다
  (카카오 지도 Web API 문서 https://apis.map.kakao.com/web/documentation/).
- **지도에 원래 그려진 가게·랜드마크(POI)를 눌렀다는 이벤트나 API 는 없다.** POI 는 타일 이미지의 일부다. `click` 은 좌표(`latLng`)만 준다.
- 4단계 후보(구현 안 함): 빈 곳 탭 좌표 반경 30~50m 를 서버 카카오 **카테고리 검색**(음식점 FD6·카페 CE7, `x,y,radius`)으로 찾아 "여기 이 가게인가요?" 후보로 보여 주기.
  `KakaoLocalClient` 에 메서드 + 엔드포인트 하나가 필요하다(서버 변경).

## 7. 남은 리스크

1. **실제 카카오 SDK 로 화면을 본 적이 없다**(웹 패널 차단). 클러스터 옵션·이름표 숨김·`containerPointFromCoords` 오프셋 계산은 문서 API 그대로지만 실기기에서 확인해야 한다.
2. 시트 끌기 ↔ 지도 팬·줌 충돌: 웹은 확인, **iOS·Android 는 실기기 확인 필요**(시트가 WebView 위의 형제 View 라 충돌하지 않을 것으로 본다 (추정)).
3. 장소 100곳 성능: FREE 한도(20) 때문에 로컬에서 100곳을 만들 수 없어 **측정 못 했다**. 마커는 `useMemo`, 갱신은 `injectJavaScript` 한 번이고 21곳부터 묶이므로 큰 문제는 없을 것으로 본다 (추정).
4. 지도 실패 판정에 "6초 안에 타일 안 그려짐"이 있어, 느린 망에서는 목록으로 물러설 수 있다(다시 들어오면 재시도).
5. 고른 핀이 클러스터 안에 있으면(넓은 축척에서 검색으로 막 담은 곳 등) 핀이 묶음에 가려 보이지 않을 수 있다.
6. 웹은 화면이 가려진 동안 크기 이벤트가 안 와 시트가 늦게 뜰 수 있다(지도는 크기와 상관없이 바로 그리게 고쳤다).
7. 카카오 지도에는 다크 타일이 없다 — 다크 모드에서도 지도는 밝고 덮개·시트만 어둡다.

## 8. 실기기 체크리스트

- [ ] 작은 화면(iPhone SE·360dp): 검색창·칩이 지도를 너무 가리지 않는지, 시트 3단이 구분되는지, 미리보기 카드 버튼이 잘리지 않는지
- [ ] 다크 모드: 덮개(검색창·칩·"지도에 없는 N곳")와 시트 대비, 밝은 지도 위 금색 핀
- [ ] 키 없음/로드 실패 폴백: 비행기 모드로 열기 → 목록, 다시 들어오면 지도 재시도
- [ ] 빈 상태(새 커플): 서울시청, "가보고 싶은 곳을 찾아보세요", 검색 → 담기 → 첫 핀
- [ ] 좌표 없는 장소: "위치 없음" → 수정 화면 위치 칸으로 스크롤 → 지도 탭으로 좌표 → 돌아오면 핀
- [ ] 시트 손잡이 끌기 ↔ 지도 팬·핀치 줌이 서로 안 먹히는지(iOS·Android)
- [ ] 핀 탭 → 핀이 시트에 안 가리는지, [다녀왔어요] → 방문 폼 펼쳐짐
- [ ] 검색 → 결과 핀/목록 → 담기 → 임시 핀이 우리 핀으로, 같은 곳 다시 → "이미 럽슐랭에 있어요", FREE 20곳 → 업그레이드 시트
- [ ] PRO 21곳 이상: 넓게 보면 묶임, 당기면 풀리며 이름표가 나타남
- [ ] 지도 끌기 → "이 지역 장소 보기" → 시트가 그 범위로, ✕ 로 해제
