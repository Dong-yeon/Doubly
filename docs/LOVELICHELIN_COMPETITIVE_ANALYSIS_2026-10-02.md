# 럽슐랭 경쟁앱 분석 & 개선 백로그 (2026-10-02)

> 근거: 경쟁앱 조사(커플맵로그·둘이서·비트윈/썸원·Beli·Corner·왓챠피디아·Letterboxd) + `docs/lovechelin-current-state.md`(같은 날 코드 분석).
> 전체 문서(표·출처): https://claude.ai/code/artifact/7e8e596e-858a-4965-9488-4b57a8e979b4

## 결론
- 나/상대 대표 평점 + 등급(tier) 구조는 이미 있고, 조사한 앱 중 2인 평점을 따로 받는 곳은 없다 → 이 구조가 차별화 지점.
- 부족한 것은 **입력 경로**: 링크로 추가 없음, 담기→평가 최소 6탭, 카카오 검색 경로 2개로 인한 중복.
- Dubly는 채팅 사용량이 가장 많다(사용자 판단) → 채팅 URL을 럽슐랭 유입 경로로 삼는다.
- Beli는 미국 중심, 국내 사용 미미. 비교 랭킹 UX는 국내 검증이 안 되어 P2.

## 결정
- "가고 싶은 곳"은 **status 컬럼을 다시 넣지 않는다**(V70 결정 유지). 방문 0건으로 파생한 필터로만 제공.
- 0.5점 단위는 보류 — 평점 테이블 4개 타입 변경 비용 대비 효과 불확실.

## 채팅 URL 칩 설계 메모
- 감지: linkify 결과 중 도메인 화이트리스트(naver.me, map.naver.com, place.map.kakao.com, kko.to, instagram.com, 콘텐츠 도메인)만.
- 해석: 서버에서 리다이렉트 추적 + OG title 추출. SSRF 방어(허용 도메인만, 사설 IP 차단), 타임아웃 3~5s.
- 매칭: 카카오 로컬 검색 후보 1~3개 → 사용자 확인. 네이버 place ID 직접 조회용 공식 API는 미확인.
- 저장: 방문 0건(가고 싶은 곳)으로 저장, 평점 묻지 않음. 이미 있으면 "이미 럽슐랭에 있어요"(현재 중복 시에도 "추가했어요" 토스트가 뜨는 문제 함께 수정).
- 피드백: 원 메시지에 "OO님이 럽슐랭에 추가함" — `CoupleEventPublisher`로 상대 화면 갱신.
- 피로도: 닫으면 그 메시지엔 재노출 안 함, 반복해서 닫으면 끄기 옵션.
- 새 테이블이 생기면 Purger 순서 갱신(CLAUDE.md 4절).
