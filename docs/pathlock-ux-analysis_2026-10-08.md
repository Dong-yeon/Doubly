# PathLock 앱 분석 + 길막기 "드래그로 벽 세우기" 도입 검토 (2026-10-08)

> **결론**: 드래그로 벽 세우기는 **도입한다.** 지금 방식(벽 모드 → 교차점 탭 → 같은 곳 다시 탭해 방향 전환 → 확정 버튼)은
> 4단계이고 방향 전환이 숨어 있다(WALL_RACE_UX_REVIEW_2026-09-30 P2-5·6). 다만 그대로 베끼지 않고 세 가지를 바꾼다.
> ① 손을 떼면 바로 놓지 않고 **판 위에 "놓을까요?" 확인을 한 번** 둔다(벽은 되돌리기 어려운 자원이고, 무르기는 상대 동의가 필요하다).
> ② 손가락에 가려지지 않게 **미리보기를 손가락 위로 띄운다.**
> ③ 놓을 수 없는 자리는 **서버가 계산해 내려주고**(`legalMoves` 와 같은 방식) 미리보기를 빨갛게 그린다.
> 서버 응답에 필드 하나가 추가되고, 나머지는 앱 JS 만 바뀐다(OTA 가능, 마이그레이션 없음).

> "드래그로 세운다"는 사용자가 직접 써 본 설명이고, 아래 화면 분석은 스토어 스크린샷(정지 화면)에서 읽은 것이다.
> 드래그 중 미리보기·스냅·확인 단계가 실제로 어떤지는 **직접 확인하지 못했다**(§6).

### 1-1. 게임 화면에서 읽히는 것 (스크린샷 2·4)

- **어두운 판 + 좌표.** 열 A–I, 행 1–9 를 판 가장자리에 적는다. 체스처럼 "D4"로 말할 수 있다.
- **벽은 주인 색으로 빛나는 막대**다(파랑/금색). 누가 어디를 막았는지 한눈에 보인다.
- **판 아래 벽 트레이**: 가로 벽 조각과 세로 벽 조각이 따로 놓여 있고, 고른 쪽에 테두리가 쳐진다. 옆에 남은 벽 개수(아이콘 + 숫자)가 있다.
  드래그는 여기서 조각을 끌어 판에 놓는 방식으로 보인다 — **방향을 트레이에서 먼저 고르므로 "같은 곳을 다시 눌러 방향 전환"이 필요 없다.**
- **갈 수 있는 칸**은 말 옆에 작은 금색 원으로 표시한다(우리 `legalMoves` 점과 같은 발상).
- **위·아래 플레이어 카드**: 위는 상대(이름·남은 벽), 아래는 나("Your turn"·남은 벽). 같은 기기 2인 모드에서는 위쪽 UI 를 180° 뒤집어 맞은편 사람이 읽게 한다.
- `···` 메뉴(접기·무르기 등으로 추정).

### 1-2. 비슷한 앱에서 확인된 드래그의 함정

- **Quoridor.II**(Xtra Game Studio): "벽은 터치한 채로 끌어서" 놓는다. 리뷰에 **"원하는 자리에 벽을 놓기가 거의 불가능"** 이라는 불만이 있다.
- **Quoridor Arena**: 드래그 앤 드롭과 **탭을 둘 다** 지원하고, 버튼·핀치로 확대할 수 있다.
- **logic-puzzles-online 의 Pathlock**(이름만 같은 웹 게임): 벽 자리를 탭하면 놓인다(드래그 아님). 겹치거나 길을 막는 벽은 거절한다.

→ 드래그는 **스냅이 넉넉하고 손가락에 가려지지 않아야** 성공한다. 작은 판에서 정밀하게 끌게 만들면 Quoridor.II 처럼 된다. **탭 대안도 남겨야 한다.**

## 2. 지금 길막기의 벽 놓기 — 무엇이 불편한가

`WallRaceScreen.tsx`(origin/main 4901eccd 기준):

1. `벽 놓기` 버튼으로 모드 전환(`wallMode`, :141, :590)
2. 교차점 8×8 중 하나를 탭 → 미리보기(`pending`, :477-501). 기본은 가로
3. 세로로 놓으려면 **같은 자리를 한 번 더** 탭 — 이 동작은 화면 어디에도 보이지 않는다(9/30 리뷰 P2-6)
4. `가로로 놓기`/`세로로 놓기` 버튼으로 확정(`confirmWall`, :255)

남은 문제(9/30 리뷰에서 미해결):
- **겹치는 자리도 미리보기가 똑같이 뜨고**, 확정 뒤 서버 거절 토스트로 안다(P1-4).
- **길을 막는 자리도 확정한 뒤에야 거절된다**(서버 BFS — 의도된 설계였다).
- 터치 목표가 작다 — 360dp 폰에서 교차점 슬롯 ≈36px(P2-5).

## 3. 드래그를 넣을 때의 설계

### 3-1. 흐름

```
[판 아래 트레이]  ▬ 가로 벽   ┃ 세로 벽   · 남은 벽 7
        │ 꾹 누르고 끈다
        ▼
판 위에서 손가락 위 ~48px 에 벽 미리보기가 따라온다
  - 가장 가까운 교차점에 스냅(교차점 사이 절반 거리 안이면 붙는다)
  - 놓을 수 있으면 내 색, 못 놓으면 빨강 + 이유 한 줄("이미 벽이 있어요" / "길을 완전히 막아요")
  - 판 밖으로 끌고 나가면 취소
        │ 손을 뗀다
        ▼
판 위에 벽이 "놓을까요?" 상태로 남는다 — 벽 옆에 [✓] [✕]
  - ✓ → 서버 전송(지금의 confirmWall 그대로)
  - ✕ 또는 트레이로 다시 끌면 취소
  - 미리보기를 끌어서 다른 자리로 옮길 수 있다
```

**탭도 남긴다**: 트레이 조각을 탭하면 지금의 벽 모드(교차점 탭 → 확인)로 들어간다. 정밀 조작이 어려운 사람과 접근성(스크린리더)용이다.

### 3-2. "손을 떼면 바로 놓기"를 하지 않는 이유

PathLock 이 놓자마자 설치하는지는 확인하지 못했다(§6). 우리는 확인을 한 번 둔다.
- 벽은 판당 10개뿐인 되돌리기 어려운 자원이다. 우리 무르기는 **상대 동의가 필요하고, 상대가 몇 시간 뒤에 볼 수도 있다**(비동기 게임).
- 손을 뗄 때 손가락이 1~2mm 미끄러지면 스냅이 옆 칸으로 넘어간다. 작은 판일수록 그렇다.
- 확인 버튼이 판 위 벽 바로 옆에 붙으므로 지금보다 단계는 오히려 줄어든다(4단계 → 끌기·✓ 2단계).

### 3-3. 놓을 수 없는 자리를 미리 알기 — 규칙은 서버에 한 벌만

- **겹침**은 벽 문자열 몇 칸을 보는 검사라 앱에서 해도 되지만, **길 막힘(BFS)**까지 앱에 두면 Java·TS 두 벌이 된다(설계 §10-3 원칙).
- 그래서 `legalMoves` 처럼 **서버가 계산해 내려준다**: `WallRaceGameResponse.illegalWalls` — 지금 내 차례에 놓을 수 없는 (교차점, 방향) 목록과 이유 코드(OVERLAP / BLOCKS_PATH).
  128가지(64자리×2방향)를 81칸 판에서 BFS 로 확인하므로 응답마다 계산해도 비용이 작다.
- 앱은 목록에 있으면 빨강으로 그리고 ✓ 를 막는다. 서버 거절은 최후 방어선으로 남는다.

### 3-4. 손가락·화면 문제 (이미 겪은 것들)

| 문제 | 대책 | 근거 |
|---|---|---|
| 판 위에서 오른쪽으로 끌면 **화면이 닫힌다**(전역 `fullScreenGestureEnabled`) | 길막기 화면도 `gestureEnabled: false` — 캐치마인드·연쇄 퍼즐과 같은 조치 | `HomeStackNavigator.tsx:76-110` |
| 위아래로 끌면 **목록이 같이 스크롤**된다(화면이 `FlatList`) | 끄는 동안 `scrollEnabled=false` — 캐치마인드 캔버스와 같은 처리 | `WallRaceScreen.tsx:733`, `CatchMindScreen` drawing 잠금 |
| 손가락이 미리보기를 가린다 | 미리보기를 터치점 위로 띄우고, 스냅된 교차점을 확대 원으로 표시 | Quoridor.II 리뷰 |
| 작은 판(360dp, 칸 ≈29px) | 스냅 반경을 교차점 간격의 절반으로 넉넉하게. 끄는 동안 판을 키우지는 않는다(판이 움직이면 조준이 어긋난다) | 9/30 리뷰 P2-5 |

### 3-5. 구현 범위

- **앱**: `react-native-gesture-handler`·`reanimated` 는 이미 의존성에 있다(`package.json`). PanResponder 로도 된다(연쇄 퍼즐이 그렇게 한다). 둘 다 JS 라 **OTA 로 나간다.**
- **서버**: `WallRaceGameResponse` 에 `illegalWalls` 필드 하나. 마이그레이션은 없다. 예전 앱은 이 필드를 무시한다.
- 대략 앱 하루 + 서버 반나절 규모(추정). 위험 요소는 제스처 충돌(§3-4)이고, 실기기로 확인해야 한다.

## 4. PathLock 에서 더 가져올 만한 것 / 가져오지 않을 것

| PathLock | 우리 | 판단 |
|---|---|---|
| 판 가장자리 좌표 A–I / 1–9 | 없음 | **가져온다** — 둘이 "D4 막았어"라고 채팅으로 말할 수 있다. 판을 돌리지 않는 이유(§10-4)와도 맞는다 |
| 벽을 주인 색으로 칠함 | 벽 주인을 저장하지 않음(V97 주석) | **보류** — 기보(`race_moves`)를 재생하면 주인을 알 수 있어 마이그레이션 없이도 된다. 드래그 다음 단계 |
| 위·아래 플레이어 카드(이름·남은 벽·차례) | 차례 칩 + 남은 벽이 흩어져 있음 | 가져온다(드래그 트레이와 한 줄로 합침) |
| 같은 기기 2인(pass & play) | 없음 | **고려할 만하다** — 커플이 같이 있을 때 폰 하나로. 서버 판이 아니라 앱 안에서만 도는 판이라 기록·전적에는 남기지 않는다. 별도 결정 |
| 봇 4단계 | 없음 | 혼자 연습용으로 고려(연쇄 퍼즐의 혼자 연습과 같은 자리). 별도 결정 |
| 랭크·ELO·주간 리그·다이아·일일 미션 | — | **가져오지 않는다** — 둘만 하는 앱이고, 승패보다 "같이 한 판"이 남는 것이 원칙(허브 각주) |

## 6. 확인하지 못한 것

- PathLock 의 실제 드래그 동작: 손을 떼면 바로 놓이는지, 확인 단계가 있는지, 스냅 반경, 미리보기 위치, 놓을 수 없는 자리를 미리 보여 주는지. 스토어 문구와 정지 스크린샷에는 나오지 않는다. 직접 설치해 보면 §3-1 을 다듬을 수 있다.
- 스크린샷의 트레이가 "끌어 오는 출처"인지 "방향 선택 토글"인지 — 정지 화면이라 둘 다 가능하다.
