# 채팅 입력바를 카톡 비율로 (2026-10-01)

> 대상: `frontend/src/screens/chat/ChatRoomScreen.tsx`(입력바·패널 교대), `components/chat/StickerPanel.tsx`(패널 높이).
> 선행: `CHAT_UX_REVIEW_2026-10-01.md`(같은 날, I1·I2·I3·R1·D2 구현, K2 미해결).

## 1. 실측 — 카톡 채팅방 캡처 (iPhone 15)

캡처 파일은 **1186×2576px** 이다(@3x 원본 1179 에서 약 0.6% 늘어난 사본). 그래서 **3.018 px/pt** 로 나눴다.
측정은 픽셀 열·행을 훑어 색 경계를 찾은 값이다(눈대중이 아님). 오차 ±1px ≈ ±0.3pt.

| 항목 | px | pt |
| --- | --- | --- |
| 입력 알약 높이 (y 2356→2484) | 128 | **42.4** |
| 알약 좌우 화면 여백 (x 26 / 1158) | 26·28 | **8.6~9.3** |
| "+" 원 지름 (x 49→134) | 85 | **28** |
| 알약 왼끝 → "+" 중심 | 65 | **21.6** |
| 오른쪽 원(AI) 지름 · 알약 오른끝 → 중심 | 86 · 65 | **28 · 21.5** |
| 이모티콘 중심 ↔ 오른쪽 원 중심 | 108 | **36** |

## 2. Dubly 값 — 어디를 맞추고 어디서 벗어났나

| 항목 | 카톡 | Dubly | 비고 |
| --- | --- | --- | --- |
| 보이는 알약 높이 | 42.4 | **42** | 버튼 칸(터치) 안쪽에 깐 배경 |
| 버튼 터치 영역 | (작음) | **44pt iOS / 48dp Android** | 요구사항. 칸 크기 자체로 지킨다(hitSlop 아님) |
| 바 전체 높이(인셋 제외) | — | **60** (iOS 8+44+8, Android 6+48+6) | 09-18 의 60 을 그대로 유지 |
| 알약 → 키보드·패널 | 9 | **9** | 바 여백 = 9 − (칸−알약)/2 |
| 좌우 화면 여백 | ≈9 | **8** | 예전 16. 버튼이 알약 안쪽으로 8 더 들어가 화면 끝 → "+" 원은 여전히 16 — 모서리 곡률 잘림(08-31) 조건 유지 |
| "+"·전송 원 | 28 | **28** | 아이콘 20·18 |
| 알약 끝 → 첫·끝 버튼 중심 | 21.5 | **22** | 칸 44 의 절반 |
| 이모티콘 ↔ 전송 중심 | 36 | **44** (Android 48) | **벗어남**: 두 칸 모두 터치 하한이라 겹칠 수 없다 |
| 글자 시작 | 43.7 | **46** (iOS) | 칸 44 + 2 |
| 입력 글자 | (미측) | 14 (웹 16) | 오늘 I1 결정 유지 |
| 최대 줄 수 | — | **5줄 후 칸 안 스크롤** | lineHeight 20 고정 → maxHeight iOS 124 / Android 128 |

**터치 영역을 hitSlop 대신 칸 크기로 잡은 이유**: 안드로이드는 부모 경계 밖으로 나간 hitSlop 이 터치를 못 받는다
(CHAT_UX_REVIEW §1-4). 알약을 버튼 칸보다 작은 **절대 위치 배경**으로 깔면 "42 로 보이고 44/48 로 눌린다"가
구조로 보장된다. 줄이 늘면 행이 커지고 배경도 따라 늘어난다.

**색**: 카톡 노랑·아이콘은 쓰지 않았다. 알약 = `chat.inputField`, "+" 원 = `chat.inputBar` 채움 + `inputIcon`
(verify:chat-theme 가 이미 검증한 "아이콘 vs 입력바" 쌍), 이모티콘 아이콘 = `inputPlaceholder`(칸 위 4.5 이상 검증),
전송 = `colors.primary`. 테마 파일·검증 스크립트는 바꾸지 않았다(220건 그대로 통과).

## 3. 구조 변화

- **이모티콘 버튼이 늘 알약 안에 있다.** 예전엔 빈 입력일 때만 전송 자리를 빌려 떴다. 쓰다가 이모티콘으로 넘어가고
  다시 키보드로 돌아오는 왕복을 버튼 하나로 하려면 상주해야 한다. 순서: `[+] 입력 [이모티콘] [전송(글자 있을 때)]`.
- **이모티콘을 다시 누르면 키보드로 돌아간다**(카톡과 같다, 아이콘이 `keyboard-outline` 으로 바뀜). 09-11 의
  "닫을 때 키보드를 올리지 않는다"를 **이모티콘에 한해** 뒤집었다. "+" 패널은 예전대로 접기만 한다.
- **패널 높이 = 키보드 높이 그대로.** 09-17·09-22 의 264~320 클램프 + `maxHeight`(작은 팩에서 빈 칸을 줄이려던 것)를
  걷었다. 클램프 밖 키보드(낮은 233dp 기기·큰 Android 키보드)에서 전환마다 입력바가 그 차이만큼 튀었고,
  작은 팩으로 넘기면 패널이 줄어 대화가 내려앉았다. **대가: 작은 팩은 아래가 빈다**(카톡도 같다).
  바닥 180 은 하드웨어 키보드처럼 높이가 비정상일 때만 걸린다.
- **K2 해결**: iOS 키보드 높이는 홈 인디케이터 띠(34)를 포함하는데 패널은 그 띠 위에 놓인다 → iOS 만 `insets.bottom` 을 뺀다.
- **K3 해결 + 교대 타이밍**: 키보드 ↔ 패널을 같은 순간에 바꾼다.
  - iOS: KAV 가 `keyboardWillShow/WillHide` 에서 여백을 바꾸므로 패널도 그 이벤트에서 바꾼다(한 렌더에 묶임).
    키보드가 떠 있을 때 이모티콘을 누르면 `WillHide` 에서 패널을 연다.
  - Android: 패널이 열려 있으면 키보드 여백을 0 으로 본다(DidHide 지연과 겹치지 않게). 키보드로 돌아갈 때는 `DidShow` 까지 패널을 남긴다.
  - 이벤트가 안 오면(하드웨어 키보드) 600ms 뒤 그냥 바꾼다. 웹은 기다리지 않는다.
- **붙여넣기**: 막는 코드는 없었다(`contextMenuHidden`·`onPaste`·`editable` 조작 0곳). 입력창이 스와이프 제스처에
  덮여 메뉴가 씹히던 것은 오늘 `1f9b8bd` 에서 이미 고쳤다. 그 커밋이 **말풍선 "복사하기"**(TEXT 메시지, 길게 누르기 시트)도 넣었다.

## 4. 빌드 vs 업데이트

아이콘 서브셋에 `keyboard-outline` 이 늘어 `assets/fonts/MaterialCommunityIcons.ttf` 가 바뀌었다. 이 폰트는 `require()` 로
번들에 실리는 JS 에셋이고 fingerprint 입력이 아니다 — `expo-updates fingerprint:generate` 해시가 변경 전후 같다
(Android `f7081291…`, iOS `f21afb05…`). **EAS Update 로 배포 가능.** 같이 생긴 글리프맵 변화(`details` 추가·`tray` 제거)는
스캐너가 소스 문자열을 다시 읽은 결과다(`details` 는 CHAT_UX_REVIEW §6 이 미뤄 둔 그것).

## 5. 확인하지 못한 것 — 실기기에서 볼 것

화면으로 보지 못했다(웹 프리뷰 로그인이 운영 Railway). typecheck·verify:chat-theme·verify:nested-buttons·build:web 통과,
바꾼 두 파일 lint 새 경고 0.

1. iPhone: 키보드 열린 채 이모티콘 → 패널, 다시 이모티콘 → 키보드. **입력바가 한 번도 위아래로 움직이지 않아야** 한다.
   움직이면 KAV 의 여백 갱신(비동기 측정 후 setState)과 패널 렌더가 다른 프레임에 떨어진 것 — 그때는 `react-native-keyboard-controller`(빌드) 쪽.
2. Android 같은 왕복. 그리고 패널 열린 채 입력칸 탭 → 키보드가 패널 자리로 올라오는가.
3. 5줄까지 늘고 6줄째부터 칸 안에서 스크롤되는가(iOS·Android 둘 다). 버튼이 바닥 줄에 붙어 있는가.
4. 빈 입력 상태에서 오른쪽 끝이 이모티콘이고, 글자를 치면 그 오른쪽에 전송이 나타나는가.
5. 작은 팩(예: 23장)에서 패널 아래 빈 칸이 거슬리는가 — 거슬리면 높이는 두고 격자를 세로 가운데로 두는 게 다음 수.
6. 인디고·기본 테마에서 "+" 원이 알약 위에 보이는가(원 = 바 색).
