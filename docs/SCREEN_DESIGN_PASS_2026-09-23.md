# 화면별 디자인 점검 — "AI 가 만든 것 같다"를 걷어내기 (2026-09-23~)

> 화면 하나씩 본다. 각 절은 ① 관찰(근거 파일:라인) ② 왜 그렇게 보이는지 ③ 방향 ④ 결정.
> 색조·명도 문제는 `UI_UX_COMPETITIVE_REVIEW_2026-09-22.md` 에서 끝냈다(대표 그린 확정 · 채움 토큰 · primaryFill). 여기서는 다루지 않는다.
> 확정된 구조 결정(홈 스크롤 없음·칩 3개·탭 구조·배경 길게 누르기)은 건드리지 않는다.

## 0. 판정 기준 — 무엇이 "AI 스럽게" 보이는가

"AI 스럽다"는 인상이지만 원인은 반복해서 나타나는 몇 가지 패턴이고, 패턴은 셀 수 있다.
LLM 이 UI 를 만들 때 기본값으로 고르는 것들이라 사람이 디자인한 앱에서는 드물다.

| # | 패턴 | 왜 그렇게 읽히나 |
| --- | --- | --- |
| P1 | **모든 컨테이너가 알약·둥근 카드 + 헤어라인** | 컴포넌트 키트를 그대로 깔아 놓은 모양. 화면마다 고유한 형태가 없다 |
| P2 | **이모지를 아이콘 자리에** | 아이콘 자산이 없을 때의 대체재. 사람이 그린 앱은 이모지를 콘텐츠에만 쓴다 |
| P3 | **라벨 → 큰 숫자 → 캡션의 3단 스탯 카드** | 대시보드 템플릿. 숫자가 콘텐츠가 아니라 위젯으로 보인다 |
| P4 | **좌우 대칭 2열, 같은 행이 같은 높이** | 비교표 템플릿. 사람 관계를 표로 그린다 |
| P5 | **원 안 아이콘 + 아래 라벨의 바로가기 줄** | 런처 템플릿. 앱 안에 또 홈 화면을 만든다 |
| P6 | **기본 아이콘 세트(Material) 만, 커스텀 형태 0** | 모든 앱이 같은 아이콘을 쓴다 |
| P7 | **설명문이 화면에 상주** ("눌러서 …하기", "아직 …가 없어요") | 안내가 UI 를 대신한다. 사람이 만든 앱은 형태로 말하고 문장은 비운다 |
| P8 | **전부 가운데 정렬** | 정렬 기준이 콘텐츠가 아니라 캔버스 |
| P9 | **회색 알약(surfaceAlt)이 상단 컨트롤의 기본 옷** | 주 액션과 보조 액션의 옷이 같다 |
| P10 | **사진·그림 없이 텍스트와 선만** | 채울 것이 없을 때의 결과 |
| P11 | **텍스트 기호로 상태 표시** ("✓", "—", "›") | 아이콘 대신 글자. 확대 시 깨지고 정렬이 안 맞는다 |

이 기준으로 화면마다 어느 패턴이 몇 군데 있는지 센다. 없애는 순서는 **면적이 큰 것부터**다 —
작은 기호 하나보다 화면의 절반을 차지하는 템플릿이 인상을 만든다.

## 1. 홈 (HomeScreen + CoupleHero + QuickActions)

캡처: `store/shots/05-streak.png` (Android · 라이트 · 배경 사진 없음).

### 1-1. 가장 큰 발견 — 사진이 주인공인데 사진이 안 보인다

설계 의도는 "배경 사진 위의 우리 화면"이다(`HomeScreen.tsx:2`). 그런데 사진 위에 깔리는
스크림이 **흰색 84 → 92 → 97 %** 다(`HomeScreen.tsx:99-105`). 사진이 있어도 위 1/6 만 희미하게
비치고 나머지는 흰 화면이다. 캡처는 사진이 없는 경우인데, 사진이 있어도 인상은 거의 같다.

왜 이렇게 됐나: **글자를 사진 전면에 놓았기 때문**이다. D+ 숫자·두 열·최근 기록이 화면
전체에 퍼져 있어, 어느 사진이 와도 AA 를 맞추려면 사진을 지워야 했다(주석의 "0.84 아래로
내리지 말 것"이 그 계산이다). 비트윈·Locket 이 사진을 그대로 보여줄 수 있는 이유는
글자를 **사진 아래 한 구역**(하단 패널 또는 짧은 하단 그라데이션)에만 두기 때문이다.

즉 홈의 "AI 스러움"은 개별 위젯이 아니라 **사진과 글자가 자리를 나누지 않은 구조**에서
나온다. 이걸 두고 위젯만 다듬으면 흰 화면 위 위젯이 조금 예뻐질 뿐이다.

### 1-4. 방향 — 셋 중 하나

확정 결정(스크롤 없음·칩 3개·배경 길게 누르기)은 세 안 모두 지킨다.

**A. 사진이 주인공 (비트윈형)** — 권장
- 사진을 **지우지 않는다**. 스크림은 하단 1/3 에만 짧은 그라데이션(투명 → 배경색).
- 글자는 **하단 패널** 한 구역에 모은다: 첫 줄 "이름 · 이름 D+474", 둘째 줄 오늘(운동·식단
  아이콘 4개, 채움/비움으로 상태), 셋째 줄 바로가기. 2열 비교표는 없앤다 — 사람 구분은
  아바타 두 개 + 이름으로 충분하다.
- 상단 바는 사진 위에 **아이콘만**(무드·배경·프로필), 회색 알약 없이. 무드는 이모지 대신
  현재 무드 이미지가 있으면 그것, 없으면 무드 아이콘.
- 사진이 없을 때는 계란 캐릭터 둘이 앉아 있는 기본 벽지(스티커 자산 재사용) + "첫 사진
  넣기" 한 줄. 흰 그라데이션은 없앤다.
- 비용: `CoupleHero` 재작성(중), 스크림·벽지 교체(소), 상단 바(소). 백엔드 변경 없음.

**B. 캐릭터가 주인공 (썸원형)**
- 화면 가운데 더비·블리 두 캐릭터, 무드가 표정으로. D+ 는 캐릭터 아래 작은 태그.
- 사진 기능은 유지하되 배경이 아니라 하단 카드로 내려간다.
- 비용: 캐릭터 상태별 일러스트(무드 × 2)가 필요 — 지금 자산으로는 부족. 아이콘 방향 문서의
  캐릭터 확정(§8 미결)이 선행돼야 한다. 지금은 못 한다.

**C. 구조 유지, 패턴만 제거**
- 스탯 카드를 한 줄로("D+474 · 2025.6.1부터"), 2열을 유지하되 빈 자리 예약 제거, 이모지·
  텍스트 기호·회색 알약 제거, 11px 토큰화.
- 비용 소. 하지만 1-1 의 구조(사진을 지우는 스크림)가 그대로 남아 "흰 화면 위 위젯"에서
  벗어나지 못한다.

**권장은 A.** 설계 의도("배경 사진 위의 우리 화면")를 실제로 실현하는 유일한 안이고, 세 안
중 유일하게 P10(그림 없음)을 사진으로 푼다. B 는 자산이 준비되면 A 위에 얹을 수 있다
(사진 없을 때의 기본 벽지가 B 의 자리다).

### 2-3. 상용 앱의 설정 문법 (비교 기준)

- **카드가 아니라 묶음(group)**: iOS 설정·카카오톡·토스·당근 전부 그림자 없는 묶음이다. iOS 는
  살짝 다른 명도의 사각 블록(inset grouped), 카카오톡·토스는 아예 바탕 위에 행만 놓고
  머리말로 나눈다. 묶음마다 그림자를 주는 앱은 없다 — 설정은 "떠 있는 카드"가 아니라
  "목록"이다.
- **행은 한 줄**: 제목 + (오른쪽 값 또는 스위치 또는 셰브론). 설명은 **묶음 아래 각주 한 번**
  (iOS footer) 이거나, 법적으로 필요한 행(마케팅 수신)에만 붙인다. 행마다 두 줄이면 화면이
  안내문이 된다.
- **머리말 위계가 낮다**: 작은 회색 대문자/캡션 — 지금의 `sectionLabel` 은 이 기준에 맞다.
- **프로필은 행이다**: 아바타 48~56 왼쪽, 이름·부제, 셰브론 → 편집 화면. 상시 노출 "수정"
  버튼은 없다.
- **행 제목 굵기는 보통(400~500)**: 설정 행이 전부 600 이면 어디가 강조인지 없다. 지금
  `rowTitle` 17/600 이다.

### 2-4. 방향

이 두 화면은 홈처럼 구조를 다시 짤 일은 아니다. **묶음 목록 컴포넌트 하나를 만들고 두 화면을
그것으로 다시 그리는** 일이다. 그 컴포넌트가 이후 화면의 목록 문법이 된다.

**`SettingsGroup` / `SettingsRow` (신규 공용 컴포넌트)**
- Group: 머리말(캡션·회색) + 표면색 블록(radius.lg, 그림자 없음, 헤어라인 없음 — 바탕이 §2 의
  명도 하향을 받으면 블록이 저절로 뜬다; 그 전까지는 헤어라인만) + 선택적 각주(footer 캡션).
- Row: 왼쪽 제목(body 또는 subtitle, **500**), 오른쪽 슬롯 하나 — `value`(캡션 회색) ·
  `switch` · `chevron`(아이콘 `chevron-right`, 텍스트 아님). 높이 52. 행 사이 헤어라인은 블록
  안쪽 왼쪽 패딩부터.
- 설명은 Row 의 prop 이 아니라 Group 의 `footer` 다 — "행마다 설명"을 구조적으로 막는다.
  법적 문구(마케팅 수신, 맞춤법 온디바이스 고지)만 Row `note` 로 허용한다.

**설정 화면 (Settings) 재배치**
1. 알림 — 푸시 알림(스위치) · 알림 종류 › · 식사 알림 › (하위 화면 둘로 분리. 각각 지금의
   카테고리 스위치·시간 칩을 그대로 옮긴다) · 마케팅 정보 수신(스위치, note 유지)
2. 화면 — 테마(칩 3) · 액센트(칩 3). 머리말 문장은 각주로 한 번.
3. 기능 — 사진으로 칼로리 채우기(스위치) · 맞춤법 제안(스위치, note 유지)
4. 계정 — 플랜 › (값 FREE/PRO) · 비밀번호 변경 ›
5. 정보 — 이용약관 › (값 v) · 개인정보처리방침 › (값 v) · 오픈소스 라이선스 › · 문의 ›
6. 하단 버전 (그대로)
   → 카드 10 → 묶음 5, 상주 설명문 15 → 각주 3 + note 2.

**MY 화면 재배치**
1. 프로필 행 — 아바타 56 · 이름 · 이메일 · › → 편집은 시트(이름·사진). "이름 수정" 버튼 제거.
2. 신체 정보 행 — 값 한 줄("170cm · 1990.01.01 · 남성") · › ; 미등록이면 값 자리에 "등록"
   한 단어(세 번 "미등록"을 나열하지 않는다). 편집은 시트. 설명 문장은 각주 한 번.
3. 레벨 카드 — 유지(이건 콘텐츠다).
4. 묶음: 지난 기록 › · 플랜 › · 스티커 상점 › · 설정 ›
5. 묶음(위험): 커플 연결 끊기 · 로그아웃 · 회원 탈퇴 — 빨간 글자, 셰브론 없음
6. 슬로건 footer 유지.

**건드리지 않는 것**: 두 화면의 항목 자체(무엇이 어디 있는지의 큰 틀), 트레이너 섹션(비활성),
플랜 중복 노출(문서화된 의도), Switch 색(`primaryFill`, 오늘 로컬 세션이 정함).

비용: 컴포넌트 둘(소) + 설정 하위 화면 둘(소~중, 기존 블록 이동) + MY 시트 둘(중). 백엔드 없음.

### 6-3. 방향

구조 결정은 유지하고 **고정 영역을 줄이고 카드를 접는** 일이다. 비용 중.

1. **화면 제목 + 헤더 아이콘**: "럽바디" 제목(우리 탭과 같은 화면 안 헤더) 오른쪽에 통계·캘린더
   아이콘. 바로가기 칩 줄이 사라진다.
2. **AI 버튼 둘은 목록 안으로**(스크롤). 고정 영역은 제목 + 체크인 카드뿐.
3. **체크인 카드**: 버튼을 `leftIcon`(check / camera) + "운동 완료" / "오운완 사진"으로, 안내 문장
   제거(버튼 둘이 곧 안내). 완료 상태 "챙겼어요 💪" → 아이콘 + "챙겼어요".
4. **영양 카드**: 막대·링 색을 `accent` → `primaryFill`(내 지표, 소유자 의미 없음). 미등록 안내
   두 줄 → 한 줄 + "등록 ›"(MY 신체 정보 시트로). 10px → `micro`.
5. **물·단식 → 한 줄 타일 둘**: 물은 `NumberStepper`(이미 있음)로 "물 750 / 2000ml [−][+]", 단식은
   "간헐적 단식 · 시작하기 ›" 한 줄(진행 중이면 경과 시간). 카드 하나가 절반으로 준다.
6. **커플 목표 카드**: `together` 색은 뜻이 맞으니 유지. 프롬프트 "정해볼까요? 설정하기 ›" →
   "커플 식단 목표 · 설정" 행 + 셰브론 아이콘.
7. **하단 버튼**: "＋ 식단 기록하기" → `leftIcon` plus. 물 버튼 "＋250ml" → 스테퍼로 흡수.
8. **운동 홈**: 점 색 범례 문장 제거(주간 스트립 점에 이니셜 없이 색만 두는 건 §3-2 문제라,
   범례 대신 오늘 셀 옆에 "나·상대" 작은 라벨 한 번), "✨ 맞춤 운동" → 아이콘. 나머지 구조 유지.

**하지 않는 것**: 세그먼트 토글, 체크인 위치, 식단 진입 동선, 모달 셋의 내용, 트래커 기능 자체.

알약 모양만 세면 제목 줄 2 + 모드 2 + 카테고리 9 = 첫 카드 전에 **13개**. 그리고 AI 알약 둘은
9/23 오전에 럽바디에서 "목록 안으로" 내린 것과 같은 컴포넌트다 — 탭마다 자리가 다르면 그것이
AI 스럽다.

**상세**: 카드 세 장이 세로로 선다 — 정보 카드(이름 `title` 크기 + 연필·휴지통 아이콘, 칩 줄, 주소,
통계, 지도 140, 구분선, "럽슐랭 평가" + ⓘ + 배지, "나 ★★★★☆ / 상대 아직 평가 전" + 고스트
"수정"), "다녀왔어요" 버튼(누르면 폼 카드: ★ 32px `accent`, 별점 안내 문장, 날짜, "사진 추가하기"
글자만 있는 16:9 상자, 메모, 띄어쓰기 바, 식단 체크 + 끼니 칩(`accentSoft/accent`) + 안내 문장,
취소·저장), "방문 기록" 제목 + "길게 눌러 삭제 · 사진은 탭해서 크게 보기" + 방문 카드(날짜·이름,
★ `togetherText`, 사진 160, 메모, "🍽 식단에도 기록됨" `primary`). 화면 제목(내비 헤더)이 이미
장소 이름인데 정보 카드가 같은 이름을 `title` 크기로 한 번 더 쓴다.

**추가**: 폼 레이블이 문장이다 — "카카오 장소 검색 — 이름·주소·위치가 자동 입력돼요", "위치 확인
(선택) — 지도를 탭해 직접 고를 수도 있어요", 지도 아래 상주 상태문 "아직 위치를 선택하지

### 7-3. 방향

구조 결정은 유지하고 **상단을 한 줄 줄이고 옷을 갈라입히는** 일이다. 비용 소~중.

1. **제목 줄은 제목 + 아이콘만**: "럽슐랭" + 지도 토글. AI 알약 둘은 **목록 머리(스크롤)** 로 —
   럽바디 §6-4 와 같은 자리, 같은 컴포넌트. 제목 줄이 두 줄로 접히는 일이 사라진다.
2. **검색 필드도 카테고리 칩과 같은 기준**(`CATEGORY_FILTER_MIN_PLACES`)으로 — 8곳 미만이면 목록이
   한 화면에 들어오니 검색이 필요 없다. 상수 하나를 둘이 공유한다.
3. **모드 세그먼트를 칩과 구분**: 칩 둘 `fill` 대신 **밑줄 탭**(선택 = `textPrimary` 글자 + 2px
   밑줄, 비선택 = `textSecondary`) 한 줄. 알약이 둘 줄고, 선택 칩(필터)과 모드(내비게이션)의
   옷이 갈린다. 콘텐츠 모드의 거취(§3-5)와 무관 — 모드가 하나가 되면 줄 자체가 사라진다.
4. **이모지 → 아이콘/글자**: 범례 `crown` 아이콘, "여행에 담김" 알약에 `airplane` 12px, 하단 버튼
   `leftIcon` plus, 추천 카드의 "💡" 제거(문장만), "추가했어요 ✓" → "추가했어요", "🍽 식단에도
   기록됨" → `silverware-fork-knife` 12px + 글자(`textSecondary`).
5. **지도 안내문**: 상주 세 문장 → 핀이 0일 때만 한 줄("빈 곳을 탭해 장소를 추가해보세요"),
   그 외엔 없음. 좌표를 고른 상태는 이미 하단 바가 말한다.
6. **상세 정보 카드**: 이름 줄을 빼고(내비 헤더가 제목) 연필·휴지통은 **헤더 오른쪽**으로. 카드는
   칩 줄부터 시작한다. 방문 카드 ★ → `me`/`partner`(`visitedByName` 이 누구인지 이미 안다 —
   `isMine` 이 응답에 있는지 확인, 없으면 이름 비교). 입력 ★ `accent` → `primaryFill`, 끼니 칩
   `accentSoft/accent` → `primaryBg/primaryFill`(럽바디 마법사 칩과 같은 값). "사진 추가하기" →
   `image-plus` 아이콘 + 글자. 별점 안내 두 갈래 문장은 유지하되 **별점을 고른 뒤에만**(0이면
   비운다 — "별점 없이 기록만 남길 수도 있어요"는 빈 별 다섯 개가 이미 말한다). "길게 눌러 삭제 ·
   사진은 탭해서 크게 보기"는 **유지** — 숨은 제스처의 유일한 안내라 법적 고지와 같은 예외.
7. **추가 화면 레이블**: "카카오 장소 검색"(설명은 placeholder "이름으로 검색하면 주소·위치가
   채워져요"), "위치 (선택)"(설명 제거 — 지도 자체가 탭을 부른다), 상태문은 **선택했을 때만**
   ("위치 선택됨 · 37.5, 127.0"), 미선택 문장 제거.
8. **카드 머리 줄**: 매거진 이름을 `flexShrink:1` + 배지 `flexShrink:0`, 일반 카드는 이름 한 줄 +
   알약 줄을 **두 번째 줄로 분리**(카테고리 · 솔로 픽 · 여행). 이름이 길어도 알약이 이름 사이로
   끼어들지 않는다.

**하지 않는 것**: 콘텐츠 모드 존치/이관(§3-5 보류 유지), 정렬 규칙, 솔로 픽 조건, 등급 규칙·등극
모달, ★☆ 텍스트 관례(빌드 비용), 매거진 카드의 `together` 틴트(둘이 인증한 곳 — 뜻이 맞다),
지도 핀 색(카카오 지도 관례), 방문 폼의 필드 구성.

### 8-3. 방향

첫인상이라 **면적이 큰 것부터** — 인트로의 원 아이콘과 폼의 그림자 카드. 비용 중.

1. **인트로 4장의 원 아이콘 → 자체 캐릭터**: 140px 원 자리에 duo/dubi/bli 스티커 이미지(예:
   1장 `duo_idea`·2장 `dubi_wink`·3장 `duo_happy`·4장 `duo_drool` — 실제 그림 보고 고른다) 160px.
   구조(아이콘+문구 4장, 캡처 없음)와 문구는 그대로 — 결정 문서의 이유("곧 낡는다")는 캐릭터에는
   해당하지 않는다. 액센트는 점 색에만 남는다. 번들에 이미 있는 파일이라 **업데이트로 나간다**.
2. **폼의 그림자 카드 제거** (Login·Register·Forgot·Reset·ConsentGate): 필드가 페이지 위에 놓인다.
   `Card` 를 `View` 로, 카드 밖 고스트 버튼 줄은 폼 아래 **한 줄 문장 + 인라인 링크**
   ("아직 계정이 없나요? 회원가입")로. 비밀번호 화면의 고스트 둘도 한 줄.
3. **비밀번호 화면의 `display` 제목 제거**: 헤더가 제목이다. 본문은 설명 한 줄부터, 왼쪽 정렬.
4. **가입 문구**: "반가워요!" / "둘의 기록을 시작해요" (인트로 4장과 같은 어휘). 성별 칩과 체크박스를
   `primaryBg`/`primaryFill` 로. 체크박스 "✓" 글자는 **유지**(`check` 글리프 없음, 22px 상자 안
   caption 굵게라 깨지지 않음) — 서브셋을 늘리는 빌드 때 함께 바꾼다.
5. **미연결 홈**: 아이콘 40 → 캐릭터 `duo_love` 120px, 연결 버튼을 `Button`(primary) 컴포넌트로,
   "연결을 기다리는 동안, 혼자서도 시작할 수 있어요" → 묶음 제목 "혼자서도 시작할 수 있어요"
   (`SettingsGroup title` 과 같은 캡션), 행 3 은 `SettingsRow` 문법(40px 상자 대신 아이콘만)으로.
6. **초대코드는 열자마자**: 화면 진입 시 자동 생성(있으면 재사용). 버튼은 "새 코드" 하나로 줄고,
   설명 둘은 코드 상자 아래 캡션 한 줄("24시간 동안 유효 · 상대가 이 코드를 입력하면 연결돼요")로.
   공유 버튼에 `share-variant` 아이콘. 백엔드는 안 건드린다 — 이미 있는 생성 API 를 mount 에서 부른다.
7. **스플래시 슬로건 알약 제거**: 글자만. 알약은 마크·워드마크 아래에서 세 번째 도형이다.
8. **Google 버튼**: `google` 글리프가 서브셋에 없어 로고는 빌드 항목 — 이번엔 두고 **미완 항목**으로
   적는다.

**하지 않는 것**: 인트로 장수·문구·캡처 정책, 슬라이드 스크롤 구현(웹 우회 코드), 로그인 방식,
동의 항목·각주, 비밀번호 재설정 흐름, 초대코드 규칙(6자리·24시간), ConsentGate 의 Modal 구조.
