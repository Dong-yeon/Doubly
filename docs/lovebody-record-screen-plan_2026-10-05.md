## 2. 원칙

1. **주 경로가 첫 화면에 있다** — 사진(또는 음식 이름) → 분석 → 확인 → 저장. 저장은 언제나 보인다.
2. **기본값으로 충분한 것은 한 줄 요약으로** — 날짜(오늘)·끼니(시각으로 정함, `frontend/src/utils/mealType.ts:8-14`)는 바꾸는 사람만 연다.
3. **기능은 없애지 않고 자리만 옮긴다** — 인벤토리 §5 의 ⚠(유일한 진입점: 바코드·즐겨찾기 선물함)는 반드시 새 자리를 둔다.
4. **"같이 먹었어요"는 접지 않는다** — 방향의 핵심이고(`docs/lovebody-direction_2026-10-02.md`), 10-05 에 사라짐 버그를 고친 당사자다.
5. **서버는 건드리지 않는다** — 저장 요청 모양(`SaveMealPayload`, `frontend/src/api/diet.ts`)은 그대로. 전부 OTA 로 나간다.

## 6. 위험과 확인할 것

- **럽슐랭 연동 P0 와 겹친다** — `LOVEBODY_LOVELICHELIN_LINK_2026-10-05.md` §6 의 6단계가 같은 장소 블록(저장 API 교체·별점은 건드렸을 때만·`revisitIntent` 제거)을 고친다.
  **P0 6단계를 먼저 넣고 S4 를 그 위에 얹는 순서**를 권한다(동작은 그쪽, 자리는 이쪽). 동시에 하면 같은 줄을 두 세션이 고친다.
- **키보드와 고정 푸터** — iOS `padding`·Android `height` 로 푸터가 키보드 위로 올라오면 입력 영역이 그만큼 줄어든다(§7 Q4).
  Android 15 edge-to-edge 이슈가 있었던 자리라(`FormKeyboardView.tsx` 주석) **실기기 확인 필수**.
- **숨은 기능의 발견성** — 즐겨찾기·최근·바코드가 시트 뒤로 가면 덜 보인다. 받은 선물 배지를 칩에 달고, 칩 라벨에 개수를 붙인다(⭐ 즐겨찾기 ·2).
  쓰는 빈도는 **데이터 없음**(인벤토리 §4)이라 정리 뒤에도 알 길이 없다(§7 Q6).
- **편집 한 번이 한 탭 늘어난다** — 지금은 카드가 다 펼쳐져 있어 바로 고친다. 행을 눌러야 펼쳐진다. 수정 모드에서 특히 체감된다.
- **배수 칩** — 지금은 칼로리가 있으면 항상 보인다(DR:1670). 펼친 안으로 넣으면 "반 공기"가 한 탭 늘어난다(§7 Q3).
- **검증 수단** — 앱에는 테스트 러너가 없다. `npm run typecheck`·`lint`·`verify:nested-buttons`(행 안 버튼)·`build:web` 과 **실기기 확인**이 전부다.
  행에 아이콘만 있는 버튼이 늘면 `doubly-a11y/icon-button-label` 경고를 챙긴다.
- **QuickMealSheet 와의 말 맞추기** — 빈 사진 칸의 두 버튼을 시트와 같은 말("사진 찍기"·"앨범에서 고르기", `frontend/src/screens/home/components/QuickMealSheet.tsx:71-84`)로.
