## 🔴 P0 — 운동 세션 화면(WorkoutSessionScreen)이 운동 카드를 전혀 렌더링하지 않음

- **심각도**: 최상 — **운동 기록 핵심 기능이 사실상 전부 사용 불가능한 상태**
- **재현 경로 3가지 전부 동일 증상 확인**:
  1. 운동 탭 → **자유 운동** 버튼 → 세션 화면 진입, 운동 0개
  2. AI 운동 추천 → "오늘 뭐하지?" → 루틴으로 편집하기 → 저장 → 내 루틴에서 ▶(시작) → 세션 화면 진입, **5개 운동 · 16세트가 정상적으로 상단 카운터에 반영됨(즉 데이터는 로드됨)**
  3. 루틴 만들기(수동, "+ 운동 추가"로 BenchPress 1개 직접 추가) → 저장 → ▶(시작) → 세션 화면 진입, **"세트 0/3"으로 세트 수는 정상 반영**
- **공통 증상**: 위 세 경우 모두 헤더 바로 아래(총 볼륨/완료 세트 카운터, 휴식 프리셋 칩) 밑으로 **운동 카드가 단 하나도 렌더링되지 않고 화면이 완전히 빈 채로 끝남**. "세트 0/16", "세트 0/3"처럼 총 세트 수는 정확히 계산되어 있으나(= 라우트 파라미터/스토어에 운동 목록 자체는 정상 전달됨), 그걸 렌더링해야 할 운동별 카드 리스트(세트 체크박스, 무게/횟수 입력, ✕ 삭제, ＋ 세트 등)가 전부 비어 있음.
- **재현성**: 100% (3가지 경로 × 여러 번 시도, 대기 후 재확인해도 동일 — 로딩 레이스 아님).
- **로그**: `adb logcat`에서 JS 예외/red screen 없음 — **조용히** 실패함(크래시가 아니라 렌더 조건이 항상 falsy인 형태의 버그로 추정).
- **부수 효과**: 운동 카드가 없으니 세트를 체크할 방법이 없고, "운동 완료"를 누르면 정상적으로 "완료한 세트가 없어요. 세트를 체크해주세요!" 밸리데이션이 뜨는데(이 자체는 정상 동작) — **결과적으로 이 화면을 통해서는 어떤 방식으로도 운동을 기록/완료할 수 없다.**
- **영향 범위**: 자유 운동, AI 추천 루틴, 수동 루틴 전부 막힘. `WorkoutRecordScreen`(다른 진입점, "+ 기록하기" 형태)이 남아있는지, 그쪽은 정상인지는 별도 확인 필요(운동 탭 메인 화면 UI가 QA_CHECKLIST 서술과 달라져 있어 "+ 기록하기" 버튼 자체가 현재 UI에는 없음 — 자유 운동/맞춤 운동 두 버튼으로 대체된 것으로 보임).
- **QA_CHECKLIST.md와의 관계**: 기존 문서의 "WorkoutSessionScreen ⚠️ 최우선" 섹션은 세트/무게 입력값 검증 미비(P0-1, P0-2) 등 *입력값 품질* 문제를 지적했었는데, 지금 실기기에서는 그 이전 단계인 **"화면 자체가 안 뜬다"** 로 퇴행한 상태. Workout Log v2 리팩터링(PLAN.md 참고) 도중 화면 UI가 크게 바뀌면서(주간 캘린더 스트립·자유 운동/맞춤 운동 버튼 추가) 발생한 회귀로 추정됨.
## 🔬 근본 원인 확정 (코드 분석 + 실기기 재현 실험)

**`react-native-draggable-flatlist@4.0.3`가 `react-native-reanimated@4.3.1`(New Architecture 전용 메이저 버전)과 호환되지 않아, 네이티브 렌더링 경로에서 리스트 항목이 전부 렌더링되지 않는 문제.**

### 근거
- `package.json`: `react-native-draggable-flatlist: ^4.0.3`, `react-native-reanimated: 4.3.1`(2025년 하반기 출시된 최신 메이저 버전), `react-native-worklets: 0.8.x`
- `react-native-draggable-flatlist`의 `peerDependencies`는 `react-native-reanimated: >=2.8.0`로만 명시돼 있어 **Reanimated 4의 아키텍처 변경(워크릿 런타임 분리, New Architecture 전용화)을 전혀 알지 못하는 버전**이다. 이 라이브러리는 마지막 배포 이후 관리가 뜸해져 Reanimated 4 대응이 없다.
- 문제의 핵심 파일 `node_modules/react-native-draggable-flatlist/src/components/CellRendererComponent.tsx`가 **모듈 로드 시점에 즉시** `runOnUI(() => { "worklet"; ... })()`를 호출한다(컴포넌트 마운트가 아니라 import 시점). 각 카드는 `useAnimatedStyle`로 계산된 `transform: translateY(...)`를 씌운 `Animated.View`로 렌더링되는데, 이 값 계산 체인(`useCellTranslate` → `useDerivedValue`/`withSpring`)이 Reanimated 4의 새 워크릿 런타임 초기화 순서와 맞지 않아 조용히 깨지는 것으로 보인다(크래시 없이 뷰가 화면에 나타나지 않는 형태).

### 실기기 재현 실험으로 확정
Metro를 재기동해 실기기에 직접 접속한 뒤, `WorkoutSessionScreen.tsx`의 분기 조건
```ts
{Platform.OS === 'web' ? <FlatList .../> : <DraggableFlatList .../>}
```
을 일시적으로 `{true || Platform.OS === 'web' ? ... }`로 바꿔 **네이티브에서도 강제로 (Reanimated를 쓰지 않는) 평범한 `FlatList`를 타게** 만들고 전체 리로드 후 확인:

- **원본 코드(DraggableFlatList)**: 운동 0개든 3개든 카드도 "+ 운동 추가" 푸터도 전혀 안 보임(완전히 빈 화면)
- **FlatList로 강제 전환**: 같은 화면·같은 데이터로 "+ 운동 추가" 버튼과 안내 문구가 즉시 렌더링됨. 직접 운동(TestSquat)을 추가하자 **드래그 손잡이·이모지·부위 배지·세트별 무게/횟수/RPE 입력·완료 체크박스까지 카드 전체가 정상적으로 렌더링됨**을 확인.

→ `renderExerciseCard` 자체나 스타일, 데이터 흐름에는 문제가 없고, **오직 `DraggableFlatList`(Reanimated 기반 드래그 리스트) 래퍼만 실패한다**는 것이 실험으로 확정됨. 실험 후 코드는 원래 조건으로 되돌려놨다.

### 권장 조치 (우선순위 순)
1. **가장 빠른 수정**: `WorkoutSessionScreen.tsx`의 `Platform.OS === 'web'` 조건을 없애고 **네이티브에서도 항상 평범한 `FlatList`를 쓰도록 변경**. 순서 바꾸기(드래그) 기능만 잃고 나머지는 100% 정상 동작한다 — 지금 당장 기능을 살리는 게 목적이면 이 방법이 제일 안전하고 빠르다.
2. **근본 수정**: `react-native-draggable-flatlist`를 Reanimated 4를 지원하는 버전으로 업그레이드(현재 npm에 있는지 확인 필요 — 이 저장소 상태로는 인터넷 확인을 못 했음), 또는 유지보수가 활발한 대체 라이브러리(`@quidone/react-native-draggable-flatlist` 등 커뮤니티 포크)로 교체.
3. **비권장**: `react-native-reanimated`를 3.x로 다운그레이드하는 방법도 있으나, `app.json`의 `newArchEnabled: true`(New Architecture) 및 다른 화면(`CallOverlay`, `AvatarCropSheet`)의 gesture-handler 사용과 얽혀 있어 부작용 범위가 넓다. 권장하지 않음.

## [확정] BodyMetricScreen 체중 입력 NaN 무필터 — QA_CHECKLIST 추정 항목 실증
- 체중(kg) 필드에 "70.5.2"(점 2개) 입력 시 아무 제지 없이 그대로 입력됨.
- 저장 누르면 `Number("70.5.2")` → NaN → 앱이 "측정값이나 사진을 하나 이상 입력해주세요" 에러를 띄움.
  **즉 사용자가 값을 입력했는데도 "아무것도 안 입력했다"는 엉뚱한 메시지를 받는다.** 어디가 잘못됐는지 알 길이 없음.
- QA_CHECKLIST의 "패턴 2" 추정이 실기기에서 그대로 재현됨(확정으로 격상).
