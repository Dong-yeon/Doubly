# 홈에서 남긴 식단이 채팅에 안 나온다 (2026-10-12)

## 제보

"홈 화면에서 식단을 공유했을 때는 채팅에 바로 공유가 안 된다" — 언제나, 홈 식단 칩의 (a) 사진 한 장 저장과 (b) 저장 직후 "같이 먹었어요" 둘 다.

## 확인한 것 (운영 DB 읽기 전용 · 코드)

- 홈 칩 저장도 기록 화면과 같은 `POST /meal`(MealService.save) 이다. 서버는 커플이면 저장할 때 `MEAL_CARD` 를 남기고 `/sub/rooms/{id}` 로 방송한다.
- 그런데 이 **식단 자동 공유는 9/13 에 만들어 두고 origin/main 에는 10-11 오후(f356a426)에야 합쳐졌다.** 그 전에는
  - 기록 화면만 저장 뒤 "채팅에 공유할까요?" 확인창으로 **앱이** 카드를 올렸다(`meal_id` 없는 카드들 — 7238, 7289).
  - 홈 칩은 그런 단계가 아예 없었다 → "언제나 안 나왔다"와 맞다. 10-01~10-09 식단 30여 건은 카드 0.
- 자동 공유 이후로는 홈 칩 저장에도 카드가 생긴다 — 10-10 저녁 파트너의 홈 칩 저장(meal 170)에 카드 7299.
- 자동 공유가 막 들어간 날, 옛 앱의 확인창과 겹쳐 **카드 2장**이 생긴 기록이 있다(meal 169: 서버 7288 + 앱 7289).
  지금 앱에는 그 확인창이 없다(DietRecordScreen 주석) — 오늘 OTA 로 받은 기기부터는 겹치지 않는다.
- **(b) 는 진짜 빈틈이었다.** `MealService.share`(같이 먹었어요)는 끼니를 데이트 식단으로 바꾸고 상대 몫을 만들지만 채팅 카드는 건드리지 않았다
  — 카드는 혼자 기록("저녁 · …")으로 남고, 자동 공유 이전 기록이면 카드 자체가 없다.

## 수정 (서버만, OTA 불필요)

- `ChatService.markMealCardAsDate` — 이 끼니의 살아 있는 카드를 찾아 끼니 이름 뒤에 " (데이트)"만 붙인다(`withDateMark`).
  본문을 통째로 다시 만들지 않는 이유: 뒤에 붙은 럽슐랭 조각(`appendPlaceFragment`)과 목표 달성 접두어를 잃지 않으려고.
  두 번 눌러도 한 번만 붙는다.
- `MealService.share` 끝에서 호출 — 바꾼 카드는 `/sub/rooms/{id}/updates` 로 제자리 교체 방송(앱은 이미 id 로 갈아 끼운다,
  chatStore `subscribeRoomUpdates`). 카드가 없으면 데이트 카드를 새로 남긴다.
- 테스트: `MealFlowTest.같이_먹었어요를_누르면_채팅_카드가_데이트_카드로_바뀐다`(카드 1장·두 번 눌러도 한 번), `MealCardDateMarkTest`.

## 남은 것

- 사진만 저장한 카드는 본문이 끼니 이름뿐이다("저녁"). 칼로리 자동 분석이 음식 이름을 채운 뒤에도 카드 본문은 그대로 —
  필요하면 자동 분석 반영 때 카드 본문도 갱신할 수 있다(이번엔 안 함).
- 실기기 확인: 홈 칩으로 사진 저장 → 내·상대 채팅방에 카드, "같이 먹었어요" → 그 카드가 "(데이트)"로 바뀌는지.
