# 우리 이모지 배경 따내기 + 말풍선 파스텔 (2026-09-30)

비트윈 채팅과 나란히 놓고 본 개선점 중 1·2번.

## 1. 우리 이모지 흰 원판 없애기

**문제**: 생성 모델(NB2) 출력은 알파 없는 흰 배경 JPEG 이라, 채팅이 흰 원판(`borderRadius: 66`)에 얹어 그렸다.
배경 없이 그림만 뜨는 캐릭터 스티커 옆에서 무거워 보였다.

**결정 — 서버에서 한 번 따내고, 앱은 URL 로 구분한다.**
- 채팅 메시지는 이모지 URL 을 **복사해** 들고 있다. 그래서 "따낸 이미지인가"는 메시지만 보고 알 수 있어야 한다 →
  따낸 PNG 는 별도 Cloudinary 폴더 `couple-emoji-cut` 에 올리고, 앱은 `/couple-emoji-cut/` 이 들어간 URL 이면
  원판 없이 그린다(`frontend/src/utils/coupleEmoji.ts`). 플래그 필드를 메시지에 더하는 것보다 옛 메시지까지 한 번에 맞는다.
- 앱에서 따내기(클라이언트 처리)는 기각 — 매번 계산하고, 웹·네이티브 둘 다 구현해야 한다.

**알고리즘** (`EmojiCutout.java`, 실제 이모지 12장으로 튜닝):
1. 흰색 아닌 화소 = 그림 재료 (min 채널 < 236 또는 채도 > 24)
2. 닫힘(팽창→침식, 창 25@1024)으로 선 사이 틈을 막는다
3. 위·왼쪽·오른쪽 변에서 들어오는 빈 곳만 바깥 — **아래 변은 막는다**(흉상이 잘려 나가는 자리라 흰 셔츠 속으로 샌다)
4. 실루엣을 15px@1024 넓혀 흰 스티커 테두리를 고르게 다시 두른다, 가장자리 살짝 흐림
5. 바깥 비율이 12~88% 밖이면 실패로 보고 원본 유지

**기각한 1안**: 가장자리에서 이어진 흰색 지우기 — 흰 외곽선과 흰 옷 사이에 선이 없는 곳으로 번져 셔츠가 뚫렸다.
임계값 215 는 옅은 셔츠 윤곽선을 놓쳤다. `EmojiCutoutTest` 가 이 회귀를 합성 그림으로 막는다.

**새 이모지**: 생성 직후 따낸다(`CoupleEmojiService.generateOne`). 실패하면 원본을 기존 폴더에.

**기존 이모지 백필** (`CoupleEmojiCutoutBackfill`): 10분마다 20장, 서버 기동 2분 뒤 시작.
- `bg_removed`(V109): null=안 해 봄 / true=따냄 / false=원본 유지(다시 안 함)
- 숨긴 이모지도 대상 — 지난 대화에 그려지므로
- 한 트랜잭션에서 이모지 URL + 같은 URL 을 가진 COUPLE_EMOJI 메시지 교체, 커밋 뒤 원본 삭제
- 원본이 없으면(PHOTO_DOWNLOAD_FAILED) false, 네트워크·업로드 실패는 다음 차례에 재시도

**미검증**: 새 쿼리(`replaceImageUrl`)의 PostgreSQL 실행(도커 꺼짐 — 단순 JPQL update 라 위험은 낮다),
배포 후 실기기에서 원판 없이 보이는지.

## 2. 내 말풍선 파스텔화

라이트 5종(로즈·스카이·라벤더·피치·민트)의 내 말풍선을 진한 색+흰 글자 → 파스텔+진한 글자로.
본문 대비는 8.8~10.1 로 오히려 올랐다. 파스텔은 같은 계열 배경에 묻히기 쉬워 검증에
**"내 말풍선 vs 배경 ≥ 1.2"** 규칙을 더했다(현재 1.27~1.37). 다크 테마와 기본 테마는 그대로.
